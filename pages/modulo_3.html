3.1 Navegando no Desktop Linux

Para ser um administrador de sistemas Linux, é necessário estar confortável com o Linux como sistema operacional desktop e ter proficiência em habilidades básicas de Tecnologia da Informação e Comunicação (ICT). Usar Linux para tarefas de produtividade, em vez de depender de sistemas Windows ou Macintosh, acelera o aprendizado ao trabalhar com ferramentas Linux diariamente.


Administradores de sistemas fazem muito mais do que gerenciar servidores; eles são frequentemente chamados para ajudar usuários com problemas de configuração, recomendar novos softwares e atualizar documentação, entre outras tarefas.

Começando com Linux

A maioria das distribuições Linux permite que os usuários baixem um pacote de instalação "desktop" que pode ser carregado em um pendrive USB. Esta é uma das primeiras coisas que aspirantes a administradores de sistemas devem fazer: baixar uma distribuição importante e carregá-la em um PC antigo. Este processo é bastante simples e tutoriais estão disponíveis online.

Interface Familiar

O desktop Linux deve ser familiar para qualquer pessoa que tenha usado um PC ou Macintosh, com ícones para selecionar diferentes programas e um aplicativo de "configurações" para configurar coisas como contas de usuário, redes WiFi e dispositivos de entrada.

3.1.1 Acessando a Linha de Comando

A interface de linha de comando (CLI) é um sistema simples de entrada de texto para inserir qualquer coisa, desde comandos de uma única palavra até scripts complicados. A maioria dos sistemas operacionais possui uma CLI que fornece uma maneira direta de acessar e controlar o computador.

Terminal GUI

Um terminal GUI é um programa dentro do ambiente gráfico que emula uma janela de terminal. Terminais GUI podem ser acessados através do sistema de menus.


Por exemplo, em uma máquina CentOS, você pode clicar em Applications na barra de menu, depois System Tools e, finalmente, Terminal. Se você tiver ferramentas de busca, pode pesquisar por "terminal".

Terminal Virtual

Um terminal virtual pode ser executado ao mesmo tempo que uma GUI, mas requer que o usuário faça login através do terminal virtual antes de executar comandos (como fariam antes de acessar a interface GUI).

Diferenças entre Distribuições

Cada distribuição Linux desktop é ligeiramente diferente, mas o aplicativo terminal ou x-term abrirá uma janela de terminal a partir da GUI. Embora existam diferenças sutis entre os termos console e sessão de janela de terminal, eles são todos iguais do ponto de vista do administrador e exigem o mesmo conhecimento de comandos para usar. 

$ # Tarefas comuns da linha de comando
$ ls -la                    # Listar arquivos e diretórios
$ cd /etc                   # Navegar para diretório /etc
$ nano config.txt          # Editar arquivo de configuração
$ bash script.sh            # Executar script shell
$ ps aux                    # Ver processos em execução

Servidores e CLI

Tarefas comuns da linha de comando incluem iniciar programas, executar scripts e editar arquivos de texto usados para configuração do sistema ou de aplicações. A maioria dos servidores inicializa diretamente em um terminal, pois uma GUI pode consumir muitos recursos e geralmente não é necessária para operações baseadas em servidor.

Gerenciamento de Recursos

As aplicações fazem solicitações ao kernel e, em troca, recebem recursos, como memória, CPU e espaço em disco. Se duas aplicações solicitarem o mesmo recurso, o kernel decide qual delas o recebe e, em alguns casos, encerra outra aplicação para salvar o restante do sistema e prevenir uma queda.

Abstração de Detalhes

O kernel também abstrai alguns detalhes complicados da aplicação. Por exemplo, a aplicação não sabe se um bloco de armazenamento em disco está em um SSD, um HDD tradicional ou até mesmo em um compartilhamento de arquivos de rede. As aplicações precisam apenas seguir a Interface de Programação de Aplicações (API) do kernel e, portanto, não precisam se preocupar com os detalhes de implementação.


Cada aplicação se comporta como se tivesse um grande bloco de memória no sistema; o kernel mantém essa ilusão remapeando blocos menores de memória, compartilhando blocos de memória com outras aplicações ou até mesmo trocando blocos não utilizados para o disco.

Multitarefa

O kernel também gerencia a alternância de aplicações, um processo conhecido como multitarefa. Um sistema computacional tem um pequeno número de unidades centrais de processamento (CPUs) e uma quantidade finita de memória. O kernel cuida de descarregar uma tarefa e carregar uma nova se houver mais demanda do que recursos disponíveis.

Alternância de Tarefas

Quando uma tarefa é executada por um período específico de tempo, a CPU a pausa para que outra possa ser executada. Se o computador está fazendo várias tarefas ao mesmo tempo, o kernel está decidindo quando alternar o foco entre as tarefas. Com a alternância rápida das tarefas, parece que o computador está fazendo muitas coisas ao mesmo tempo.

Processos

Quando nós, como usuários, pensamos em aplicações, tendemos a pensar em processadores de texto, navegadores web e clientes de e-mail. No entanto, há uma grande variedade de tipos de aplicações. O kernel não diferencia entre uma aplicação voltada para o usuário, um serviço de rede que se comunica com um computador remoto ou uma tarefa interna. A partir disso, obtemos uma abstração chamada de processo.


Um processo é apenas uma tarefa que é carregada e rastreada pelo kernel. Uma aplicação pode até precisar de múltiplos processos para funcionar, então o kernel cuida de executar os processos, iniciando-os e interrompendo-os conforme solicitado e distribuindo os recursos do sistema.

📌 Resumo: O kernel é o coração do sistema operacional, gerenciando memória, CPU, disco e processos. As aplicações solicitam recursos através da API do kernel, que decide como alocá-los. A multitarefa permite que várias aplicações rodem simultaneamente, alternando rapidamente entre elas.

3.2.1 Principais Aplicações

O kernel Linux pode executar uma grande variedade de softwares em muitas plataformas de hardware. Um computador pode atuar como servidor, o que significa que ele lida principalmente com dados em nome de outros, ou como desktop, o que significa que um usuário interage diretamente com ele. A máquina pode executar software ou ser usada como uma máquina de desenvolvimento no processo de criação de software. Uma máquina pode até adotar múltiplos papéis, pois o Linux não faz distinção; é meramente uma questão de configurar quais aplicações serão executadas.

Simulação de Ambientes de Produção

Uma vantagem resultante é que o Linux pode simular quase todos os aspectos de um ambiente de produção, desde o desenvolvimento até os testes e verificação em hardware reduzido, o que economiza custos e tempo. Um administrador Linux pode executar as mesmas aplicações de servidor em um desktop ou servidor virtual de baixo custo que são executadas por grandes provedores de serviços de internet.


É claro que um desktop não seria capaz de lidar com o mesmo volume que um grande provedor, mas quase qualquer configuração pode ser simulada sem necessidade de hardware poderoso ou licenciamento de servidor.

📡 Aplicações de Servidor

Software que não tem interação direta com o monitor e teclado da máquina em que é executado. Seu propósito é servir informações para outros computadores, chamados de clientes. Às vezes, aplicações de servidor podem não se comunicar com outros computadores, mas apenas processar dados internamente.


Exemplos: Apache (web), Nginx, MySQL, PostgreSQL, SSH, DHCP, DNS

🖥️ Aplicações Desktop

Navegadores web, editores de texto, players de música ou outras aplicações com as quais os usuários interagem diretamente. Em muitos casos, como um navegador web, a aplicação está se comunicando com um servidor na outra ponta e interpretando os dados. Este é o lado "cliente" de uma aplicação cliente/servidor.


Exemplos: Firefox, Chrome, LibreOffice, VLC, GIMP, VS Code

🔧 Ferramentas (Tools)

Uma categoria flexível de software que existe para facilitar o gerenciamento de sistemas computacionais. Ferramentas podem ajudar a configurar displays, fornecer um shell Linux onde os usuários digitam comandos, ou até mesmo ferramentas mais sofisticadas, chamadas compiladores, que convertem código-fonte em programas aplicativos que o computador pode executar.


Exemplos: Bash, GCC, make, git, systemctl, htop, vim, nano

Disponibilidade de Aplicações por Distribuição

A disponibilidade de aplicações varia dependendo da distribuição. Frequentemente, os fornecedores de aplicações escolhem um subconjunto de distribuições para suportar. Diferentes distribuições têm diferentes versões de bibliotecas-chave, e é difícil para uma empresa suportar todas essas versões diferentes.


No entanto, algumas aplicações, como Firefox e LibreOffice, são amplamente suportadas e disponíveis para todas as principais distribuições.

Excelência em Servidores

O Linux é a plataforma preferida para servidores por várias razões:


  • Confiabilidade - Sistemas Linux podem rodar por anos sem reinicialização
  • Eficiência - Baixo consumo de recursos, máximo desempenho
  • Customização - Instale apenas o necessário (minimal install)
  • Segurança - Modelo robusto de permissões e atualizações rápidas
  • Custo-benefício - Sem licenças caras, rodando em qualquer hardware

Otimização "Do More With Less"

A capacidade de otimizar sistemas operacionais de servidor com apenas os componentes necessários permite que administradores façam mais com menos recursos. Isso significa:


  • Menor superfície de ataque para segurança
  • Menos atualizações e manutenção
  • Maior desempenho por núcleo de CPU
  • Redução de custos com hardware e energia

Para Startups e Grandes Empresas

Startups amam o Linux porque podem começar com recursos mínimos e escalar conforme crescem. Grandes empresas apreciam a estabilidade, segurança e o suporte empresarial disponível (RHEL, SUSE, Ubuntu LTS).

3.2.2.4 Servidores de E-mail

O e-mail sempre foi um uso generalizado para servidores Linux. Ao discutir servidores de e-mail, é sempre útil analisar as 3 diferentes tarefas necessárias para enviar e-mails entre pessoas:

MTA (Mail Transfer Agent)

Agente de Transferência de Correio - Software usado para transferir mensagens eletrônicas para outros sistemas.


O MTA mais conhecido é o Sendmail. Postfix é outro popular e tem como objetivo ser mais simples e seguro que o Sendmail.

MDA (Mail Delivery Agent)

Agente de Entrega de Correio - Também chamado de Agente de Entrega Local, cuida do armazenamento do e-mail na caixa de correio do usuário. Geralmente é invocado a partir do MTA final na cadeia.

POP/IMAP Server

POP (Post Office Protocol) e IMAP (Internet Message Access Protocol) são dois protocolos de comunicação que permitem que um cliente de e-mail no seu computador converse com um servidor remoto para buscar e-mails.

3.2.2.5 Compartilhamento de Arquivos

Para compartilhamento de arquivos centrado em Windows, o Samba é o claro vencedor. O Samba permite que uma máquina Linux pareça e se comporte como uma máquina Windows, para que possa compartilhar arquivos e participar de um domínio Windows. O Samba implementa os componentes do servidor, como disponibilizar arquivos para compartilhamento e certas funções de servidor Windows, e também a parte do cliente para que uma máquina Linux possa consumir um compartilhamento de arquivos Windows.

Samba (Windows)

Permite que uma máquina Linux compartilhe arquivos com sistemas Windows e participe de um domínio Windows. Implementa tanto o lado servidor quanto o cliente para compatibilidade total com o protocolo SMB/CIFS.

Netatalk (macOS)

O projeto Netatalk permite que uma máquina Linux atue como um servidor de arquivos Apple Macintosh, fornecendo compatibilidade com o protocolo AFP (Apple Filing Protocol).

NFS (Linux/UNIX)

O protocolo nativo para compartilhamento de arquivos em UNIX/Linux é o Network File System (NFS). NFS geralmente faz parte do kernel, permitindo que um sistema de arquivos remoto seja montado como um disco local.

DNS (Domain Name System)

À medida que uma rede de computadores se torna mais substancial, a necessidade de um diretório aumenta. Um dos sistemas de diretório de rede mais antigos é o Domain Name System (DNS). Ele é usado para converter um nome como https://www.icann.org/ em um endereço IP como 192.0.43.7, que é um identificador único de um computador na Internet.


O DNS também contém informações globais como o endereço do MTA para um determinado nome de domínio. Uma organização pode querer executar seu próprio servidor DNS para hospedar seus nomes públicos e também servir como um diretório interno de serviços. O Internet Software Consortium mantém o servidor DNS mais popular, simplesmente chamado de bind (em homenagem ao nome do processo que executa o serviço).

Bind é o servidor DNS mais popular no Linux.

LDAP (Lightweight Directory Access Protocol)

Foco: Armazenar informações como contas de usuário e funções de segurança

Estrutura em árvore - objetos organizados hierarquicamente


OpenLDAP é o programa dominante na infraestrutura Linux.

DHCP (Dynamic Host Configuration Protocol)

Uma peça final da infraestrutura de rede a ser discutida aqui é o Dynamic Host Configuration Protocol (DHCP). Quando um computador inicializa, ele precisa de um endereço IP para a rede local, para que possa ser identificado de forma única.


O trabalho do DHCP é ouvir solicitações e atribuir um endereço livre do pool DHCP. O Internet Systems Consortium (ISC) mantém o servidor ISC DHCP, que é o servidor DHCP de código aberto mais comum.

3.3.1 Shells

No nível básico, os usuários interagem com um sistema Linux através de um shell, seja conectando-se remotamente ao sistema ou a partir de um teclado conectado. O trabalho do shell é aceitar comandos, como manipulações de arquivos e inicialização de aplicações, e passá-los ao kernel do Linux para execução.

O shell do Linux fornece uma linguagem rica para iterar sobre arquivos e customizar o ambiente, tudo sem sair do shell. Por exemplo, é possível escrever uma única linha de comando que encontra arquivos com conteúdo correspondendo a um padrão específico, extrai informações úteis do arquivo e depois copia as novas informações para um novo arquivo. 

# Exemplo: encontrar arquivos, extrair e copiar informações
grep -r "erro" /var/log/* | cut -d: -f1 | sort -u | while read file; do
    echo "Processando: $file" >> resumo.txt
done

O Linux oferece uma variedade de shells para escolher, diferindo principalmente em como e o que pode ser customizado, e na sintaxe da linguagem de script embutida. As duas principais famílias são o Bourne shell e o C shell.

O Bourne shell foi nomeado em homenagem ao seu criador Stephen Bourne do Bell Labs. O C shell foi assim nomeado porque sua sintaxe empresta fortemente da linguagem C. Como ambos os shells foram inventados na década de 1970, existem versões mais modernas: o Bourne Again Shell (Bash) e o tcsh (pronuncia-se tee-cee-shell).

Bash é o shell padrão na maioria dos sistemas, embora o tcsh também esteja tipicamente disponível. Programadores pegaram recursos favoritos do Bash e do tcsh e fizeram outros shells, como o Korn shell (ksh) e o Z shell (zsh).

Escolha do Shell: A escolha do shell é principalmente pessoal. Usuários que estão confortáveis com o Bash podem operar efetivamente na maioria dos sistemas Linux. Outros shells podem oferecer recursos que aumentam a produtividade em casos de uso específicos.

3.4 Gerenciamento de Pacotes

Todo sistema Linux precisa adicionar, remover e atualizar software. No passado, isso significava baixar o código-fonte, configurá-lo, compilá-lo e copiar os arquivos para cada sistema que exigia atualização.

Felizmente, as distribuições modernas usam pacotes, que são arquivos compactados que agrupam uma aplicação e suas dependências (ou arquivos necessários), simplificando muito a instalação ao criar os diretórios corretos, copiar os arquivos adequados para eles e criar itens necessários, como links simbólicos.

Um gerenciador de pacotes cuida de rastrear quais arquivos pertencem a qual pacote e até mesmo baixar atualizações de repositórios, tipicamente um servidor remoto que compartilha as atualizações apropriadas para uma distribuição.

No Linux, existem muitos sistemas diferentes de gerenciamento de pacotes de software, mas os dois mais populares são os do Debian e do Red Hat.

A ferramenta de nível mais baixo para gerenciar esses arquivos é o comando dpkg. Este comando pode ser complicado para usuários Linux iniciantes, então o Advanced Package Tool (apt-get) — um programa front-end para a ferramenta dpkg — torna o gerenciamento de pacotes mais fácil.

Ferramentas adicionais de linha de comando que servem como front-ends para o dpkg incluem o aptitude e front-ends gráficos como Synaptic e Software Center.

3.4.2 Gerenciamento de Pacotes RPM

O Linux Standards Base (LSB), que é um projeto da Linux Foundation, é projetado para especificar (através de consenso) um conjunto de padrões que aumentam a compatibilidade entre sistemas Linux conformes. De acordo com o LSB, o sistema de gerenciamento de pacotes padrão é o RPM.

RPM faz uso de um arquivo .rpm para cada pacote de software. Este sistema é o que distribuições derivadas do Red Hat, incluindo CentOS e Fedora, usam para gerenciar software. Várias outras distribuições que não são derivadas do Red Hat, como SUSE, openSUSE e Arch, também usam RPM.

Assim como o sistema Debian, os sistemas de gerenciamento de pacotes RPM rastreiam dependências entre pacotes. Rastrear dependências garante que, quando um pacote é instalado, o sistema também instale quaisquer pacotes necessários para que esse pacote funcione corretamente. Dependências também garantem que atualizações e remoções de software sejam realizadas corretamente.

A ferramenta back-end mais comumente usada para RPM é o comando rpm. Embora o comando rpm possa instalar, atualizar, consultar e remover pacotes, as ferramentas front-end de linha de comando como yum e up2date automatizam o processo de resolução de problemas de dependência.

Nota: Um programa ou aplicação back-end interage diretamente com um programa front-end ou é "chamado" por um programa intermediário. Programas back-end não interagem diretamente com o usuário. Basicamente, existem programas que interagem com pessoas (front-end) e programas que interagem com outros programas (back-end).

Existem também ferramentas front-end baseadas em GUI como Yumex e Gnome PackageKit que também facilitam o gerenciamento de pacotes RPM.

Algumas distribuições baseadas em RPM implementaram o estilo de gerenciamento de pacotes ZYpp (ou libzypp), principalmente openSUSE e SUSE Linux Enterprise, mas também as distribuições móveis MeeGo, Tizen e Sailfish.

O comando zypper é a base do método ZYpp, e apresenta comandos curtos e longos em inglês para executar funções, como zypper in nomedopacote que instala um pacote incluindo quaisquer dependências necessárias.

Privilégios Root: A maioria dos comandos associados ao gerenciamento de pacotes requer privilégios root. A regra geral é: se um comando afeta o estado de um pacote, acesso administrativo é necessário. Um usuário comum pode realizar consultas ou buscas, mas para adicionar, atualizar ou remover um pacote, o comando precisa ser executado como usuário root.

3.5 Linguagens de Desenvolvimento

Não é surpresa que, como software construído com base em contribuições de programadores, o Linux tenha excelente suporte para desenvolvimento de software. Os shells são construídos para serem programáveis, e há editores poderosos incluídos em cada sistema. Existem também muitas ferramentas de desenvolvimento disponíveis, e muitas linguagens de programação modernas tratam o Linux como um cidadão de primeira classe.

Linguagens de programação de computador fornecem uma maneira para o programador inserir instruções em um formato mais legível por humanos, e para que essas instruções sejam eventualmente traduzidas em algo que o computador entenda. As linguagens se dividem em dois campos: interpretadas ou compiladas. Uma linguagem interpretada traduz o código escrito em código de máquina conforme o programa é executado, e uma linguagem compilada é traduzida de uma só vez.

O próprio Linux foi escrito em uma linguagem compilada chamada C. O principal benefício do C é que a linguagem em si mapeia diretamente para o código de máquina gerado, de modo que um programador habilidoso pode escrever código pequeno e eficiente. Quando a memória do computador era medida em kilobytes, isso era muito importante. Mesmo com grandes tamanhos de memória hoje, o C ainda é útil para escrever código que precisa rodar rápido, como um sistema operacional.

C foi estendido ao longo dos anos. Existe C++, que adiciona suporte a objetos ao C (um estilo diferente de programação), e Objective-C que tomou outra direção e é muito usado em produtos da Apple.

A linguagem Java dá uma abordagem diferente à compilação. Em vez de compilar para código de máquina, o Java primeiro imagina uma CPU hipotética chamada Java Virtual Machine (JVM) e então compila todo o código para ela. Cada computador host então executa o software JVM para traduzir as instruções JVM (chamadas de bytecode) em instruções nativas.

Benefício do Java: Um arquivo Java compilado pode ser executado em qualquer computador que implemente a JVM! A tradução adicional com Java pode fazer você pensar que seria lento, mas a JVM é relativamente simples e pode ser implementada de forma rápida e confiável em qualquer dispositivo.

Linguagens interpretadas, por outro lado, são traduzidas para código de máquina conforme são executadas. O poder computacional extra gasto nisso muitas vezes pode ser recuperado pela maior produtividade que o programador ganha ao não ter que parar de trabalhar para compilar. Linguagens interpretadas também tendem a oferecer mais recursos que linguagens compiladas, significando que frequentemente menos código é necessário.

JavaScript é uma linguagem de programação interpretada de alto nível que é uma das tecnologias centrais da world wide web. É semelhante, mas fundamentalmente diferente do Java. JavaScript é uma linguagem de script multiplataforma para adicionar elementos interativos a páginas web, amplamente utilizada em toda a internet.

Considere Isto: O termo orientado a objetos refere-se à programação que abstrai ações e processos complexos para que o usuário final lide apenas com tarefas básicas. Para visualizar este conceito, pense em uma máquina que realiza um conjunto complexo de tarefas simplesmente apertando um botão.

Perl é uma linguagem interpretada originalmente desenvolvida para manipulação de texto. Ao longo dos anos, ganhou favor com administradores de sistemas e continua sendo melhorada e usada em tudo, desde automação até construção de aplicações web.

PHP é uma linguagem inicialmente construída para criar páginas web dinâmicas. Um arquivo PHP é lido por um servidor web como Apache. As principais vantagens do PHP são que é fácil de aprender e disponível em quase qualquer sistema. Exemplos notáveis incluem WordPress (para blogs), cacti (para monitoramento), e até partes do Facebook.

Ruby é outra linguagem que foi influenciada por Perl e Shell, junto com muitas outras linguagens. Com a inclusão do framework Ruby on Rails, é uma escolha popular para construir aplicações web complexas. Ruby também é a linguagem que alimenta muitas das principais ferramentas de automação como Chef e Puppet.

Python é outra linguagem de script de uso geral. Assim como Ruby, torna tarefas complexas mais fáceis e tem um framework chamado Django que torna a construção de aplicações web muito fácil. Python tem excelentes capacidades de processamento estatístico e é um favorito na academia.

Uma linguagem de programação de computador é apenas uma ferramenta que facilita dizer ao computador o que você quer que ele faça. Uma biblioteca agrupa tarefas comuns em um pacote distinto que pode ser usado pelo desenvolvedor. ImageMagick é uma dessas bibliotecas que permite aos programadores manipular imagens em código. OpenSSL é uma biblioteca criptográfica usada em tudo, desde servidores web até a linha de comando.

Biblioteca C: Em um nível muito mais baixo está a biblioteca C. Ela fornece um conjunto básico de funções para ler e escrever em arquivos e telas, sendo usada por aplicações e outras linguagens.

3.6 Segurança e Privacidade

Administradores e usuários de computadores estão cada vez mais conscientes das preocupações com privacidade em suas vidas pessoais e profissionais. Violações de dados de alto perfil têm estado nas notícias com muita frequência recentemente, e o custo dessas invasões pode chegar a milhões de dólares para as instituições que são vítimas de hackers e ataques de ransomware. Muitas vezes, a causa dessas violações é simplesmente erro humano, como abrir um e-mail suspeito ou inserir senhas em uma página de login falsa.

Cookies são o principal mecanismo que os sites usam para rastrear você. Às vezes, esse rastreamento é bom, como para manter o controle do que está no seu carrinho de compras ou para mantê-lo logado quando você retorna ao site.

Conforme você navega na web, um servidor web pode enviar de volta o cookie, que é um pequeno pedaço de texto, junto com a página web. Seu navegador armazena essa informação e a envia de volta com cada solicitação para o mesmo site. Cookies são normalmente enviados apenas de volta para o site de onde se originaram, então um cookie do example.com não seria enviado para example.org.

No entanto, muitos sites têm scripts incorporados que vêm de terceiros, como um anúncio em banner ou pixel de analytics do Google. Se tanto example.com quanto example.org têm um pixel de rastreamento, como um de um anunciante, então o mesmo cookie será enviado ao navegar em ambos os sites. O anunciante então sabe que você visitou tanto example.com quanto example.org.

Rastreamento: Com um alcance amplo o suficiente, como a colocação em sites de redes sociais com botões "Curtir" e similares, um site pode obter uma compreensão de quais sites você frequenta e descobrir seus interesses e dados demográficos.

3.6.1 Questões de Senhas

O bom gerenciamento de senhas é essencial para a segurança em qualquer ambiente computacional. O administrador de sistemas Linux é frequentemente a pessoa responsável por definir e aplicar políticas de senhas para usuários de todos os níveis.

O usuário mais privilegiado em qualquer sistema Linux é o root. Esta conta é o administrador principal e é criada quando o sistema operacional é instalado. Frequentemente, administradores desabilitam o acesso root como primeira linha de defesa contra invasões, pois hackers tentarão obter acesso root para assumir o controle do sistema.

Atenção: A conta root tem poder absoluto sobre o sistema. Por isso, recomenda-se usar sudo em vez de fazer login diretamente como root.

Existem muitos níveis de acesso e vários meios de gerenciamento de senhas em um sistema Linux. Quando os usuários são criados, eles recebem diferentes permissões de login dependendo de quais grupos eles são atribuídos. Por exemplo, administradores podem criar e gerenciar usuários, enquanto usuários comuns não podem.

Serviços que rodam em sistemas como bancos de dados também podem ter permissões de login com suas próprias senhas e privilégios. Além disso, existem senhas específicas para acessar sistemas remotamente através de SSH, FTP ou outros programas de gerenciamento.

Desafio do Administrador: Gerenciar todas essas contas e suas senhas correspondentes é uma parte complicada e necessária do papel do administrador de sistemas. Senhas precisam ser complexas o suficiente para não serem facilmente adivinhadas por hackers, mas fáceis de lembrar para os usuários.

Cada vez mais, usuários e administradores estão recorrendo a programas gerenciadores de senhas para armazenar credenciais de login de forma criptografada. Outra tendência é a autenticação de dois fatores (2FA), uma técnica onde uma senha é complementada por um segundo "fator", geralmente um código enviado para o telefone ou outros dispositivos do usuário.

Desafio Contínuo: Acompanhar as tendências atuais de segurança, enquanto garante o fácil acesso dos usuários autorizados, é um desafio contínuo que deve ser enfrentado.
Tipo de Conta Nível de Privilégio Exemplo de Uso

Usuário comum Limitado (apenas seus arquivos) Tarefas diárias, navegação, documentos
Usuário de serviço Específico do serviço MySQL, Apache, PostgreSQL
Remote Access (SSH/FTP) Variável (configurável) Acesso remoto seguro

  • Use um gerenciador de senhas (ex: Bitwarden, KeePass)
  • Ative autenticação de dois fatores (2FA) sempre que possível
  • Nunca reutilize a mesma senha em múltiplos serviços
  • Nunca compartilhe senhas por e-mail ou mensagem
  • Para root, use sudo e desabilite login direto

3.6.2 Protegendo-se

Conforme você navega na web, você deixa uma pegada digital. Muita dessa informação é ignorada; parte dela é coletada para estatísticas de publicidade, e alguma pode ser usada para propósitos maliciosos.

A coisa mais fácil que você pode fazer é usar uma senha boa e única em todos os lugares, especialmente na sua máquina local. Uma boa senha tem pelo menos 10 caracteres e contém uma mistura de números, letras (maiúsculas e minúsculas) e símbolos especiais. Use um gerenciador de senhas como KeePassX para gerar senhas, e então você só precisa ter uma senha de login para sua máquina e uma senha para abrir seu arquivo do KeePassX.

Dica: Limite as informações que você fornece aos sites apenas ao que é necessário. Dar seu nome de solteira da mãe e data de nascimento pode ajudar a desbloquear seu login de rede social se você perder sua senha, mas as mesmas informações podem ser usadas para se passar por você junto ao seu banco.

Depois disso, faça questão de verificar atualizações periodicamente. O sistema pode ser configurado para verificar atualizações regularmente. Se houver atualizações relacionadas à segurança, você pode ser solicitado imediatamente a instalá-las.

3.6.3 Ferramentas de Privacidade

O uso de ferramentas modernas de privacidade, tanto no nível do servidor quanto do usuário, pode ajudar a prevenir invasões de sistema e acesso não autorizado a dados.

A boa notícia é que o Linux é, por padrão, um dos sistemas operacionais mais seguros já criados. Muitas das explorações que afetam outros sistemas operacionais simplesmente não funcionam no Linux devido à arquitetura subjacente. No entanto, ainda existem muitas fraquezas conhecidas que os hackers podem aproveitar, então o administrador de sistemas proativo é sábio em implantar ferramentas de privacidade que protegem seus usuários, bem como os sistemas que eles usam.

Criptografia é provavelmente a ferramenta de privacidade mais conhecida e amplamente implantada atualmente. Administradores implantam criptografia com chaves de autenticação em quase todos os sistemas que se comunicam com o mundo externo. Um exemplo bem conhecido é o padrão HyperText Transfer Protocol Secure (HTTPS) usado em servidores web para garantir que os dados transmitidos entre usuários e recursos online não possam ser interceptados enquanto trafegam na Internet aberta.

Redes privadas virtuais (VPN) têm sido usadas por empresas para conectar seus servidores remotos e funcionários por muitos anos. Agora estão ganhando popularidade entre usuários comuns que buscam proteger sua privacidade online. Elas funcionam criando um canal de comunicação criptografado entre dois sistemas, de modo que os dados transmitidos entre eles são embaralhados por um algoritmo que apenas os sistemas conhecem.

O projeto Tor está envolvido há muito tempo na criação de ferramentas de privacidade, como seu navegador Tor Browser, que funciona retransmitindo solicitações da Internet através de uma rede de servidores que impede que sites e outros descubram a identidade da pessoa que faz a solicitação.

Evolução Constante: Essas ferramentas estão em constante evolução e escolher quais são apropriadas para os usuários e sistemas envolvidos é uma parte essencial do papel do administrador de sistemas.
Ferramenta Nível de Proteção Melhor Para Exemplo de Uso

3.7 A Nuvem (Cloud)

Sem dúvida você já ouviu falar da nuvem. Seja usando o Google Docs para suas tarefas escolares ou armazenando músicas e fotos no iCloud, você provavelmente tem pelo menos parte do seu conteúdo digital hospedado em algum servidor na nuvem em algum lugar.

A computação em nuvem revolucionou a forma como acessamos a tecnologia. À medida que a conectividade e a velocidade da Internet aumentaram, tornou-se mais fácil mover recursos computacionais para locais remotos onde o conteúdo pode ser acessado, manipulado e compartilhado em todo o mundo. Organizações estão cada vez mais vendo a nuvem como essencial para seus negócios e operações.

A migração das aplicações e processos de TI de uma organização para serviços em nuvem, conhecida como adoção da nuvem, está rapidamente se tornando uma decisão estratégica de negócios para muitos. Com a adoção da nuvem crescendo significativamente em todo o mundo, a computação em nuvem não é mais apenas um slogan. É vista como uma das principais tecnologias disruptivas da próxima década, que transformará significativamente negócios, economias e vidas globalmente.

Fisicamente, uma nuvem pode ser descrita como recursos computacionais de um ou vários data centers remotos que podem ser acessados através da internet. A nuvem constrói sobre os benefícios de um data center e fornece soluções computacionais para organizações que precisam armazenar e processar dados, permitindo-lhes delegar o gerenciamento da infraestrutura de TI a terceiros.

O que pode ser armazenado na nuvem: Os dados e recursos que as organizações armazenam na nuvem podem incluir dados, servidores, armazenamento, hospedagem de aplicações, análises e uma infinidade de outros serviços.

Um modelo de implantação em nuvem fornece uma base para como a infraestrutura de nuvem é construída, gerenciada e acessada. Existem quatro modelos principais de implantação em nuvem:

1. Nuvem Pública (Public Cloud)

Uma nuvem pública é uma infraestrutura de nuvem implantada por um provedor para oferecer serviços de nuvem ao público em geral e organizações pela Internet. No modelo de nuvem pública, pode haver múltiplos inquilinos (consumidores) que compartilham recursos comuns da nuvem. Mais provavelmente, muitos de nós já acessaram recursos de nuvem pública em algum momento através de provedores como Amazon, Google e outros provedores populares.

2. Nuvem Privada (Private Cloud)

Uma nuvem privada é uma infraestrutura de nuvem configurada para uso exclusivo de uma organização específica. Quando comparada a uma nuvem pública, oferece maior grau de privacidade e controle sobre a infraestrutura, aplicações e dados. Pode ser hospedada em servidores gerenciados pela empresa que a utiliza ou através de um provedor de nuvem privada gerenciada como Rackspace ou IBM.

3. Nuvem Comunitária (Community Cloud)

Uma nuvem comunitária é uma infraestrutura configurada para uso exclusivo por um grupo de organizações com objetivos ou requisitos comuns. As organizações participantes tipicamente compartilham o custo do serviço. Esta opção pode ser mais cara que a nuvem pública, mas pode oferecer maior nível de controle e proteção contra ameaças externas.

4. Nuvem Híbrida (Hybrid Cloud)

Uma nuvem híbrida é composta por duas ou mais nuvens individuais, cada uma podendo ser privada, comunitária ou pública. Pode mudar ao longo do tempo à medida que nuvens componentes entram e saem. O uso dessa tecnologia permite portabilidade de dados e aplicações. Também permite que empresas aproveitem recursos externos enquanto mantêm o controle de recursos sensíveis.

3.7.1 Linux na Nuvem

O Linux desempenha um papel fundamental na computação em nuvem. Ele alimenta 90% da carga de trabalho em nuvem pública, a maioria dos servidores virtuais é baseada em alguma versão do kernel Linux, e o Linux é frequentemente usado para hospedar as aplicações por trás dos serviços de computação em nuvem.

O que torna o Linux tão adequado para viabilizar a computação em nuvem? Flexibilidade, Acessibilidade, Custo-benefício, Gerenciabilidade, Segurança, Virtualização e Contêineres.

Flexibilidade

A computação em nuvem fornece a capacidade de provisionar recursos de TI rapidamente e a qualquer momento. Essa agilidade permite desenvolvimento e experimentação rápidos que, por sua vez, facilitam a inovação essencial para pesquisa e desenvolvimento, descoberta de novos mercados e oportunidades de receita, criação de novos segmentos de clientes e desenvolvimento de novos produtos.

O Linux se destaca aqui porque é altamente adaptável. É modular por design e está no centro de um enorme ecossistema de aplicações de código aberto. Além disso, o Linux escala eficientemente, permitindo executar desde um pequeno sensor remoto até uma fazenda de servidores inteira.

Acessibilidade

Em um ambiente tradicional, os recursos de TI são acessados de dispositivos dedicados. Na computação em nuvem, aplicações e dados residem centralmente e são acessados de qualquer lugar através de uma rede a partir de qualquer dispositivo. Existe uma versão do Linux para cada um desses dispositivos.

Custo-Benefício

A computação em nuvem é atraente por ter o potencial de reduzir custos de TI. Os provedores de nuvem absorvem os custos de infraestrutura, mas precisam permanecer uma alternativa de baixo custo. Escolher o Linux é uma das soluções mais econômicas que os provedores podem implantar.

O kernel Linux é completamente gratuito, assim como muitas aplicações, utilitários e componentes de software adicionais. Organizações empresariais e governamentais podem optar por pagar por distribuições com suporte comercial, que ainda são mais econômicas quando comparadas aos concorrentes licenciados.

Gerenciabilidade

Embora o Linux tenha começado como um sistema operacional de nicho, sua presença generalizada na indústria de TI tornou o uso e a administração do Linux uma habilidade necessária para profissionais de TI. A natureza do Linux, construído sobre a linguagem C, também se presta a ferramentas de gerenciamento automatizado.

Uma parte significativa dos servidores Linux que operam na nuvem é criada e gerenciada por programas de gerenciamento automatizado, em vez de operadores humanos. Esse processo libera administradores para monitorar operações computacionais, em vez de configurar e atualizar sistemas manualmente.

Segurança

Ao usar uma solução em nuvem, especialmente uma nuvem pública, uma organização pode ter preocupações relacionadas à privacidade, ameaças externas e falta de controle sobre os recursos e dados de TI. O Linux ajuda a compensar essas questões porque é um dos sistemas operacionais mais seguros e confiáveis disponíveis.

O Linux é open source, o que significa que seu código-fonte está disponível para qualquer pessoa obter, revisar e modificar. Isso também significa que o código pode ser inspecionado quanto a vulnerabilidades e problemas de compatibilidade, resultando em um esforço extensivo da comunidade para corrigir esses problemas e manter a robusta reputação do Linux.

Virtualização

A virtualização é um dos avanços mais significativos que contribuíram para a viabilização da computação em nuvem. É o processo onde um computador físico (host) executa múltiplas cópias de um sistema operacional (cada cópia chamada de guest).

O sistema host executa um software chamado hypervisor que alterna recursos entre os vários guests. Com hypervisors bare metal, o hypervisor executa diretamente no hardware do computador, liberando mais recursos para as imagens dos guests.

A virtualização funciona porque os servidores passam a maior parte do tempo ociosos. Com software como Workstation e VirtualBox (VMWare e Oracle), é possível executar múltiplas máquinas virtuais em uma única CPU poderosa, otimizando o uso de recursos físicos e reduzindo drasticamente os custos.

Contêineres e Implantações Bare Metal

Com o surgimento de tecnologias de contêinerização como Docker e Kubernetes, o software de aplicação agora está sendo escrito para executar em um ambiente serverless. Os programadores estão criando software que faz uma única função de um sistema (como processamento de banco de dados ou armazenamento) que executa em um contêiner.

Esses contêineres são organizados em pods que executam dentro de um nó e podem se comunicar entre si. Os nós, por sua vez, são organizados e controlados por um nó mestre que fornece serviços a cada componente dentro da estrutura.

Construir aplicações dessa forma desacopla cada um dos componentes dos outros e da sobrecarga de executar um SO. Embora essas novas arquiteturas de programação estejam, de muitas maneiras, contornando a necessidade de um SO tradicional, a tecnologia subjacente que as faz funcionar ainda é o Linux.

# Comandos de virtualização e contêineres

# KVM (Kernel-based Virtual Machine)
virsh list --all          # Listar VMs
virsh start vm-name       # Iniciar VM
virsh shutdown vm-name    # Desligar VM

# Docker
docker ps                 # Listar contêineres em execução
docker run -it ubuntu     # Executar contêiner Ubuntu
docker build -t minha-app . # Construir imagem
docker-compose up -d      # Subir serviços com docker-compose

# Kubernetes
kubectl get pods          # Listar pods
kubectl get nodes         # Listar nós
kubectl apply -f arquivo.yaml  # Aplicar configuração

# VirtualBox (CLI)
VBoxManage list vms       # Listar VMs
VBoxManage startvm "VM Name" --type headless
