7.1 Introdução

No Linux, tudo é considerado um arquivo. Arquivos são usados para armazenar dados, como texto, gráficos e programas. Diretórios são um tipo de arquivo usado para armazenar outros arquivos; usuários do Windows e Mac OS X geralmente se referem a eles como pastas. Em qualquer caso, os diretórios são usados para fornecer uma estrutura de organização hierárquica. No entanto, essa estrutura pode ser um pouco diferente dependendo do tipo de sistema em uso.

Ao trabalhar em um sistema operacional Linux, é importante saber como manipular arquivos e diretórios. Algumas distribuições Linux possuem aplicações baseadas em interface gráfica (GUI) que permitem gerenciar arquivos, mas é vantajoso saber como realizar essas operações via linha de comando.

Sabia? No Linux, até mesmo dispositivos como discos rígidos, teclados e impressoras são representados como arquivos no sistema de arquivos.

7.2 Estrutura de Diretórios

Em um sistema Windows, o nível superior da estrutura de diretórios é chamado de Meu Computador. Dispositivos físicos, como discos rígidos, unidades USB, unidades de rede, aparecem em Meu Computador e cada um recebe uma letra de unidade, como C: ou D:.

As estruturas de diretórios mostradas abaixo são fornecidas apenas como exemplos. Esses diretórios podem não estar presentes no ambiente de máquina virtual deste curso.

Estrutura de Diretórios do Windows

Meu Computador
├── DVD Drive (D:)
│   └── Data
├── Hard Drive (C:)
│   ├── Program Files
│   ├── Users
│   └── Windows
└── USB Disk (E:)
    └── Data
Assim como o Windows, a estrutura de diretórios do Linux, tipicamente chamada de sistema de arquivos (filesystem), também possui um nível superior. No entanto, em vez de "Meu Computador", é chamado de diretório raiz (root directory), e é simbolizado pelo caractere barra /. Além disso, não há unidades no Linux; cada dispositivo físico é acessível sob um diretório, ao contrário de uma letra de unidade.

Estrutura de Diretórios do Linux

/
├── bin/     → Comandos essenciais do sistema
├── boot/    → Arquivos de inicialização
├── dev/     → Dispositivos (hardware)
├── etc/     → Arquivos de configuração
├── home/    → Diretórios dos usuários
├── lib/     → Bibliotecas compartilhadas
├── media/   → Pontos de montagem (CD, USB)
├── mnt/     → Montagem temporária
├── opt/     → Softwares opcionais
├── proc/    → Informações de processos
├── root/    → Diretório do usuário root
├── sbin/    → Comandos administrativos
├── srv/     → Dados de serviços
├── sys/     → Informações do kernel
├── tmp/     → Arquivos temporários
├── usr/     → Programas dos usuários
└── var/     → Dados variáveis (logs, spool)

Para visualizar o conteúdo do diretório raiz, use o comando ls com o caractere / como argumento:

sysadmin@localhost:~$ ls /
bin    etc    lib    mnt    root    sbin    tmp
boot   home   lib64  opt    run     srv     usr
dev    init   media  proc   sbin    sys     var
Observe que existem muitos diretórios com nomes descritivos, incluindo /boot, que contém os arquivos para inicializar o computador.

7.2.1 Diretório Home

O termo diretório home frequentemente confunde novos usuários Linux. Para começar, na maioria das distribuições Linux existe um diretório chamado home sob o diretório raiz /. 

/
├── bin/
├── boot/
├── dev/
├── etc/
├── home/          ← Diretório que contém os homes dos usuários
├── lib/
├── media/
├── mnt/
└── opt/

Sob este diretório /home existe um diretório para cada usuário no sistema. O nome do diretório é o mesmo que o nome do usuário, então um usuário chamado sysadmin teria um diretório home chamado /home/sysadmin. 

/home/
├── sysadmin/      ← Diretório home do usuário sysadmin
├── bob/           ← Diretório home do usuário bob
└── alice/         ← Diretório home do usuário alice

O diretório home é um diretório importante. Para começar, quando um usuário abre um shell, ele deve ser automaticamente colocado em seu diretório home, pois normalmente é onde ele faz a maior parte do seu trabalho.

Além disso, o diretório home é um dos poucos diretórios onde o usuário tem controle total para criar e excluir arquivos e diretórios adicionais. Na maioria das distribuições Linux, os únicos usuários que podem acessar os arquivos em um diretório home são o proprietário e o administrador do sistema. A maioria dos outros diretórios em um sistema de arquivos Linux é protegida com permissões de arquivo.

Permissões de arquivo e propriedade serão abordadas em detalhes posteriormente no curso.

O diretório home tem um símbolo especial usado para representá-lo: o caractere tilde ~. Assim, se o usuário sysadmin está logado, o caractere tilde ~ pode ser usado no lugar do diretório /home/sysadmin. 

sysadmin@localhost:~$ cd ~
sysadmin@localhost:~$ pwd
/home/sysadmin

Também é possível referir-se ao diretório home de outro usuário usando o caractere tilde ~ seguido pelo nome da conta do usuário. Por exemplo, ~bob seria o equivalente a /home/bob. 

sysadmin@localhost:~$ ls ~bob
Documentos  Downloads  Música  Desktop

7.2.2 Diretório Atual

Para determinar onde o usuário está localizado atualmente dentro do sistema de arquivos, o comando pwd (print working directory) pode ser usado: 

pwd [OPTIONS]
sysadmin@localhost:~$ pwd
/home/sysadmin

O comando pwd imprime o diretório de trabalho, que é a localização atual do usuário dentro do sistema de arquivos. A saída do comando acima indica que o usuário sysadmin está atualmente em seu diretório home, mostrado no sistema de arquivos abaixo: 

/
├── bin/
├── boot/
├── dev/
├── etc/
├── home/
│   └── sysadmin/     ← Você está aqui!
│       ├── Desktop/
│       ├── Documents/
│       ├── Downloads/
│       ├── Music/
│       ├── Pictures/
│       ├── Public/
│       ├── Templates/
│       └── Videos/
├── lib/
├── media/
├── mnt/
└── opt/

7.2.3 Mudando de Diretório

Quando um usuário abre um shell, ele tipicamente começa em seu diretório home. Quando você inicia uma máquina virtual neste curso, seja abrindo o curso ou após usar o botão de reset, você está logado como o usuário sysadmin e começa no diretório home desse usuário, destacado na imagem abaixo: 

/
├── bin/
├── boot/
├── dev/
├── etc/
├── home/
│   └── sysadmin/     ← Você começa aqui (home)
│       ├── Desktop/
│       ├── Documents/
│       ├── Downloads/
│       ├── Music/
│       ├── Pictures/
│       ├── Public/
│       ├── Templates/
│       └── Videos/
├── lib/
├── media/
├── mnt/
└── opt/

Para navegar pelo sistema de arquivos, use o comando cd (change directory).

cd [opções] [caminho]

Existe um diretório chamado Documents localizado no diretório home do usuário sysadmin. Para sair do diretório home e entrar no diretório Documents, use o nome do diretório como argumento para o comando cd: 

sysadmin@localhost:~$ cd Documents
sysadmin@localhost:~/Documents$
Considere isto: Para alguns comandos, nenhuma notícia é boa notícia; não há saída se o comando cd for bem-sucedido. Se o usuário tentar mudar para um diretório que não existe, o comando retorna uma mensagem de erro: 
sysadmin@localhost:~$ cd Junk
-bash: cd: Junk: No such file or directory

Quando usado sem argumentos, o comando cd leva o usuário de volta ao seu diretório home.

sysadmin@localhost:~/Documents$ cd
sysadmin@localhost:~$
Observe que nossas máquinas virtuais empregam um prompt que exibe o diretório de trabalho atual, enfatizado com a cor azul. No primeiro prompt, o caractere tilde ~ é equivalente a /home/sysadmin, representando o diretório home do usuário.

Após mudar de diretório, a nova localização ~/Documents também pode ser confirmada no novo prompt, novamente mostrada em azul. 

sysadmin@localhost:~$ cd Documents
sysadmin@localhost:~/Documents$

7.3 Caminhos (Paths)

O argumento para o comando cd é mais do que apenas o nome de um diretório; é na verdade um caminho (path). Um caminho é uma lista de diretórios separados pelo caractere /. Se você pensar no sistema de arquivos como um mapa, os caminhos são os endereços dos diretórios, que incluem instruções de navegação passo a passo; eles podem ser usados para indicar a localização de qualquer arquivo dentro do sistema de arquivos.

Por exemplo, /home/sysadmin é um caminho para o diretório home:

/
├── bin/
├── boot/
├── dev/
├── etc/
├── home/
│   └── sysadmin/     ← /home/sysadmin
│       ├── Desktop/
│       ├── Documents/
│       ├── Downloads/
│       ├── Music/
│       ├── Pictures/
│       ├── Public/
│       ├── Templates/
│       └── Videos/
├── lib/
├── media/
├── mnt/
└── opt/

Existem dois tipos de caminhos: absoluto e relativo.

Resumo: Caminhos (paths) são como endereços no sistema de arquivos. Eles podem ser absolutos (começando da raiz /) ou relativos (a partir do diretório atual).

7.3.1 Caminhos Absolutos

Caminhos absolutos permitem que o usuário especifique a localização exata de um diretório. Ele sempre começa no diretório raiz e, portanto, sempre começa com o caractere /. O caminho /home/sysadmin é um caminho absoluto; ele instrui o sistema a começar no diretório raiz /, entrar no diretório home e depois no diretório sysadmin. 

/
└── home/
    └── sysadmin/     ← /home/sysadmin (caminho absoluto)
        ├── Desktop/
        ├── Documents/
        ├── Downloads/
        ├── Music/
        ├── Pictures/
        ├── Public/
        ├── Templates/
        └── Videos/

Se o caminho /home/sysadmin for usado como argumento para o comando cd, ele move o usuário para o diretório home do usuário sysadmin. 

sysadmin@localhost:~/Documents$ cd /home/sysadmin
sysadmin@localhost:~$

Novamente, nenhuma saída significa que o comando foi bem-sucedido. Isso pode ser confirmado olhando para o prompt ou usando o comando pwd: 

sysadmin@localhost:~$ pwd
/home/sysadmin
Dica: Caminhos absolutos funcionam de qualquer lugar do sistema, pois sempre começam da raiz /. Eles são como um "endereço completo" no sistema de arquivos.

7.3.2 Caminhos Relativos

Caminhos relativos começam a partir do diretório atual. Um caminho relativo fornece direções para um arquivo relativo à localização atual no sistema de arquivos. Eles não começam com o caractere /. Em vez disso, começam com o nome de um diretório. Mais especificamente, caminhos relativos começam com o nome de um diretório contido dentro do diretório atual.

Dê outra olhada no primeiro exemplo do comando cd. O argumento é um exemplo do caminho relativo mais simples: o nome de um diretório dentro do diretório de trabalho atual. 

sysadmin@localhost:~$ cd Documents
sysadmin@localhost:~/Documents$

Se o usuário está localizado no diretório Documents, mover para o diretório Art pode ser feito de várias maneiras.

Estrutura do diretório Documents

/home/sysadmin/Documents/
├── School/
│   ├── Art/
│   ├── Engineering/
│   └── Math/
├── Work/
├── Adjectives.txt
├── alpha-first.txt
├── alpha-second.txt
├── Desktop/
├── Downloads/
├── Music/
├── Pictures/
├── Public/
├── Templates/
└── Videos/

O caminho absoluto para o diretório Art pode ser usado:

sysadmin@localhost:~/Documents$ cd /home/sysadmin/Documents/School/Art
sysadmin@localhost:~/Documents/School/Art$

Múltiplos caminhos relativos podem ser usados:

sysadmin@localhost:~/Documents$ cd School
sysadmin@localhost:~/Documents/School$ cd Art
sysadmin@localhost:~/Documents/School/Art$

No entanto, o método mais simples é usar um único caminho relativo que cubra a jornada do diretório de origem até o diretório de destino: 

sysadmin@localhost:~/Documents$ cd School/Art
sysadmin@localhost:~/Documents/School/Art$

Visualização do caminho percorrido

Documents/               (Você está aqui)
    └── School/
        └── Art/          (Destino: School/Art)

Use o comando pwd para confirmar a mudança:

sysadmin@localhost:~/Documents/School/Art$ pwd
/home/sysadmin/Documents/School/Art
Resumo: Caminhos relativos são como "endereços locais" - eles partem de onde você está. Caminhos absolutos são como "endereços completos" - eles partem da raiz /.

7.3.3 Atalhos

Os caracteres .. (dois pontos)

Independentemente de qual diretório o usuário está, dois caracteres ponto .. sempre representam um diretório acima do diretório atual, às vezes chamado de diretório pai (parent directory). Para sair do diretório Art e voltar para o diretório School: 

sysadmin@localhost:~/Documents/School/Art$ cd ..
sysadmin@localhost:~/Documents/School$
Documents/
└── School/
    ├── Art/        ← Você está aqui
    ├── Engineering/
    └── Math/

Depois de cd .. :
Documents/
└── School/        ← Agora você está aqui
    ├── Art/
    ├── Engineering/
    └── Math/

O ponto duplo também pode ser usado em caminhos mais longos. O seguinte caminho relativo pode ser usado para sair do diretório School para o diretório Downloads: 

/home/sysadmin/
├── Desktop/
├── Documents/
│   └── School/     ← Você está aqui
├── Downloads/      ← Destino
├── Music/
├── Pictures/
├── Public/
├── Templates/
└── Videos/
sysadmin@localhost:~/Documents/School$ cd ../Downloads
sysadmin@localhost:~/Downloads$

../Downloads significa: "vá um diretório acima (para Documents) e depois entre no diretório Downloads".

O caractere . (ponto simples)

Independentemente de qual diretório o usuário está, o ponto simples . sempre representa o diretório atual. Para o comando cd, este atalho não é muito útil, mas é útil para comandos cobertos em seções subsequentes. 

sysadmin@localhost:~$ cd .
sysadmin@localhost:~$
Resumo dos atalhos:
• . (ponto simples) = diretório atual
• .. (dois pontos) = diretório pai (um nível acima)

7.4 Listando Arquivos em um Diretório

Para os exemplos anteriores, imagens foram fornecidas para mostrar a estrutura do sistema de arquivos. Na prática, mapas como esses não são fornecidos, e os usuários devem confiar no que está disponível na linha de comando, tornando o comando ls (list) um dos mais poderosos para navegar pelo sistema de arquivos. 

ls [OPÇÃO] ... [ARQUIVO] ...

O comando ls é usado para exibir o conteúdo de um diretório e pode fornecer informações detalhadas sobre os arquivos. Por padrão, quando usado sem opções ou argumentos, ele lista os arquivos no diretório atual: 

sysadmin@localhost:~$ ls
Desktop  Documents  Downloads  Music  Pictures  Public  Templates  Videos

O comando ls também pode ser usado para listar o conteúdo de qualquer diretório no sistema de arquivos. Forneça o caminho para o diretório como um argumento: 

sysadmin@localhost:~$ ls /var
backups  cache  lib  local  lock  log  mail  opt  run  spool  tmp
Considere isto: Em muitas distribuições Linux, incluindo a usada em nossas máquinas virtuais, o comando ls usa cores para distinguir por tipo de arquivo. Por exemplo, diretórios podem ser exibidos em azul, arquivos executáveis em verde e links simbólicos em ciano.

A saída colorida não é o comportamento padrão para o comando ls, mas sim o efeito da opção --color. O ls parece executar essa coloração automaticamente porque existe um alias para o comando ls, então ele é executado com a opção --color. 

sysadmin@localhost:~$ type ls
ls is aliased to `ls --color=auto'

Para evitar usar o alias, coloque um caractere de barra invertida \ na frente do seu comando:

sysadmin@localhost:~$ \ls
Desktop  Documents  Downloads  Music  Pictures  Public  Templates  Videos
Dica: Usar \ls executa o comando original sem o alias, útil se você precisar de uma saída sem cores ou comportamentos personalizados.

7.4.1 Listando Arquivos Ocultos

Quando o comando ls é usado para exibir o conteúdo de um diretório, nem todos os arquivos são mostrados automaticamente. O comando ls omite arquivos ocultos por padrão. Um arquivo oculto é qualquer arquivo (ou diretório) que começa com um caractere ponto ..

Para exibir todos os arquivos, incluindo arquivos ocultos, use a opção -a no comando ls:

sysadmin@localhost:~$ ls -a
.    .bashrc    .selected_editor    Downloads    Public
..   .cache     Desktop              Music        Templates
.bash_logout    .profile    Documents    Pictures    Videos

Por que os arquivos são ocultos em primeiro lugar? A maioria dos arquivos ocultos são arquivos de personalização (customization files), projetados para personalizar como o Linux, seu shell ou programas funcionam. Por exemplo, o arquivo .bashrc no diretório home personaliza recursos do shell, como criar ou modificar variáveis e aliases.

Esses arquivos de personalização não são aqueles com os quais você trabalha regularmente, e tê-los exibidos dificulta encontrar outros arquivos.

Dica: Arquivos ocultos começam com . (ponto). Use ls -a para visualizá-los.

7.4.2 Listagem Detalhada (Long Display)

Cada arquivo tem detalhes associados a ele chamados metadados. Isso pode incluir informações como tamanho, propriedade ou timestamps. Para visualizar essas informações, use a opção -l no comando ls. Abaixo, uma listagem do diretório /var/log é usada como exemplo, pois fornece uma variedade de saída: 

sysadmin@localhost:~$ ls -l /var/log/
total 900                                                                       
-rw-r--r-- 1 root   root  15322 Dec 10 21:33 alternatives.log
drwxr-xr-x 1 root   root   4096 Jul 19 06:52 apt
-rw-r----- 1 syslog adm     371 Dec 15 16:38 auth.log
-rw-r--r-- 1 root   root  35330 May 26  2018 bootstrap.log
-rw-rw---- 1 root   utmp      0 May 26  2018 btmp
-rw-r----- 1 syslog adm     197 Dec 15 16:38 cron.log
-rw-r--r-- 1 root   adm   85083 Dec 10 21:33 dmesg
-rw-r--r-- 1 root   root 351960 Jul 19 06:52 dpkg.log
-rw-r--r-- 1 root   root  32064 Dec 10 21:33 faillog
drwxr-xr-x 2 root   root   4096 Jul 19 06:51 journal
-rw-rw-r-- 1 root   utmp 292584 Dec 15 16:38 lastlog
-rw-r----- 1 syslog adm   14185 Dec 15 16:38 syslog
-rw------- 1 root   root  64128 Dec 10 21:33 tallylog
-rw-rw-r-- 1 root   utmp    384 Dec 15 16:38 wtmp

Na saída acima, cada linha exibe metadados sobre um único arquivo. O seguinte descreve cada um dos campos de dados na saída do comando ls -l:

Tipo de Arquivo (File Type)

O primeiro caractere de cada linha indica o tipo de arquivo.

Símbolo Tipo de Arquivo Descrição
d directory Um arquivo usado para armazenar outros arquivos.
- regular file Inclui arquivos legíveis, imagens, binários e compactados.
l symbolic link Aponta para outro arquivo.
s socket Permite comunicação entre processos.
p pipe Permite comunicação entre processos.
b block file Usado para comunicar com hardware.
c character file Usado para comunicar com hardware.

O primeiro arquivo alternatives.log é um arquivo regular (-), enquanto o segundo arquivo apt é um diretório (d).

Permissões (Permissions)

drwxr-xr-x 2 root   root   4096 Jul 19 06:51 journal

Os próximos nove caracteres demonstram as permissões do arquivo. Permissões indicam como certos usuários podem acessar um arquivo.

Permissões serão abordadas em detalhes posteriormente no curso.

Contagem de Hard Links (Hard Link Count)

-rw-r----- 1 syslog adm     371 Dec 15 16:38 auth.log
drwxr-xr-x 2 root   root   4096 Jul 19 06:51 journal

Este número indica quantos hard links apontam para este arquivo.

Links serão abordados em detalhes posteriormente no curso.

Usuário Proprietário (User Owner)

-rw-r----- 1 syslog adm     197 Dec 15 16:38 cron.log

Cada arquivo é propriedade de uma conta de usuário. Isso é importante porque o proprietário tem o direito de definir permissões em um arquivo.

Propriedade de arquivos será abordada em detalhes posteriormente no curso.

Grupo Proprietário (Group Owner)

-rw-rw-r-- 1 root  utmp  292584 Dec 15 16:38 lastlog

Indica qual grupo é proprietário deste arquivo. Isso é importante porque qualquer membro deste grupo tem um conjunto de permissões sobre o arquivo.

Tamanho do Arquivo (File Size)

-rw-r----- 1 syslog adm   14185 Dec 15 16:38 syslog

Exibe o tamanho do arquivo em bytes.

Para diretórios, este valor não descreve o tamanho total do diretório, mas sim quantos bytes são reservados para manter o controle dos nomes de arquivos no diretório. Em outras palavras, ignore este campo para diretórios.

Timestamp

-rw-rw---- 1 root   utmp      0 May 26  2018 btmp

Indica o momento em que o conteúdo do arquivo foi modificado pela última vez. Para diretórios, este timestamp indica a última vez que um arquivo foi adicionado ou removido do diretório.

Nome do Arquivo (File Name)

-rw-r--r-- 1 root   root  35330 May 26  2018 bootstrap.log

O campo final contém o nome do arquivo ou diretório.

No caso de links simbólicos, o nome do link é exibido junto com uma seta e o caminho do arquivo original.

lrwxrwxrwx. 1 root root 22 Nov 6 2018 /etc/grub.conf -> ../boot/grub/grub.conf
Links simbólicos serão abordados em detalhes posteriormente no curso.

7.4.3 Tamanhos Legíveis para Humanos

A opção -l no comando ls exibe tamanhos de arquivos em bytes. Para arquivos de texto, um byte é 1 caractere. Para arquivos menores, tamanhos em bytes são adequados. No entanto, para arquivos maiores, é difícil compreender o tamanho do arquivo. Por exemplo, considere a saída do seguinte comando: 

sysadmin@localhost:~$ ls -l /var/log/lastlog                                    
-rw-rw-r-- 1 root utmp 292584 Dec 15 16:38 /var/log/lastlog

O tamanho do arquivo é difícil de determinar em bytes. 292584 é um arquivo grande ou pequeno? Parece relativamente grande, mas é difícil determinar usando bytes.

Pense desta forma: se alguém desse a distância entre Boston e Nova York usando polegadas, esse valor seria sem sentido. A maioria das pessoas pensa em termos de milhas ou quilômetros.

Às vezes é preferível apresentar o tamanho do arquivo em um formato mais legível para humanos, como megabytes ou gigabytes. Para conseguir isso, adicione a opção -h ao comando ls: 

sysadmin@localhost:~$ ls -lh /var/log/lastlog                                   
-rw-rw-r-- 1 root utmp 286K Dec 15 16:38 /var/log/lastlog
Importante: A opção -h deve ser usada com a opção -l.
Resumo: ls -lh exibe tamanhos de arquivo em formato legível (K, M, G) em vez de bytes.

7.4.4 Listando Diretórios

Quando a opção -d é usada, ela se refere ao diretório atual, e não ao conteúdo dentro dele. Sem outras opções, é um tanto sem significado. Lembre-se de que o diretório atual é sempre referenciado com um único caractere ponto .: 

sysadmin@localhost:~$ ls -d
.

Para usar a opção -d de maneira significativa, é necessária a adição da opção -l. Neste caso, note que o seguinte comando lista os detalhes do conteúdo no diretório /home/sysadmin: 

sysadmin@localhost:~$ ls -l
total 32
drwxr-xr-x 2 sysadmin sysadmin 4096 Dec 10 21:33 Desktop
drwxr-xr-x 4 sysadmin sysadmin 4096 Dec 10 21:33 Documents
drwxr-xr-x 2 sysadmin sysadmin 4096 Dec 10 21:33 Downloads
drwxr-xr-x 2 sysadmin sysadmin 4096 Dec 10 21:33 Music
drwxr-xr-x 2 sysadmin sysadmin 4096 Dec 10 21:33 Pictures
drwxr-xr-x 2 sysadmin sysadmin 4096 Dec 10 21:33 Public
drwxr-xr-x 2 sysadmin sysadmin 4096 Dec 10 21:33 Templates
drwxr-xr-x 2 sysadmin sysadmin 4096 Dec 10 21:33 Videos

Em comparação, o próximo comando lista o diretório /home/sysadmin em si:

sysadmin@localhost:~$ ls -ld
drwxr-xr-x 1 sysadmin sysadmin 224 Nov  7 17:07 .

Note o único ponto no final da listagem longa. Isso indica que o diretório atual está sendo listado, e não o seu conteúdo.

Resumo: ls -l lista o conteúdo do diretório. ls -ld lista o próprio diretório.

7.4.5 Listagem Recursiva

Há momentos em que você deseja exibir todos os arquivos em um diretório, bem como todos os arquivos em todos os subdiretórios sob esse diretório. Isso é chamado de listagem recursiva.

Para realizar uma listagem recursiva, use a opção -R no comando ls:

sysadmin@localhost:~$ ls -R /etc/ppp
/etc/ppp:
ip-down.d  ip-up.d         

/etc/ppp/ip-down.d:
bind9

/etc/ppp/ip-up.d:
bind9

Note que no exemplo anterior, os arquivos no diretório /etc/ppp foram listados primeiro. Depois disso, o conteúdo de seus subdiretórios /etc/ppp/ip-down.d e /etc/ppp/ip-up.d foram listados.

Cuidado com esta opção: por exemplo, executar o comando no diretório raiz listaria todos os arquivos no sistema de arquivos, incluindo todos os arquivos em qualquer dispositivo USB conectado e DVD no sistema. Limite o uso de listagens recursivas a estruturas de diretórios menores.

7.4.6 Ordenando uma Listagem

Por padrão, o comando ls ordena arquivos alfabeticamente pelo nome do arquivo. Às vezes, pode ser útil ordenar arquivos usando critérios diferentes.

Para ordenar arquivos por tamanho, podemos usar a opção -S. Note a diferença na saída dos dois comandos a seguir. Os mesmos arquivos e diretórios são listados, mas em uma ordem diferente: 

sysadmin@localhost:~$ ls /etc/ssh
moduli              ssh_host_ecdsa_key.pub    ssh_host_rsa_key      sshd_config
ssh_config          ssh_host_ed25519_key      ssh_host_rsa_key.pub
ssh_host_ecdsa_key  ssh_host_ed25519_key.pub  ssh_import_id

sysadmin@localhost:~$ ls -S /etc/ssh
moduli            ssh_host_ed25519_key  ssh_host_ecdsa_key.pub
sshd_config       ssh_host_rsa_key.pub  ssh_host_ed25519_key.pub
ssh_host_rsa_key  ssh_import_id
ssh_config        ssh_host_ecdsa_key
Nota: A opção acima usa a letra S maiúscula.

Embora a opção -S funcione sozinha, é mais útil quando usada com a opção -l para que os tamanhos dos arquivos fiquem visíveis. O seguinte comando lista arquivos do maior para o menor e exibe o tamanho real do arquivo. 

sysadmin@localhost:~$ ls -lS /etc/ssh
total 580
-rw-r--r-- 1 root root 553122 Feb 10  2018 moduli
-rw-r--r-- 1 root root   3264 Feb 10  2018 sshd_config
-rw------- 1 root root   1679 Jul 19 06:52 ssh_host_rsa_key
-rw-r--r-- 1 root root   1580 Feb 10  2018 ssh_config
-rw------- 1 root root    411 Jul 19 06:52 ssh_host_ed25519_key
-rw-r--r-- 1 root root    399 Jul 19 06:52 ssh_host_rsa_key.pub
-rw-r--r-- 1 root root    338 Jul 19 06:52 ssh_import_id
-rw------- 1 root root    227 Jul 19 06:52 ssh_host_ecdsa_key
-rw-r--r-- 1 root root    179 Jul 19 06:52 ssh_host_ecdsa_key.pub
-rw-r--r-- 1 root root     99 Jul 19 06:52 ssh_host_ed25519_key.pub

Também pode ser útil usar a opção -h para exibir tamanhos de arquivo legíveis para humanos:

sysadmin@localhost:~$ ls -lSh /etc/ssh                                
total 580K                                                                      
-rw-r--r-- 1 root root 541K Feb 10  2018 moduli
-rw-r--r-- 1 root root 3.2K Feb 10  2018 sshd_config
-rw------- 1 root root 1.7K Jul 19 06:52 ssh_host_rsa_key
-rw-r--r-- 1 root root 1.6K Feb 10  2018 ssh_config
-rw------- 1 root root  411 Jul 19 06:52 ssh_host_ed25519_key
-rw-r--r-- 1 root root  399 Jul 19 06:52 ssh_host_rsa_key.pub
-rw-r--r-- 1 root root  338 Jul 19 06:52 ssh_import_id
-rw------- 1 root root  227 Jul 19 06:52 ssh_host_ecdsa_key
-rw-r--r-- 1 root root  179 Jul 19 06:52 ssh_host_ecdsa_key.pub
-rw-r--r-- 1 root root   99 Jul 19 06:52 ssh_host_ed25519_key.pub

A opção -t ordena arquivos com base no horário em que foram modificados. Ela lista os arquivos modificados mais recentemente primeiro. Esta opção pode ser usada sozinha, mas, novamente, geralmente é mais útil quando combinada com a opção -l: 

sysadmin@localhost:~$ ls -tl /etc/ssh                                 
total 580
-rw------- 1 root root    227 Jul 19 06:52 ssh_host_ecdsa_key
-rw-r--r-- 1 root root    179 Jul 19 06:52 ssh_host_ecdsa_key.pub
-rw------- 1 root root    411 Jul 19 06:52 ssh_host_ed25519_key
-rw-r--r-- 1 root root     99 Jul 19 06:52 ssh_host_ed25519_key.pub
-rw------- 1 root root   1679 Jul 19 06:52 ssh_host_rsa_key
-rw-r--r-- 1 root root    399 Jul 19 06:52 ssh_host_rsa_key.pub
-rw-r--r-- 1 root root    338 Jul 19 06:52 ssh_import_id
-rw-r--r-- 1 root root 553122 Feb 10  2018 moduli
-rw-r--r-- 1 root root   1580 Feb 10  2018 ssh_config
-rw-r--r-- 1 root root   3264 Feb 10  2018 sshd_config

É importante lembrar que a data de modificação em diretórios representa a última vez que um arquivo foi adicionado ou removido do diretório.

Se os arquivos em um diretório foram modificados há muitos dias ou meses, pode ser mais difícil saber exatamente quando foram modificados, pois apenas a data é fornecida para arquivos mais antigos. Para informações de horário de modificação mais detalhadas, você pode usar a opção --full-time para exibir o timestamp completo (incluindo horas, minutos, segundos). Ela assumirá a opção -l automaticamente: 

sysadmin@localhost:~$ ls -t --full-time /etc/ssh
total 580
-rw------- 1 root root    227 2018-07-19 06:52:16.000000000 +0000 ssh_host_ecdsa_key
-rw-r--r-- 1 root root    179 2018-07-19 06:52:16.000000000 +0000 ssh_host_ecdsa_key.pub
-rw------- 1 root root    411 2018-07-19 06:52:16.000000000 +0000 ssh_host_ed25519_key
-rw-r--r-- 1 root root     99 2018-07-19 06:52:16.000000000 +0000 ssh_host_ed25519_key.pub
-rw------- 1 root root   1679 2018-07-19 06:52:16.000000000 +0000 ssh_host_rsa_key
-rw-r--r-- 1 root root    399 2018-07-19 06:52:16.000000000 +0000 ssh_host_rsa_key.pub
-rw-r--r-- 1 root root    338 2018-07-19 06:52:16.000000000 +0000 ssh_import_id
-rw-r--r-- 1 root root 553122 2018-02-10 02:31:46.000000000 +0000 moduli
-rw-r--r-- 1 root root   1580 2018-02-10 02:31:46.000000000 +0000 ssh_config
-rw-r--r-- 1 root root   3264 2018-02-10 02:31:46.000000000 +0000 sshd_config

É possível realizar uma ordenação reversa usando a opção -r. Ela pode ser usada sozinha ou combinada com as opções -S ou -t. O seguinte comando ordenará arquivos por tamanho, do menor para o maior: 

sysadmin@localhost:~$ ls -lrS /etc/ssh
total 580
-rw-r--r-- 1 root root     99 Jul 19 06:52 ssh_host_ed25519_key.pub
-rw-r--r-- 1 root root    179 Jul 19 06:52 ssh_host_ecdsa_key.pub
-rw------- 1 root root    227 Jul 19 06:52 ssh_host_ecdsa_key
-rw-r--r-- 1 root root    338 Jul 19 06:52 ssh_import_id
-rw-r--r-- 1 root root    399 Jul 19 06:52 ssh_host_rsa_key.pub
-rw------- 1 root root    411 Jul 19 06:52 ssh_host_ed25519_key
-rw-r--r-- 1 root root   1580 Feb 10  2018 ssh_config
-rw------- 1 root root   1679 Jul 19 06:52 ssh_host_rsa_key
-rw-r--r-- 1 root root   3264 Feb 10  2018 sshd_config
-rw-r--r-- 1 root root 553122 Feb 10  2018 moduli

O seguinte comando listará arquivos por data de modificação, do mais antigo para o mais novo:

sysadmin@localhost:~$ ls -lrt /etc/ssh                                 
total 580
-rw-r--r-- 1 root root   3264 Feb 10  2018 sshd_config
-rw-r--r-- 1 root root   1580 Feb 10  2018 ssh_config
-rw-r--r-- 1 root root 553122 Feb 10  2018 moduli
-rw-r--r-- 1 root root    338 Jul 19 06:52 ssh_import_id
-rw-r--r-- 1 root root    399 Jul 19 06:52 ssh_host_rsa_key.pub
-rw------- 1 root root   1679 Jul 19 06:52 ssh_host_rsa_key
-rw-r--r-- 1 root root     99 Jul 19 06:52 ssh_host_ed25519_key.pub
-rw------- 1 root root    411 Jul 19 06:52 ssh_host_ed25519_key
-rw-r--r-- 1 root root    179 Jul 19 06:52 ssh_host_ecdsa_key.pub
-rw------- 1 root root    227 Jul 19 06:52 ssh_host_ecdsa_key
Resumo das opções de ordenação:
• -S - ordena por tamanho (maior primeiro)
• -t - ordena por data/hora (mais recente primeiro)
• -r - ordenação reversa
• --full-time - mostra timestamp completo
