Trabalhando com Texto

Working With Text

10.1 Introdução

Um grande número dos arquivos em um sistema de arquivos típico são arquivos de texto. Arquivos de texto contêm apenas texto, sem recursos de formatação que você poderia ver em um arquivo de processador de texto.

Por existirem tantos desses arquivos em um sistema Linux típico, um número significativo de comandos existe para ajudar os usuários a manipular arquivos de texto. Existem comandos para visualizar e modificar esses arquivos de várias maneiras.

Além disso, existem recursos disponíveis no shell para controlar a saída dos comandos, então ao invés de ter a saída exibida na janela do terminal, a saída pode ser redirecionada para outro arquivo ou para outro comando. Esses recursos de redirecionamento proporcionam aos usuários um ambiente muito mais flexível e poderoso para trabalhar.

10.1.1 Visualizando Arquivos no Terminal

O comando cat, abreviação de concatenate (concatenar), é um comando simples mas útil cujas funções incluem criar e exibir arquivos de texto, bem como combinar cópias de arquivos de texto. Um dos usos mais populares do cat é exibir o conteúdo de arquivos de texto. Para exibir um arquivo na saída padrão usando o comando cat, digite o comando seguido pelo nome do arquivo: 

sysadmin@localhost:~$ cd Documents
sysadmin@localhost:~/Documents$ cat food.txt 
Food is good.

Embora o terminal seja a saída padrão deste comando, o comando cat também pode ser usado para redirecionar o conteúdo de arquivos para outros arquivos ou como entrada para outro comando, utilizando caracteres de redirecionamento.

Dica: O nome "cat" vem de "concatenate", pois ele pode unir vários arquivos em sequência.

10.1.2 Visualizando Arquivos Usando um Pager

Embora visualizar arquivos pequenos com o comando cat não apresente problemas, ele não é uma escolha ideal para arquivos grandes. O comando cat não fornece maneiras fáceis de pausar e reiniciar a exibição, então todo o conteúdo do arquivo é despejado na tela.

Para arquivos maiores, use um comando pager para visualizar o conteúdo. Comandos pager exibem uma página de dados por vez, permitindo que você avance e retroceda no arquivo usando teclas de movimento.

Existem dois comandos pager comumente usados:

  • O comando less fornece uma capacidade de paginação muito avançada. Ele é geralmente o pager padrão usado por comandos como o comando man.
  • O comando more existe desde os primórdios do UNIX. Embora tenha menos recursos que o comando less, o comando less não está incluído em todas as distribuições Linux. O comando more está sempre disponível.

Os comandos more e less permitem que os usuários naveguem pelo documento usando comandos de teclado. Como os desenvolvedores basearam o comando less na funcionalidade do comando more, todos os comandos de teclado disponíveis no comando more também funcionam no comando less.

O foco do nosso conteúdo está no comando less, mais avançado. O comando more ainda é útil de se lembrar para quando o comando less não estiver disponível. Lembre-se que a maioria dos comandos de teclado fornecidos funciona para ambos os comandos.

Atenção: O nome "less" é um trocadilho com a frase "less is more" (menos é mais), fazendo referência ao comando "more" original.

10.1.2.1 Comandos de Movimentação do Pager

Para visualizar um arquivo com o comando less, passe o nome do arquivo como argumento:

sysadmin@localhost:~/Documents$ less words

Existem muitos comandos de movimentação para o comando less, cada um com múltiplas teclas ou combinações de teclas possíveis. Embora isso possa parecer intimidante, não é necessário memorizar todos esses comandos de movimentação. 10.1.2.2 Comandos de Busca do Pager

Existem duas maneiras de buscar no comando less: buscando para frente ou para trás a partir da sua posição atual.

Para iniciar uma busca para frente a partir da sua posição atual, use a tecla barra /. Em seguida, digite o texto ou padrão a ser encontrado e pressione a tecla Enter. 

Abdul
Abdul's
Abe
/frog

Se uma correspondência for encontrada, o cursor se move no documento até a correspondência. Por exemplo, no gráfico a seguir a expressão "frog" foi procurada no arquivo words: 

bullfrog
bullfrog's
bullfrogs
bullheaded
bullhorn
bullhorn's

Observe que "frog" não precisava ser uma palavra por si só. Observe também que enquanto o comando less se moveu para a primeira correspondência a partir da posição atual, todas as correspondências foram destacadas.

Se nenhuma correspondência for encontrada à frente da sua posição atual, a última linha da tela reportará Pattern not found (Padrão não encontrado): 

Pattern not found (press RETURN)

Para buscar para trás a partir da sua posição atual, pressione a tecla ponto de interrogação ?, então digite o texto ou padrão a ser encontrado e pressione a tecla Enter. O cursor se move para trás até a primeira correspondência que conseguir encontrar ou reporta que o padrão não pode ser encontrado.

Se mais de uma correspondência for encontrada em uma busca, use a tecla n para avançar para a próxima correspondência e use a combinação de teclas Shift+N para voltar para uma correspondência anterior.

Os termos de busca na verdade usam padrões chamados expressões regulares (regular expressions). Mais detalhes sobre expressões regulares são fornecidos mais adiante neste capítulo.

Tecla Ação
/ (barra) Buscar para frente a partir da posição atual
? (ponto de interrogação) Buscar para trás a partir da posição atual
n Avançar para a próxima correspondência
Shift+N ou N Voltar para a correspondência anterior
Dica: As buscas no less diferenciam maiúsculas de minúsculas por padrão. Use -i ao iniciar o less para ignorar diferenças de caixa.

10.1.3 Head e Tail

Os comandos head e tail são usados para exibir apenas as primeiras ou as últimas linhas de um arquivo, respectivamente (ou, quando usados com um pipe, a saída de um comando anterior). Por padrão, os comandos head e tail exibem dez linhas do arquivo que é fornecido como argumento.

Por exemplo, o seguinte comando exibe as primeiras dez linhas do arquivo /etc/sysctl.conf:

sysadmin@localhost:~/Documents$ cd
sysadmin@localhost:~$ head /etc/sysctl.conf
#
# /etc/sysctl.conf - Configuration file for setting system variables
# See /etc/sysctl.d/ for additional system variables
# See sysctl.conf (5) for information.
#

#kernel.domainname = example.com

# Uncomment the following to stop low-level messages on console
#kernel.printk = 3 4 1 3

Passar um número como opção fará com que ambos os comandos head e tail exibam o número especificado de linhas, em vez das dez padrão. Por exemplo, para exibir as últimas cinco linhas do arquivo /etc/sysctl.conf use a opção -5: 

sysadmin@localhost:~$ tail -5 /etc/sysctl.conf
# Protects against creating or following links under certain conditions
# Debian kernels have both set to 1 (restricted)
# See https://www.kernel.org/doc/Documentation/sysctl/fs.txt
#fs.protected_hardlinks=0
#fs.protected_symlinks=0

A opção -n também pode ser usada para indicar quantas linhas exibir. Passe um número como argumento para a opção: 

sysadmin@localhost:~$ head -n 3 /etc/sysctl.conf
#
# /etc/sysctl.conf - Configuration file for setting system variables
# See /etc/sysctl.d/ for additional system variables

Opção com Valor Negativo

Tradicionalmente no UNIX, o número de linhas a serem exibidas era especificado como uma opção em qualquer um dos comandos, então -3 significava mostrar três linhas. Para o comando tail, tanto -3 quanto -n -3 ainda significam mostrar três linhas.

No entanto, a versão GNU do comando head reconhece -n -3 como "mostrar tudo exceto as últimas três linhas", e ainda assim o comando head reconhece a opção -3 como "mostrar as primeiras três linhas".

Opção com Valor Positivo

A versão GNU do comando tail permite uma variação de como especificar o número de linhas a serem impressas. Se a opção -n for usada com um número prefixado pelo sinal de mais (+), então o comando tail reconhece isso como "exibir o conteúdo começando na linha especificada e continuando até o final".

Por exemplo, o seguinte comando exibe o conteúdo do /etc/passwd da linha 25 até o final do arquivo:

sysadmin@localhost:~$ nl /etc/passwd | tail -n +25
    25  sshd:x:103:65534::/var/run/sshd:/usr/sbin/nologin
    26  operator:x:1000:37::/root:/bin/sh
    27  sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

Considere Isto

Alterações em tempo real em arquivos podem ser visualizadas usando a opção -f no comando tail — útil quando você quer ver as mudanças em um arquivo conforme elas acontecem.

Um bom exemplo disso seria ao visualizar arquivos de log como administrador de sistema. Arquivos de log podem ser usados para solucionar problemas e administradores frequentemente os visualizam de forma "interativa" com o comando tail enquanto executam comandos em uma janela separada.

Por exemplo, se você fizer login como usuário root, você pode solucionar problemas com o servidor de email visualizando as alterações em tempo real no arquivo de log /var/log/mail.log.

Comando Descrição Exemplo
head Exibe as primeiras 10 linhas head arquivo.txt
head -n N Exibe as primeiras N linhas head -n 20 arquivo.txt
tail Exibe as últimas 10 linhas tail arquivo.txt
tail -n N Exibe as últimas N linhas tail -n 15 arquivo.txt
tail -f Acompanha alterações em tempo real tail -f /var/log/syslog
tail -n +N Exibe da linha N até o final tail -n +25 /etc/passwd
Dica: Use tail -f para monitorar logs em tempo real. Pressione Ctrl+C para sair do modo de acompanhamento.

10.2 Pipes de Linha de Comando

O caractere pipe | pode ser usado para enviar a saída de um comando para outro. Tipicamente, quando um comando tem saída ou gera um erro, a saída é exibida na tela; no entanto, isso não precisa ser sempre assim. Ao invés de ser impressa na tela, a saída de um comando se torna a entrada para o próximo comando. Esta ferramenta pode ser poderosa, especialmente ao procurar por dados específicos; o pipe é frequentemente usado para refinar os resultados de um comando inicial.

Nos exemplos anteriores, os comandos head e tail recebiam arquivos como argumentos para operar. No entanto, o caractere pipe permite que você utilize esses comandos não apenas em arquivos, mas também na saída de outros comandos. Isso pode ser útil ao listar um diretório grande, por exemplo o diretório /etc:

O comando anterior lista um grande número de arquivos. Se você executar isso no terminal, a saída é cortada e só pode ser visualizada rolando para cima. Para visualizar mais facilmente o início da saída, use pipe com o comando head. O exemplo a seguir exibe apenas as primeiras dez linhas: 

sysadmin@localhost:~$ ls /etc | head

A saída completa do comando ls é passada pelo shell para o comando head ao invés de ser impressa na tela. O comando head recebe esta saída do comando ls como dados de entrada, e a saída do head é então impressa na tela.

Múltiplos pipes podem ser usados consecutivamente para encadear múltiplos comandos. Se três comandos são conectados por pipe, a saída do primeiro comando é passada para o segundo comando. Então, a saída do segundo comando é passada para o terceiro comando. A saída do terceiro comando seria então impressa na tela.

É importante escolher cuidadosamente a ordem em que os comandos são pipe, pois cada comando vê apenas a entrada do comando anterior. Os exemplos abaixo ilustram isso usando o comando nl, que adiciona números de linha à saída. No primeiro exemplo, o comando nl é usado para numerar as linhas da saída do comando ls anterior: 

sysadmin@localhost:~$ ls /etc/ssh | nl
     1  moduli
     2  ssh_config
     3  ssh_host_ecdsa_key
     4  ssh_host_ecdsa_key.pub
     5  ssh_host_ed25519_key
     6  ssh_host_ed25519_key.pub
     7  ssh_host_rsa_key
     8  ssh_host_rsa_key.pub
     9  ssh_import_id
    10  sshd_config

No próximo exemplo, note que o comando ls é executado primeiro e sua saída é enviada para o comando nl, numerando todas as linhas da saída do comando ls. Então o comando tail é executado, exibindo as últimas cinco linhas da saída do comando nl: 

sysadmin@localhost:~$ ls /etc/ssh | nl | tail -5
     6  ssh_host_ed25519_key.pub
     7  ssh_host_rsa_key
     8  ssh_host_rsa_key.pub
     9  ssh_import_id
    10  sshd_config

Compare a saída acima com o próximo exemplo:

sysadmin@localhost:~$ ls /etc/ssh | tail -5 | nl
     1  ssh_host_ed25519_key.pub
     2  ssh_host_rsa_key
     3  ssh_host_rsa_key.pub
     4  ssh_import_id
     5  sshd_config

Observe como os números das linhas são diferentes. Por quê?

No segundo exemplo, a saída do comando ls é primeiro enviada para o comando tail que captura apenas as últimas cinco linhas da saída. Então o comando tail envia essas cinco linhas para o comando nl, que as numera de 1 a 5.

Pipes podem ser poderosos, mas é necessário considerar como os comandos são pipe para garantir que a saída desejada seja exibida.

Dica: Pense no pipe como um "encanamento" — a saída de um comando flui para dentro do próximo comando. A ordem dos comandos importa e muda o resultado final!
Comando Descrição Exemplo
command1 | command2 Envia a saída de command1 para a entrada de command2 ls /etc | head
command1 | command2 | command3 Encadeia múltiplos comandos com pipe ls /etc/ssh | nl | tail -5

10.3 Redirecionamento de Entrada/Saída

O redirecionamento de Entrada/Saída (I/O) permite que informações da linha de comando sejam passadas para diferentes fluxos (streams). Antes de discutir redirecionamento, é importante entender os fluxos padrão (standard streams).

STDIN

Entrada padrão, ou STDIN, são informações normalmente inseridas pelo usuário via teclado. Quando um comando solicita dados ao shell, o shell fornece ao usuário a capacidade de digitar comandos que, por sua vez, são enviados ao comando como STDIN.

STDOUT

Saída padrão, ou STDOUT, é a saída normal dos comandos. Quando um comando funciona corretamente (sem erros), a saída que ele produz é chamada de STDOUT. Por padrão, STDOUT é exibido na janela do terminal onde o comando está sendo executado. STDOUT também é conhecido como fluxo ou canal #1.

STDERR

Erro padrão, ou STDERR, são mensagens de erro geradas por comandos. Por padrão, STDERR é exibido na janela do terminal onde o comando está sendo executado. STDERR também é conhecido como fluxo ou canal #2.

O redirecionamento de I/O permite que o usuário redirecione STDIN para que os dados venham de um arquivo e STDOUT/STDERR para que a saída vá para um arquivo. O redirecionamento é alcançado usando os caracteres de seta < >.

Fluxo Descrição Canal Padrão
STDIN Entrada padrão (teclado) 0 stdin (teclado)
STDOUT Saída padrão (normal) 1 stdout (terminal)
STDERR Erro padrão 2 stderr (terminal)
Dica: Pense nos canais como "portas": canal 0 para entrada, canal 1 para saída normal, canal 2 para erros.

10.3.1 STDOUT

O STDOUT pode ser direcionado para arquivos. Para começar, observe a saída do seguinte comando echo que exibe na tela: 

sysadmin@localhost:~$ echo "Line 1"
Line 1

Usando o caractere >, a saída pode ser redirecionada para um arquivo:

sysadmin@localhost:~$ echo "Line 1" > example.txt

Este comando não exibe saída porque o STDOUT foi enviado para o arquivo example.txt ao invés da tela. Você pode ver o novo arquivo com a saída do comando ls. 

sysadmin@localhost:~$ ls
Desktop    Downloads  Pictures  Templates  example.txt
Documents  Music      Public    Videos

O arquivo contém a saída do comando echo, que pode ser visualizada com o comando cat:

sysadmin@localhost:~$ cat example.txt                                  
Line 1

É importante perceber que a seta única > sobrescreve qualquer conteúdo de um arquivo existente: 

sysadmin@localhost:~$ cat example.txt
Line 1
sysadmin@localhost:~$ echo "New line 1" > example.txt
sysadmin@localhost:~$ cat example.txt
New line 1

O conteúdo original do arquivo se foi, substituído pela saída do novo comando echo.

Também é possível preservar o conteúdo de um arquivo existente adicionando a ele (appending). Use dois caracteres >> para adicionar ao final de um arquivo ao invés de sobrescrevê-lo: 

sysadmin@localhost:~$ cat example.txt
New line 1
sysadmin@localhost:~$ echo "Another line" >> example.txt
sysadmin@localhost:~$ cat example.txt
New line 1
Another line

Ao invés de ser sobrescrita, a saída do comando echo é adicionada ao final do arquivo.

Operador Nome Ação
> Redirecionamento Sobrescreve o arquivo (cria se não existir)
>> Append (adicionar) Adiciona ao final do arquivo
Cuidado! Usar > com um arquivo existente apaga todo o conteúdo anterior. Sempre verifique se não vai perder dados importantes!

10.3.2 STDERR

O STDERR pode ser redirecionado de forma semelhante ao STDOUT. Ao usar o caractere de seta para redirecionar, assume-se o fluxo #1 (STDOUT), a menos que outro fluxo seja especificado. Assim, o fluxo #2 deve ser especificado ao redirecionar o STDERR, colocando o número 2 antes do caractere >.

Para demonstrar o redirecionamento do STDERR, primeiro observe o seguinte comando que produz um erro porque o diretório especificado não existe: 

sysadmin@localhost:~$ ls /fake
ls: cannot access /fake: No such file or directory

Note que não há nada no exemplo acima que indique que a saída é STDERR. A saída é claramente uma mensagem de erro, mas como você poderia dizer que ela está sendo enviada para o STDERR? Uma maneira fácil de determinar isso é redirecionar o STDOUT: 

sysadmin@localhost:~$ ls /fake > output.txt
ls: cannot access /fake: No such file or directory

No exemplo acima, o STDOUT foi redirecionado para o arquivo output.txt. Então, a saída que é exibida não pode ser STDOUT porque teria sido colocada no arquivo output.txt ao invés do terminal. Como toda saída de comando vai para STDOUT ou STDERR, a saída exibida acima deve ser STDERR.

A saída STDERR de um comando pode ser enviada para um arquivo:

sysadmin@localhost:~$ ls /fake 2> error.txt

No exemplo, o 2> indica que todas as mensagens de erro devem ser enviadas para o arquivo error.txt, o que pode ser confirmado usando o comando cat: 

sysadmin@localhost:~$ cat error.txt
ls: cannot access /fake: No such file or directory
Operador Fluxo Descrição
> ou 1> STDOUT (1) Redireciona saída normal (padrão)
2> STDERR (2) Redireciona mensagens de erro
Dica: Lembre-se: 1> é para saída normal, 2> é para erros. Se você não colocar o número, o padrão é 1> (STDOUT).

10.3.3 Redirecionando Múltiplos Fluxos

É possível direcionar tanto o STDOUT quanto o STDERR de um comando ao mesmo tempo. O seguinte comando produz tanto STDOUT quanto STDERR porque um dos diretórios especificados existe e o outro não: 

sysadmin@localhost:~$ ls /fake /etc/ppp
ls: cannot access /fake: No such file or directory
/etc/ppp:
ip-down.d  ip-up.d

Se apenas o STDOUT for enviado para um arquivo, o STDERR ainda é impresso na tela:

sysadmin@localhost:~$ ls /fake /etc/ppp > example.txt
ls: cannot access /fake: No such file or directory
sysadmin@localhost:~$ cat example.txt
/etc/ppp:
ip-down.d
ip-up.d

Se apenas o STDERR for enviado para um arquivo, o STDOUT ainda é impresso na tela:

sysadmin@localhost:~$ ls /fake /etc/ppp 2> error.txt
/etc/ppp:
ip-down.d
ip-up.d
sysadmin@localhost:~$ cat error.txt
ls: cannot access /fake: No such file or directory

Ambos STDOUT e STDERR podem ser enviados para um arquivo usando o caractere & (ampersand) antes do caractere >. O conjunto de caracteres &> significa tanto 1> quanto 2>: 

sysadmin@localhost:~$ ls /fake /etc/ppp &> all.txt
sysadmin@localhost:~$ cat all.txt
ls: cannot access /fake: No such file or directory
/etc/ppp:
ip-down.d
ip-up.d

Note que quando você usa &>, a saída aparece no arquivo com todas as mensagens de STDERR no topo e todas as mensagens de STDOUT abaixo de todas as mensagens de STDERR: 

sysadmin@localhost:~$ ls /fake /etc/ppp /junk /etc/sound &> all.txt
sysadmin@localhost:~$ cat all.txt
ls: cannot access '/fake': No such file or directory
ls: cannot access '/junk': No such file or directory
ls: cannot access '/etc/sound': No such file or directory
/etc/ppp:
ip-down.d
ip-up.d

Se você não quer que STDERR e STDOUT vão ambos para o mesmo arquivo, eles podem ser redirecionados para arquivos diferentes usando tanto > quanto 2>. Por exemplo, para direcionar STDOUT para example.txt e STDERR para error.txt, execute o seguinte: 

sysadmin@localhost:~$ ls /fake /etc/ppp > example.txt 2> error.txt
sysadmin@localhost:~$ cat error.txt
ls: cannot access /fake: No such file or directory
sysadmin@localhost:~$ cat example.txt
/etc/ppp:
ip-down.d
ip-up.d

A ordem em que os fluxos são especificados não importa.

Operador Descrição Exemplo
> arquivo ou 1> arquivo Redireciona apenas STDOUT ls /fake /etc/ppp > out.txt
2> arquivo Redireciona apenas STDERR ls /fake /etc/ppp 2> err.txt
&> arquivo Redireciona ambos STDOUT e STDERR para o mesmo arquivo ls /fake /etc/ppp &> all.txt
> out.txt 2> err.txt Redireciona STDOUT e STDERR para arquivos diferentes ls /fake /etc/ppp > out.txt 2> err.txt
Dica: Use &> quando quiser capturar toda a saída (normal + erros) em um único arquivo. Use > out.txt 2> err.txt quando quiser separar a saída normal dos erros.

10.3.4 STDIN

O conceito de redirecionar o STDIN é um conceito difícil porque é mais complicado entender por que você iria querer redirecionar o STDIN. Com STDOUT e STDERR, seus propósitos são diretos; às vezes é útil armazenar a saída em um arquivo para uso futuro.

A maioria dos usuários Linux acaba redirecionando STDOUT rotineiramente, STDERR ocasionalmente, e STDIN muito raramente.

Existem muito poucos comandos que exigem que você redirecione o STDIN porque com a maioria dos comandos, se você quiser ler dados de um arquivo para um comando, você pode especificar o nome do arquivo como um argumento para o comando.

Para alguns comandos, se você não especificar um nome de arquivo como argumento, eles voltam a usar o STDIN para obter dados. Por exemplo, considere o seguinte comando cat: 

sysadmin@localhost:~$ cat
hello
hello
how are you?
how are you?
goodbye
goodbye
Nota: Se você tentar o comando cat sem argumentos, mate o processo e retorne ao prompt usando Ctrl+C.

No exemplo anterior, o comando cat não recebeu um nome de arquivo como argumento. Então, ele solicita os dados para exibir na tela a partir do STDIN. O usuário digita hello, e então o comando cat exibe hello na tela. Embora isso seja moderadamente interessante, não é particularmente útil.

No entanto, se a saída do comando cat fosse redirecionada para um arquivo, então este método poderia ser usado para adicionar texto a um arquivo existente ou para colocar texto em um novo arquivo.

O primeiro comando no exemplo abaixo redireciona a saída do comando cat para um arquivo recém-criado chamado new.txt. Esta ação é seguida fornecendo ao comando cat o arquivo new.txt como argumento para exibir o texto redirecionado no STDOUT. 

sysadmin@localhost:~$ cat > new.txt
Hello
How are you?
Goodbye
sysadmin@localhost:~$ cat new.txt                               
Hello
How are you?
Goodbye

Embora o exemplo anterior demonstre outra vantagem de redirecionar o STDOUT, ele não aborda por que ou como o STDIN pode ser direcionado. Para entender isso, considere um novo comando chamado tr. Este comando pega um conjunto de caracteres e os traduz em outro conjunto de caracteres.

Por exemplo, para capitalizar uma linha de texto, use o comando tr da seguinte forma:

sysadmin@localhost:~$ tr 'a-z' 'A-Z'
watch how this works
WATCH HOW THIS WORKS

O comando tr pegou o STDIN do teclado e converteu todas as letras minúsculas antes de enviar o STDOUT para a tela.

Parece que um uso melhor do comando tr seria realizar a tradução em um arquivo, não na entrada do teclado. No entanto, o comando tr não suporta argumentos de nome de arquivo: 

sysadmin@localhost:~$ cat example.txt
/etc/ppp:
ip-down.d
ip-up.d
sysadmin@localhost:~$ tr 'a-z' 'A-Z' example.txt
tr: extra operand `example.txt'
Try `tr --help' for more information

É possível, no entanto, dizer ao shell para obter o STDIN de um arquivo ao invés do teclado usando o caractere <: 

sysadmin@localhost:~$ tr 'a-z' 'A-Z' < example.txt
/ETC/PPP:
IP-DOWN.D
IP-UP.D

A maioria dos comandos aceita nomes de arquivo como argumentos, então este caso de uso é relativamente raro. No entanto, para aqueles que não aceitam, este método pode ser usado para fazer o shell ler do arquivo ao invés de depender da capacidade do comando.

Uma última observação: para salvar a saída resultante, redirecione-a para outro arquivo:

sysadmin@localhost:~$ tr 'a-z' 'A-Z' < example.txt > newexample.txt
sysadmin@localhost:~$ cat newexample.txt
/ETC/PPP:
IP-DOWN.D
IP-UP.D
Operador Descrição Exemplo
< arquivo Redireciona o conteúdo de um arquivo como STDIN para o comando tr 'a-z' 'A-Z' < example.txt
comando < arquivo > novo_arquivo Redireciona STDIN de um arquivo e STDOUT para outro arquivo tr 'a-z' 'A-Z' < example.txt > out.txt
Dica: Use < para redirecionar STDIN de um arquivo. Isso é útil para comandos como tr que não aceitam nomes de arquivo como argumentos.

10.4 Ordenando Arquivos ou Entrada

O comando sort pode ser usado para reorganizar as linhas de arquivos ou entrada em ordem dicionário ou numérica. O exemplo a seguir cria um pequeno arquivo, usando o comando head para capturar as primeiras 5 linhas do arquivo /etc/passwd e enviar a saída para um arquivo chamado mypasswd. 

sysadmin@localhost:~$ head -5 /etc/passwd > mypasswd
sysadmin@localhost:~$ cat mypasswd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
sync:x:4:65534:sync:/bin:/bin/sync

Agora vamos ordenar o arquivo mypasswd:

sysadmin@localhost:~$ sort mypasswd
bin:x:2:2:bin:/bin:/usr/sbin/nologin
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
root:x:0:0:root:/root:/bin/bash
sync:x:4:65534:sync:/bin:/bin/sync
sys:x:3:3:sys:/dev:/usr/sbin/nologin

Após um exame cuidadoso da saída no exemplo anterior, o comando sort organizou as linhas do arquivo em ordem alfabética. Compare esta saída com a saída do comando cat anterior.

Dica: Por padrão, o sort ordena em ordem alfabética. Use a opção -n para ordenação numérica e -r para ordem reversa.
Opção Descrição Exemplo
-n Ordena numericamente (pelo início numérico da linha) sort -n numeros.txt
-r Ordena em ordem reversa sort -r nomes.txt
-k N Ordena pela coluna/posição N sort -k 3 -n dados.txt
-u Remove linhas duplicadas sort -u arquivo.txt

10.4.1 Campos e Opções de Ordenação

O comando sort pode reorganizar a saída com base no conteúdo de um ou mais campos. Os campos são determinados por um delimitador de campo contido em cada linha. Na computação, um delimitador é um caractere que separa uma string de texto ou dados; o padrão é espaço em branco (whitespace), como espaços ou tabs.

O seguinte comando pode ser usado para ordenar numericamente o terceiro campo do arquivo mypasswd. Três opções são usadas para alcançar esta ordenação:

Opção Função
-t: A opção -t especifica o delimitador de campo. Se o arquivo ou entrada for separado por um delimitador diferente de espaço em branco, por exemplo uma vírgula ou dois pontos, a opção -t permite que outro separador de campo seja especificado como argumento. O arquivo mypasswd usado no exemplo anterior usa o caractere dois pontos : como delimitador para separar os campos, então o exemplo a seguir usa a opção -t:.
-k3 A opção -k especifica o número do campo. Para especificar por qual campo ordenar, use a opção -k com um argumento para indicar o número do campo, começando com 1 para o primeiro campo. O exemplo a seguir usa a opção -k3 para ordenar pelo terceiro campo.
-n Esta opção especifica o tipo de ordenação. O terceiro campo no arquivo mypasswd contém números, então a opção -n é usada para realizar uma ordenação numérica. 
sysadmin@localhost:~$ sort -t: -n -k3 mypasswd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
sync:x:4:65534:sync:/bin:/bin/sync

Outra opção comumente usada no comando sort é a opção -r, que é usada para realizar uma ordenação reversa. O exemplo a seguir mostra o mesmo comando do exemplo anterior, com a adição da opção -r, fazendo com que os números mais altos no terceiro campo apareçam no topo da saída: 

sysadmin@localhost:~$ sort -t: -n -r -k3 mypasswd
sync:x:4:65534:sync:/bin:/bin/sync 
sys:x:3:3:sys:/dev:/usr/sbin/nologin  
bin:x:2:2:bin:/bin:/usr/sbin/nologin  
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
root:x:0:0:root:/root:/bin/bash

Por fim, você pode querer realizar ordenações mais complexas, como ordenar por um campo primário e depois por um campo secundário. Por exemplo, considere o seguinte arquivo de valores separados por vírgula (comma-separated value), um arquivo onde o caractere vírgula é o delimitador de campo:

Acompanhe: Use o seguinte comando para mudar para o diretório Documents: 
sysadmin@localhost:~$ cd ~/Documents

sysadmin@localhost:~/Documents$ cat os.csv
1970,Unix,Richie

Para ordenar primeiro por sistema operacional (campo #2), depois por ano (campo #1) e depois por sobrenome (campo #3), use o seguinte comando: 

sysadmin@localhost:~/Documents$ sort -t, -k2 -k1n -k3 os.csv

Opção Função
-t, Especifica o caractere vírgula como delimitador de campo

10.5 Visualizando Estatísticas de Arquivo

O comando wc fornece o número de linhas, palavras e bytes (1 byte = 1 caractere em um arquivo de texto) para um arquivo, e uma contagem total de linhas se mais de um arquivo for especificado. Por padrão, o comando wc permite que até três estatísticas sejam impressas para cada arquivo fornecido, bem como o total dessas estatísticas se mais de um nome de arquivo for fornecido: 

sysadmin@localhost:~$ wc /etc/passwd /etc/passwd-
  35   56 1710 /etc/passwd
  34   55 1665 /etc/passwd-
  69  111 3375 total

A saída do exemplo anterior tem quatro colunas:

  • Número de linhas
  • Número de palavras
  • Número de bytes
  • Nome do arquivo

Também é possível visualizar apenas estatísticas específicas, usando a opção -l para mostrar apenas o número de linhas, a opção -w para mostrar apenas o número de palavras, a opção -c para mostrar apenas o número de bytes, ou qualquer combinação dessas opções.

O comando wc pode ser útil para contar o número de linhas de saída de algum outro comando através de um pipe. Por exemplo, se você quisesse saber o número total de arquivos no diretório /etc, envie a saída de ls para o wc e conte apenas o número de linhas: 

sysadmin@localhost:~$ ls /etc/ | wc -l
142
Opção Descrição Exemplo
-l Conta apenas o número de linhas wc -l arquivo.txt
-w Conta apenas o número de palavras wc -w arquivo.txt
-c Conta apenas o número de bytes wc -c arquivo.txt
-m Conta apenas o número de caracteres wc -m arquivo.txt
Dica: Use wc -l com pipe para contar quantos itens um comando retorna. Por exemplo: ls | wc -l conta quantos arquivos estão no diretório atual.

10.6 Filtrando Seções de Arquivo

O comando cut pode extrair colunas de texto de um arquivo ou da entrada padrão. Ele é usado principalmente para trabalhar com arquivos de banco de dados delimitados. Novamente, arquivos delimitados são arquivos que contêm colunas separadas por um delimitador. Esses arquivos são muito comuns em sistemas Linux.

Por padrão, o comando cut espera que sua entrada seja separada pelo caractere tab, mas a opção -d pode especificar delimitadores alternativos, como dois pontos ou vírgula.

A opção -f pode especificar quais campos exibir, seja como um intervalo com hífen ou uma lista separada por vírgulas.

No exemplo a seguir, o primeiro, quinto, sexto e sétimo campos do arquivo de banco de dados mypasswd são exibidos: 

sysadmin@localhost:~$ cut -d: -f1,5-7 mypasswd
root:root:/root:/bin/bash
daemon:daemon:/usr/sbin:/usr/sbin/nologin
bin:bin:/bin:/usr/sbin/nologin
sys:sys:/dev:/usr/sbin/nologin
sync:sync:/bin:/bin/sync

O comando cut também é capaz de extrair colunas de texto com base na posição do caractere com a opção -c — útil ao trabalhar com arquivos de banco de dados de largura fixa ou saídas de comandos.

Por exemplo, os campos do comando ls -l estão sempre nas mesmas posições de caractere. O exemplo a seguir exibirá apenas o tipo de arquivo (caractere 1), permissões (caracteres 2-10), um espaço (caractere 11) e o nome do arquivo (caracteres 50+): 

sysadmin@localhost:~$ ls -l | cut -c1-11,50-
total 44
drwxr-xr-x Desktop
drwxr-xr-x Documents
drwxr-xr-x Downloads
drwxr-xr-x Music
drwxr-xr-x Pictures
drwxr-xr-x Public
drwxr-xr-x Templates
drwxr-xr-x Videos
-rw-rw-r-- all.txt
-rw-rw-r-- example.txt
-rw-rw-r-- mypasswd
-rw-rw-r-- new.txt
Opção Descrição Exemplo
-d Especifica o delimitador de campo cut -d: -f1 arquivo.txt
-f Especifica quais campos exibir (1-indexado) cut -d, -f2,4 dados.csv
-c Extrai por posição de caractere(s) cut -c1-10 arquivo.txt
Dica: Use cut com -d (delimitador) e -f (campos) para extrair colunas específicas de arquivos CSV ou logs separados por dois pontos.

10.7 Filtrando Conteúdo de Arquivo

O comando grep pode ser usado para filtrar linhas em um arquivo ou na saída de outro comando que corresponda a um padrão especificado. Esse padrão pode ser tão simples quanto o texto exato que você quer encontrar ou pode ser muito mais avançado através do uso de expressões regulares (regular expressions).

Por exemplo, para encontrar todos os usuários que podem fazer login no sistema com o shell BASH, o comando grep pode ser usado para filtrar as linhas do arquivo /etc/passwd que contêm o padrão bash: 

sysadmin@localhost:~$ grep bash /etc/passwd
root:x:0:0:root:/root:/bin/bash
sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

Para facilitar a visualização do que exatamente foi encontrado, use a opção --color. Esta opção destacará os itens encontrados em vermelho: 

sysadmin@localhost:~$ grep --color bash /etc/passwd
root:x:0:0:root:/root:/bin/bash
sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash
Nota: Em nossas máquinas virtuais, o comando grep tem um alias que inclui a opção --color automaticamente.

Em alguns casos, pode não ser importante encontrar as linhas específicas que correspondem ao padrão, mas sim quantas linhas correspondem ao padrão. A opção -c fornece uma contagem de quantas linhas correspondem: 

sysadmin@localhost:~$ grep -c bash /etc/passwd
2

Ao visualizar a saída do comando grep, pode ser difícil determinar os números das linhas originais. Esta informação pode ser útil ao voltar ao arquivo (talvez para editar o arquivo) para encontrar rapidamente uma das linhas encontradas.

A opção -n do comando grep exibirá os números das linhas originais. Para exibir todas as linhas e seus números de linha no arquivo /etc/passwd que contêm o padrão bash: 

sysadmin@localhost:~$ grep -n bash /etc/passwd                          
1:root:x:0:0:root:/root:/bin/bash                                       
27:sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

A opção -v inverte a correspondência, exibindo todas as linhas que não contêm o padrão. Para exibir todas as linhas que não contêm nologin no arquivo /etc/passwd: 

sysadmin@localhost:~$ grep -v nologin /etc/passwd
root:x:0:0:root:/root:/bin/bash
sync:x:4:65534:sync:/bin:/bin/sync
operator:x:1000:37::/root:/bin/sh
sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

A opção -i ignora as diferenças de maiúsculas e minúsculas (case insensitive). O seguinte comando busca pelo padrão the no arquivo newhome.txt, permitindo que cada caractere seja maiúsculo ou minúsculo: 

sysadmin@localhost:~$ cd Documents
sysadmin@localhost:~/Documents$ grep -i the newhome.txt
There are three bathrooms.
**Beware** of the ghost in the bedroom.
The kitchen is open for entertaining.
**Caution** the spirits don't like guests.

A opção -w retorna apenas linhas que contêm correspondências que formam palavras completas. Para ser uma palavra, a string de caracteres deve ser precedida e seguida por um caractere não-palavra. Caracteres de palavra incluem letras, dígitos e o caractere sublinhado (_).

Os exemplos a seguir buscam pelo padrão are no arquivo newhome.txt. O primeiro comando busca sem opções, enquanto o segundo comando inclui a opção -w. Compare as saídas: 

sysadmin@localhost:~/Documents$ grep are newhome.txt
There are three bathrooms.
**Beware** of the ghost in the bedroom.
sysadmin@localhost:~/Documents$ grep -w are newhome.txt
There are three bathrooms.
Opção Descrição Exemplo
--color Destaca os itens encontrados (em vermelho) grep --color bash /etc/passwd
-c Conta quantas linhas correspondem ao padrão grep -c bash /etc/passwd
-n Exibe o número da linha original grep -n bash /etc/passwd
-v домаћинствима linhas que NÃO contêm o padrão grep -v nologin /etc/passwd
-i Ignora maiúsculas/minúsculas (case insensitive) grep -i the arquivo.txt
-w Busca por palavras completas grep -w are arquivo.txt
Dica: O grep é um dos comandos mais poderosos do Linux. Combine-o com pipes para filtrar resultados: ls -la | grep "\.txt$" para encontrar apenas arquivos .txt.

10.8 Expressões Regulares Básicas

Expressões regulares, também chamadas de regex, são uma coleção de caracteres normais e especiais que são usados para encontrar padrões simples ou complexos, respectivamente, em arquivos. Esses caracteres são usados para realizar uma função de correspondência específica em uma busca.

Caracteres normais são caracteres alfanuméricos que correspondem a eles mesmos. Por exemplo, um a corresponderia a um a. Caracteres especiais têm significados especiais quando usados dentro de padrões por comandos como o comando grep. Eles se comportam de maneira mais complexa e não correspondem a eles mesmos.

Existem tanto Expressões Regulares Básicas (disponíveis para uma grande variedade de comandos Linux) quanto Expressões Regulares Estendidas (disponíveis para comandos Linux mais avançados). As Expressões Regulares Básicas incluem o seguinte:

Caractere Corresponde a
. (ponto) Qualquer caractere único
[ ] Uma lista ou intervalo de caracteres para corresponder a um caractere. Se o primeiro caractere dentro dos colchetes for o circunflexo ^, significa qualquer caractere que não esteja na lista
* O caractere anterior repetido zero ou mais vezes
^ Se for o primeiro caractere no padrão, o padrão deve estar no início da linha para corresponder; caso contrário, é apenas um caractere literal ^
$ Se for o último caractere no padrão, o padrão deve estar no final da linha para corresponder; caso contrário, é apenas um caractere literal $

O comando grep é apenas um dos muitos comandos que suportam expressões regulares. Alguns outros comandos incluem os comandos more e less.

Embora algumas expressões regulares sejam desnecessariamente colocadas entre aspas simples, é uma boa prática usar aspas simples ao redor de expressões regulares para evitar que o shell tente interpretar significados especiais delas.

Importante: Sempre use aspas simples (' ') em torno das expressões regulares para evitar que o shell interprete caracteres especiais como $ ou *.
Exemplos práticos:
  • grep '^root' /etc/passwd - encontra linhas que começam com "root"
  • grep 'bash$' /etc/passwd - encontra linhas que terminam com "bash"
  • grep 'r..t' /etc/passwd - encontra "root", "rout", "rapt", etc.
  • grep '[0-9]' arquivo.txt - encontra linhas com qualquer dígito
  • grep '[^0-9]' arquivo.txt - encontra linhas com caracteres não numéricos

10.8.1 O Caractere Ponto (.)

Uma das expressões mais úteis é o caractere ponto (.). Ele corresponde a qualquer caractere, exceto o caractere de nova linha. Considere o conteúdo não filtrado do arquivo ~/Documents/red.txt: 

sysadmin@localhost:~/Documents$ cat red.txt
red
reef
rot
reeed
rd
rod
roof
reed
root
reel
read

O padrão r..f encontraria qualquer linha que contivesse a letra r seguida por exatamente dois caracteres e depois a letra f: 

sysadmin@localhost:~/Documents$ grep 'r..f' red.txt
reef
roof

A linha não precisa ser uma correspondência exata, ela simplesmente deve conter o padrão, como visto aqui quando r..t é procurado no arquivo /etc/passwd: 

sysadmin@localhost:~/Documents$ grep 'r..t' /etc/passwd
root:x:0:0:root:/root:/bin/bash
operator:x:1000:37::/root:

O caractere ponto pode ser usado qualquer número de vezes. Para encontrar todas as palavras que têm pelo menos quatro caracteres, o seguinte padrão pode ser usado: 

sysadmin@localhost:~/Documents$ grep '....' red.txt
reef
reeed
roof
reed
root
reel
read
Dica: Cada . representa exatamente UM caractere (qualquer um, exceto nova linha). r..f significa: "r" + qualquer caractere + qualquer caractere + "f".
Padrão Significado Exemplos de correspondência
r..f "r" + 2 caracteres + "f" reef, roof, raaf
r.t "r" + 1 caractere + "t" rot, rat, rzt
.... 4 ou mais caracteres (qualquer sequência de 4 caracteres) reef, reed, root

10.8.2 Os Caracteres de Colchetes [ ]

Ao usar o caractere . (ponto), qualquer caractere possível pode corresponder a ele. Em alguns casos, você quer especificar exatamente quais caracteres deseja encontrar, como um caractere alfabético minúsculo ou um caractere numérico.

Os colchetes [ ] correspondem a um único caractere da lista ou intervalo de caracteres possíveis contidos dentro dos colchetes. Por exemplo, dado o arquivo profile.txt: 

sysadmin@localhost:~/Documents$ cat profile.txt
Hello my name is Joe.
I am 37 years old.
3121991
My favorite food is avocados.
I have 2 dogs.
123456789101112

Para encontrar todas as linhas no arquivo profile.txt que contêm um número, use o padrão [0123456789] ou [0-9]: 

sysadmin@localhost:~/Documents$ grep '[0-9]' profile.txt
I am 37 years old.
3121991
I have 2 dogs.
123456789101112

Note que cada caractere possível pode ser listado [abcd] ou fornecido como um intervalo [a-d], desde que o intervalo esteja na ordem correta. Por exemplo, [d-a] não funcionaria porque não é um intervalo válido: 

sysadmin@localhost:~/Documents$ grep '[d-a]' profile.txt
grep: Invalid range end

O intervalo é especificado por um padrão chamado tabela ASCII. Esta tabela é uma coleção de todos os caracteres imprimíveis em uma ordem específica. Você pode ver a tabela ASCII com o comando ascii. Uma pequena amostra: 

      041  33  21  !                                 141   97  61  a 
      042  34  22  "                                 142   98  62  b
      043  35  23  #                                 143   99  63  c
      044  36  24  $                                 144   100 64  d
      045  37  25  %                                 145   101 65  e
      046  38  26  &                                 146   102 66  f

O valor ASCII da letra a é 97 enquanto o valor de d é 100. Como 97 é menor que 100, o intervalo a-d (97-100) é um intervalo válido.

E quanto a excluir caracteres? Por exemplo, para corresponder a um caractere que pode ser qualquer coisa, exceto x, y ou z? Seria ineficiente fornecer um conjunto com todos os caracteres, exceto x, y ou z.

Para corresponder a um caractere que não é um dos caracteres listados, comece o conjunto com um símbolo ^ (circunflexo). Para encontrar todas as linhas que contêm qualquer caractere não numérico, insira um ^ como o primeiro caractere dentro dos colchetes. Este caractere nega os caracteres listados: 

sysadmin@localhost:~/Documents$ grep '[^0-9]' profile.txt
Hello my name is Joe.
I am 37 years old.
My favorite food is avocados.
I have 2 dogs.
Considere Isto:

Não confunda [^0-9] como correspondendo a linhas que não contêm números. Na verdade, ele corresponde a linhas que contêm não-números. Observe o arquivo original para ver a diferença. A terceira e sexta linhas contêm apenas números; elas não contêm não-números, então essas linhas não correspondem.

Dica:
  • [a-z] - qualquer letra minúscula
  • [A-Z] - qualquer letra maiúscula
  • [0-9] - qualquer dígito
  • [a-zA-Z] - qualquer letra (maiúscula ou minúscula)
  • [^aeiou] - qualquer caractere que NÃO seja vogal
  • [^0-9] - qualquer caractere que NÃO seja dígito
Padrão Significado
[0123456789] ou [0-9] Qualquer dígito (0-9)
[a-z] Qualquer letra minúscula
[A-Z] Qualquer letra maiúscula
[^0-9] Qualquer caractere que NÃO seja dígito
[^aeiou] Qualquer caractere que NÃO seja vogal minúscula

10.8.3 O Caractere Asterisco *

Considere o arquivo ~/Documents/red.txt com o seguinte conteúdo:

sysadmin@localhost:~/Documents$ cat red.txt
red
reef
rot
reeed
rd
rod
roof
reed
root
reel
read

O caractere * (asterisco) corresponde a zero ou mais ocorrências do caractere anterior. Por exemplo, o padrão re*d corresponde a: um "r" seguido por zero ou mais "e" seguido por um "d": 

sysadmin@localhost:~/Documents$ grep 're*d' red.txt
red
reeed
rd
reed

Também é possível corresponder a zero ou mais ocorrências de uma lista de caracteres utilizando os colchetes. O padrão [oe]* usado no exemplo a seguir corresponde a zero ou mais ocorrências do caractere o ou do caractere e: 

sysadmin@localhost:~/Documents$ grep 'r[oe]*d' red.txt
red
reeed
rd
rod
reed

Quando usado com apenas um outro caractere, o * não é muito útil. Qualquer um dos seguintes padrões corresponderia a todas as strings ou linhas do arquivo: '.*' 'e*' 'b*' 'z*' porque o caractere asterisco * pode corresponder a zero ocorrências de um padrão. 

sysadmin@localhost:~/Documents$ grep 'z*' red.txt
red
reef
rot
reeed
rd
rod
roof
reed
root
reel
read
sysadmin@localhost:~/Documents$ grep 'e*' red.txt
red
reef
rot
reeed
rd
rod
roof
reed
root
reel
read

Para tornar o caractere asterisco * útil, é necessário criar um padrão que inclua mais do que apenas o caractere que o precede. Por exemplo, os resultados acima podem ser refinados adicionando outro e para fazer o padrão ee*, que efetivamente corresponde a cada linha que contém pelo menos um e: 

sysadmin@localhost:~/Documents$ grep 'ee*' red.txt
red
reef
reeed
reed
reel
read
Dica: O padrão .* (ponto asterisco) é um dos mais úteis — ele corresponde a qualquer caractere (exceto nova linha) repetido zero ou mais vezes, ou seja, praticamente qualquer coisa.
Importante: O asterisco * em expressões regulares NÃO é o mesmo que o coringa * do shell. No regex, ele repete o caractere anterior; no shell, ele substitui qualquer sequência de caracteres.
Padrão Significado Exemplos de correspondência
re*d "r" + zero ou mais "e" + "d" red, reed, reeed, rd
r[oe]*d "r" + zero ou mais "o" ou "e" + "d" red, rod, reed, rd
.* Qualquer caractere (zero ou mais vezes) Todas as linhas
ee* Pelo menos um "e" red, reef, reed

10.8.4 Caracteres de Âncora

Ao realizar uma correspondência de padrão, a correspondência pode ocorrer em qualquer lugar da linha. Caracteres de âncora são uma das maneiras que as expressões regulares podem ser usadas para restringir os resultados da busca. Eles especificam se a correspondência ocorre no início da linha ou no final da linha.

Por exemplo, o padrão root aparece muitas vezes no arquivo /etc/passwd:

sysadmin@localhost:~/Documents$ grep 'root' /etc/passwd
root:x:0:0:root:/root:/bin/bash
operator:x:1000:37::/root:

O caractere circunflexo (^) é usado para garantir que um padrão apareça no início da linha. Por exemplo, para encontrar todas as linhas em /etc/passwd que começam com root, use o padrão ^root. Note que ^ deve ser o primeiro caractere no padrão para ser eficaz: 

sysadmin@localhost:~/Documents$ grep '^root' /etc/passwd
root:x:0:0:root:/root:/bin/bash

O segundo caractere de âncora $ (cifrão) pode ser usado para garantir que um padrão apareça no final da linha, reduzindo assim os resultados da busca. Para encontrar as linhas que terminam com a letra r no arquivo alpha-first.txt, use o padrão r$: 

sysadmin@localhost:~/Documents$ cat alpha-first.txt
A is for Animal
B is for Bear
C is for Cat
D is for Dog
E is for Elephant
F is for Flower
sysadmin@localhost:~/Documents$ grep 'r$' alpha-first.txt
B is for Bear
F is for Flower

Novamente, a posição deste caractere é importante. O $ deve ser o último caractere no padrão para ser eficaz como âncora.

Dica: Combine âncoras para corresponder a linhas exatas:
  • ^início - linha começa com "início"
  • fim$ - linha termina com "fim"
  • ^linha exata$ - linha contém EXATAMENTE "linha exata" (nada mais, nada menos)
Exemplos práticos: 
# Linhas que começam com comentário
grep '^#' arquivo.conf

# Linhas vazias
grep '^$' arquivo.txt

# Linhas que terminam com .txt
grep '\.txt$' lista.txt

# Linhas que não estão vazias
grep -v '^$' arquivo.txt
Padrão Significado
^palavra Linhas que começam com "palavra"
palavra$ Linhas que terminam com "palavra"
^palavra$ Linhas que contêm EXATAMENTE "palavra"
^$ Linhas vazias

10.8.5 O Caractere Barra Invertida \

Em alguns casos, você pode querer encontrar um caractere que é, por acaso, um caractere especial de expressão regular. Por exemplo, considere o seguinte arquivo newhome.txt: 

sysadmin@localhost:~/Documents$ cat newhome.txt
Thanks for purchasing your new home!!

**Warning** it may be haunted.

There are three bathrooms.

**Beware** of the ghost in the bedroom.

The kitchen is open for entertaining.

**Caution** the spirits don't like guests.

Good luck!!!

No exemplo a seguir, a busca por re* corresponde a cada linha que contém um r seguido por zero ou mais da letra e: 

sysadmin@localhost:~/Documents$ grep 're*' newhome.txt
Thanks for purchasing your new home!!
**Warning** it may be haunted.
There are three bathrooms.
**Beware** of the ghost in the bedroom.
The kitchen is open for entertaining.
**Caution** the spirits don't like guests.

Para procurar um caractere asterisco * literal (e não o significado especial de "zero ou mais ocorrências"), coloque um caractere barra invertida \ antes do caractere asterisco *: 

sysadmin@localhost:~/Documents$ grep 're\*' newhome.txt
**Beware** of the ghost in the bedroom.

Isso porque re\* significa: a letra r seguida pela letra e seguida por um asterisco literal *.

Caracteres especiais que precisam ser escapados com \ quando buscados literalmente:
  • . (ponto) - corresponde a qualquer caractere
  • * (asterisco) - zero ou mais ocorrências
  • [ ] (colchetes) - lista/intervalo de caracteres
  • ^ (circunflexo) - início da linha
  • $ (cifrão) - fim da linha
  • \ (barra invertida) - o próprio caractere de escape
Dica: Para buscar um caractere literal que tem significado especial em regex, coloque \ antes dele: 
# Buscar por um ponto literal (não qualquer caractere)
grep '\.' arquivo.txt

# Buscar por um cifrão literal (não final da linha)
grep '\$' arquivo.txt

# Buscar por um colchete literal
grep '\[' arquivo.txt
Padrão Significado
re* "r" + zero ou mais "e" (expressão regular)
re\* "r" + "e" + asterisco literal * (caractere escapado)
\. Ponto literal . (não "qualquer caractere")
\$ Cifrão literal $ (não "fim da linha")
\\ Barra invertida literal \ (o próprio caractere de escape)

10.8.6 Expressões Regulares Estendidas

O uso de expressões regulares estendidas frequentemente requer que uma opção especial seja fornecida ao comando para reconhecê-las. Historicamente, existia um comando chamado egrep, que é semelhante ao grep, mas pode entender expressões regulares estendidas. Agora, o comando egrep está obsoleto em favor do uso do grep com a opção -E.

As seguintes expressões regulares são consideradas estendidas:

Caractere Significado
? (interrogação) Corresponde ao caractere anterior zero ou uma vez, ou seja, é um caractere opcional
+ (mais) Corresponde ao caractere anterior repetido uma ou mais vezes
| (pipe/barra vertical) Alternação ou como um operador lógico "ou" (OR)

Para corresponder a colo seguido por zero ou um caractere u seguido por um caractere r: 

sysadmin@localhost:~/Documents$ grep -E 'colou?r' spelling.txt
American English: Do you consider gray to be a color or a shade?
British English: Do you consider grey to be a colour or a shade?

Para corresponder a uma ou mais letras e:

sysadmin@localhost:~/Documents$ grep -E 'e+' red.txt
red
reef
reeed
reed
reel
read

Para corresponder a gray ou grey:

sysadmin@localhost:~/Documents$ grep -E 'gray|grey' spelling.txt
American English: Do you consider gray to be a color or a shade?
British English: Do you consider grey to be a colour or a shade?
Dica: Use grep -E (ou egrep) para usar expressões regulares estendidas. Os caracteres ?, +, |, ( ) e { } têm significado especial apenas no modo estendido.
Exemplos práticos com Expressões Regulares Estendidas: 
# Opcional: corresponde a "color" ou "colour"
grep -E 'colou?r' arquivo.txt

# Uma ou mais: corresponde a "abc", "abbc", "abbbc", etc.
grep -E 'ab+c' arquivo.txt

# Alternação: corresponde a "gato" ou "cachorro"
grep -E 'gato|cachorro' arquivo.txt

# Agrupamento: corresponde a "abc" ou "adc"
grep -E 'a(b|d)c' arquivo.txt

# Quantificador: corresponde a exatamente 3 letras 'a'
grep -E 'a{3}' arquivo.txt

# Quantificador: corresponde a 2 a 5 letras 'a'
grep -E 'a{2,5}' arquivo.txt
Padrão (Extended) Significado
colou?r "color" ou "colour" (u é opcional)
e+ Uma ou mais letras "e" (pelo menos uma)
gray|grey "gray" ou "grey"
a(b|c)d "abd" ou "acd"
