Módulo 15

Contas de Usuários e Grupos

Compreendendo a estrutura de segurança, permissões de arquivos e gerenciamento de identidades no Linux.

15.1 Introdução

As contas de usuário são projetadas para fornecer segurança em um sistema operacional Linux. Cada pessoa no sistema deve fazer login usando uma conta de usuário que permite ou nega o acesso a arquivos e diretórios específicos.

Isso é feito por meio de permissões de arquivos, que são restrições e concessões associadas a arquivos e diretórios dadas pelo sistema para usuários, grupos e todos os outros que se autenticam. Essas permissões podem ser editadas e modificadas pelo usuário root.

As contas de usuário também pertencem a grupos, que também podem ser utilizados para fornecer acesso a arquivos e diretórios. Cada usuário pertence a pelo menos um grupo (frequentemente a vários) para permitir que compartilhem dados armazenados em arquivos com outros usuários de forma mais fácil.

Nota de Segurança: Os dados de contas de usuários e grupos são armazenados em arquivos de banco de dados do sistema. Conhecer o conteúdo desses arquivos permite entender melhor quais usuários possuem acesso a arquivos e diretórios, além de conter informações vitais de segurança que afetam a capacidade de login e autenticação.

Diversos comandos fornecem a habilidade de visualizar informações de contas de usuários e grupos, bem como alternar de uma conta de usuário para outra (desde que você tenha a autoridade apropriada para fazê-lo). Esses comandos são valiosos para investigar o uso do sistema, diagnosticar problemas (troubleshooting) e monitorar acessos não autorizados.

15.2 Contas Administrativas

Existem muitas maneiras diferentes de executar um comando que exige privilégios administrativos ou de root. Fazer login no sistema como usuário root permite que você execute comandos como administrador. No entanto, esse tipo de acesso é potencialmente perigoso, pois você pode esquecer que está conectado como root e rodar um comando que cause sérios problemas ao sistema. Como resultado, não é recomendado fazer login diretamente como usuário root.

Aviso de Risco: Como a utilização da conta root é arriscada, você deve apenas executar comandos com esses privilégios quando eles forem estritamente necessários.

Se a conta root estiver desativada (como ocorre nativamente na distribuição Ubuntu), os comandos administrativos podem ser executados utilizando o comando sudo. Caso a conta root esteja ativada, um usuário comum pode executar o comando su para alternar de conta para o usuário root.

Quando você faz login no sistema diretamente como root para executar tarefas, absolutamente tudo na sua sessão é executado sob esse usuário. Se estiver utilizando um ambiente gráfico, isso se torna ainda mais perigoso, pois o processo de login gráfico é composto por muitos executáveis diferentes. Cada programa que roda como root representa uma ameaça muito maior do que um processo executado por um usuário padrão, já que esses programas têm permissão para fazer quase qualquer coisa, enquanto os programas de usuários comuns são altamente restritos.

Perigo Potencial: Outro grande risco de logar como root é esquecer de encerrar a sessão (logout) para realizar tarefas cotidianas e não administrativas. Isso permite que softwares como navegadores web e clientes de e-mail rodem com privilégios de root, totalmente sem restrições. O fato de várias distribuições Linux importantes, como o Ubuntu, bloquearem o login direto como root é o maior indicativo de que esta não é a forma ideal de realizar tarefas administrativas.

15.2.1 Alternando Usuários

O comando su (substitute user) permite que você execute um shell como um usuário diferente. Embora a alternância para o usuário root seja o uso mais frequente do comando su, ele também pode ser utilizado para alternar para qualquer outro usuário do sistema. 

su [opções] [nome_de_usuário]

Ao alternar de usuário, é altamente recomendável utilizar a opção de login shell. Essa opção configura completamente o novo ambiente do shell com as definições, variáveis de ambiente e caminhos do novo usuário, garantindo que quaisquer comandos executados funcionem corretamente.

Se essa opção for omitida, o novo shell altera apenas o UID (User ID), mas não realiza o login completo do usuário. A opção de login shell pode ser especificada de três formas equivalentes: 

su -
su -l
su --login

Por padrão, se um nome de usuário não for especificado, o comando su abrirá um novo shell como o usuário root. Os dois comandos abaixo são maneiras equivalentes de iniciar um shell como administrador: 

su - root
su -
Autenticação: Após pressionar Enter para executar qualquer um desses comandos, o usuário deve fornecer a senha do usuário root para iniciar o novo shell. Se você não souber a senha da conta para a qual está migrando, o comando su falhará.

Observe no exemplo de terminal abaixo como o prompt de comando se altera para refletir o usuário atual (mudando o caractere final de $ para #, o que indica privilégios de superusuário): 

sysadmin@localhost:~$ su -
Password: netlab123
root@localhost:~# id
uid=0(root) gid=0(root) groups=0(root)

Depois de usar o shell iniciado pelo comando su para realizar as tarefas administrativas necessárias, você deve retornar ao seu shell original (e à sua conta de usuário comum) utilizando o comando exit. 

root@localhost:~# exit
logout
sysadmin@localhost:~$ id
uid=1001(sysadmin) gid=1001(sysadmin) groups=1001(sysadmin),4(adm),27(sudo)

15.2.2 Executando Comandos Privilegiados

O comando sudo (superuser do) permite que os usuários executem comandos como outro usuário. De forma semelhante ao comando su, assume-se por padrão o usuário root caso nenhum outro seja especificado. 

sudo [opções] comando

Em distribuições que não permitem o login direto do usuário root (ou através do comando su), o processo de instalação configura automaticamente uma conta de usuário inicial para que ela possa utilizar o comando sudo para executar tarefas como se o próprio usuário root as estivesse executando.

Por exemplo, privilégios administrativos são estritamente necessários para ler o arquivo /etc/shadow:

sysadmin@localhost:~$ head /etc/shadow
head: cannot open '/etc/shadow' for reading: Permission denied
Autenticação com Sudo: Ao utilizar o sudo para executar um comando como root, o sistema solicita a senha do próprio usuário atual, e não a senha do root. Esse recurso de segurança evita acessos administrativos não autorizados caso o usuário deixe o computador temporariamente sozinho. Além disso, a senha não será solicitada novamente enquanto o usuário continuar executando novos comandos com sudo em um intervalo menor que cinco minutos.

O exemplo a seguir demonstra a execução correta do comando anterior precedido pelo sudo. Note que a senha solicitada é a do usuário comum sysadmin: 

sysadmin@localhost:~$ sudo head /etc/shadow
[sudo] password for sysadmin: netlab123

daemon:*:16463:0:99999:7:::
bin:*:16463:0:99999:7:::
sys:*:16463:0:99999:7:::
sync:*:16463:0:99999:7:::
games:*:16463:0:99999:7:::
man:*:16463:0:99999:7:::
lp:*:16463:0:99999:7:::
mail:*:16463:0:99999:7:::
news:*:16463:0:99999:7:::

O uso do comando sudo para executar comandos administrativos gera obrigatoriamente uma entrada em um arquivo de log do sistema. Cada registro inclui o nome do usuário que executou a ação, o comando exato que foi rodado, além da data e hora da execução.

Isso garante um alto nível de rastreabilidade (accountability), o oposto de sistemas onde múltiplos usuários compartilham a mesma senha de root e usam su de forma anônima.

Uma grande vantagem prática de utilizar o sudo é a redução drástica de erros acidentais como root. A intenção de executar uma tarefa crítica fica explícita: ela só rodará com privilégios de superusuário se for explicitamente prefixada com o comando sudo. Caso contrário, será interpretada com os limites seguros de um usuário comum.

15.3 Contas de Usuários

Existem vários arquivos de texto no diretório /etc que contêm os dados de contas dos usuários e grupos definidos no sistema. Por exemplo, para verificar se uma conta de usuário específica foi criada no sistema, o local correto para checar é o arquivo /etc/passwd.

O arquivo /etc/passwd define algumas das informações essenciais das contas de usuário. O exemplo a seguir mostra as últimas cinco linhas de um arquivo /etc/passwd típico: 

sysadmin@localhost:~$ tail -5 /etc/passwd
syslog:x:101:103::/home/syslog:/bin/false
bind:x:102:105::/var/cache/bind:/bin/false
sshd:x:103:65534::/var/run/sshd:/usr/sbin/nologin
operator:x:1000:37::/root:/bin/sh
sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

Cada linha contém informações pertencentes a um único usuário. Os dados são separados em campos pelo caractere de dois-pontos (:). A seguir, descrevemos detalhadamente cada um dos campos, da esquerda para a direita, utilizando a última linha da saída do terminal anterior como exemplo:

Nome de Usuário (Username) 

sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

O primeiro campo contém o nome do usuário ou o username. Este nome é utilizado ao fazer login no sistema e quando a propriedade dos arquivos é visualizada com o comando ls -l. Ele existe para facilitar a referência humana à conta, enquanto o sistema operacional gerencia tudo internamente por IDs.

Marcador de Senha (Password Placeholder) 

sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

Antigamente, a senha criptografada do usuário era armazenada diretamente neste local. Atualmente, o caractere x neste campo indica ao sistema que a senha real e protegida está armazenada no arquivo /etc/shadow.

ID do Usuário (UID) 

sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

Cada conta recebe um ID de Usuário (UID - User ID). Os nomes de usuário não são usados diretamente pelo sistema para controle interno, que define a conta pelo UID. Por exemplo, a propriedade e os donos de arquivos são associados a UIDs, e não a nomes de texto.

ID do Grupo Principal (GID) 

sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

Este campo indica o ID do Grupo Principal (GID - Group ID) ao qual o usuário pertence. Isso significa que o usuário herdará automaticamente as permissões especiais concedidas a este grupo em qualquer arquivo ou diretório do sistema.

Comentário (GECOS / Comment) 

sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

Este campo pode conter qualquer informação adicional sobre o usuário, incluindo seu nome completo real, número de telefone ou outras notas administrativas úteis.

Diretório Home (Home Directory) 

sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

Define a localização física do diretório de início (home) do usuário. Para usuários comuns, este caminho geralmente segue o padrão /home/nome_do_usuario (ex: /home/bob). O usuário administrador root possui um local diferente e exclusivo para seu diretório home: o diretório /root.

Shell de Login (Shell) 

sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

Este campo indica o caminho do interpretador de comandos (shell) de login do usuário. Por padrão, o usuário é direcionado para este shell sempre que se autentica em um ambiente de linha de comando ou abre uma janela de terminal. O shell Bash (/bin/bash) é o mais comum para usuários Linux.

Dica de Administração: Uma maneira muito eficiente de verificar se um usuário específico já foi definido no sistema é buscar o registro dele diretamente no arquivo /etc/passwd utilizando o comando grep. Veja o exemplo: 
sysadmin@localhost:~$ grep sysadmin /etc/passwd
sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

15.3.1 Senhas (Passwords)

Como mencionado anteriormente, o arquivo /etc/shadow contém as informações de conta relacionadas às senhas dos usuários. Por motivos de segurança, os usuários comuns não têm permissão para ler o conteúdo do arquivo /etc/shadow. Para visualizar este arquivo, é necessário autenticar-se como administrador (conta root): 

sysadmin@localhost:~$ su -
Password: netlab123
root@localhost:~#

Um arquivo /etc/shadow típico exibe uma estrutura semelhante ao exemplo abaixo:

root@localhost:~# tail -5 /etc/shadow
syslog:*:16874:0:99999:7:::
bind:*:16874:0:99999:7:::
sshd:*:16874:0:99999:7:::
operator:!:16874:0:99999:7:::
sysadmin:$6$c75ekQWF$.GpiZpFnIXLzkALjDpZXmjxZcIll14OvL2mFSIfnc1aU2cQ/221QL5AX5RjKXpXPJRQ0uVN35TY3/..c7v0.n0:16874:5:30:7:60:15050:

Assim como no arquivo anterior, cada linha é dividida em campos separados pelo caractere de dois-pontos (:). Abaixo, detalhamos cada campo, da esquerda para a direita, baseando-se no registro do usuário sysadmin:

Nome de Usuário (Username) 

sysadmin:$6$c75ekQWF$...:16874:5:30:7:60:15050::

O primeiro campo armazena o nome da conta de usuário. Ele corresponde exatamente ao nome de usuário registrado no arquivo /etc/passwd.

Senha Criptografada (Password) 

sysadmin:$6$c75ekQWF$.GpiZpFnIXLzkALjDpZXmjxZcIll14OvL2mFSIfnc1aU2cQ/221QL5AX5RjKXpXPJRQ0uVN35TY3/..c7v0.n0:16874:5:30:7:60:15050::

Contém o hash da senha criptografada. Esta longa string é gerada por uma criptografia unidirecional (one-way encryption), o que significa que ela não pode ser revertida para descobrir a senha original. Enquanto usuários comuns possuem este hash complexo, contas de sistema geralmente exibem um caractere de asterisco (*) ou ponto de exclamação (!) nesta área, impedindo logins diretos.

Última Alteração (Last Change) 

sysadmin:$6$c75ekQWF$...:16874:5:30:7:60:15050::

Este campo armazena uma data numérica que representa a última vez que a senha foi modificada. O número é baseado no total de dias decorridos desde 1º de janeiro de 1970 (conhecido como a Epoch do Unix). O valor é atualizado de forma automática e serve como base para os recursos de expiração de senhas.

Dias Mínimos (Minimum) 

sysadmin:$6$c75ekQWF$...:16874:5:30:7:60:15050::

Indica a quantidade mínima de dias que o usuário deve esperar entre as alterações de senha. Um valor diferente de zero (como 5 neste exemplo) impede que um usuário mude sua senha e a altere imediatamente de volta para a senha antiga. Caso o valor seja zero (0), o usuário pode alterar sua senha a qualquer momento.

Dias Máximos (Maximum) 

sysadmin:$6$c75ekQWF$...:16874:5:30:7:60:15050:

Estipula a quantidade máxima de dias que a senha permanece válida, forçando o usuário a renová-la periodicamente. O valor 30 indica que a senha deve ser trocada a cada 30 dias para evitar o bloqueio da conta. Se o valor estiver definido como 99999, a senha é considerada perpétua (equivalente a aproximadamente 274 anos).

Aviso (Warn) 

sysadmin:$6$c75ekQWF$...:16874:5:30:7:60:15050::

Define quantos dias antes da expiração da senha o sistema começará a exibir avisos durante o processo de login por linha de comando. No exemplo, o usuário receberá alertas de expiração durante os 7 dias anteriores ao vencimento do prazo máximo.

Inatividade (Inactive) 

sysadmin:$6$c75ekQWF$...:16874:5:30:7:60:15050::

Caso o usuário ignore os avisos e a senha expire, a conta entra em um período de carência. O campo de inatividade estipula o número de dias em que o usuário ainda consegue alterar sua própria senha durante o login gráfico ou de terminal. Se o prazo terminar (como os 60 dias estipulados aqui), a conta será totalmente desativada e apenas um administrador poderá redefini-la.

Expiração da Conta (Expire) 

sysadmin:$6$c75ekQWF$...:16874:5:30:7:60:15050::

Indica a data absoluta em que a conta será permanentemente bloqueada, também representada pelo número de dias desde a Epoch (1º de janeiro de 1970). Diferente de uma exclusão, uma conta expirada é apenas congelada, permitindo que administradores a desbloqueiem redefinindo seus parâmetros. É um recurso muito comum para gerenciar contas de funcionários temporários ou prestadores de serviço.

Reservado (Reserved) 

sysadmin:$6$c75ekQWF$...:16874:5:30:7:60:15050::

Este último campo não possui função atribuída atualmente; ele permanece em branco e está reservado para uso futuro do sistema operacional.

Considere Isto: Comando getent Além do comando grep, outra excelente técnica para extrair informações de contas contidas nos arquivos /etc/passwd e /etc/shadow é usar o comando getent. A grande vantagem do getent é a sua capacidade de buscar dados definidos localmente (nos arquivos de texto tradicionais) ou vindos diretamente de um servidor de diretório na rede (como LDAP ou Active Directory).

A sintaxe geral do comando getent é:

getent banco_de_dados registro

Por exemplo, o comando a seguir recupera as informações cadastrais do usuário sysadmin consultando a base de dados de senhas do sistema: 

sysadmin@localhost:~$ getent passwd sysadmin
sysadmin:x:1001:1001:System Administrator,,,,:/home/sysadmin:/bin/bash

15.4 Contas de Sistema (System Accounts)

Os usuários comuns realizam login no sistema utilizando contas de usuário regulares. Tipicamente, essas contas possuem valores de UID (User ID) superiores a 500 (ou superiores a 1.000 em várias distribuições modernas). Já o usuário administrador root possui acesso total e irrestrito ao sistema operacional, privilégio este concedido especificamente à conta que possui o UID igual a 0.

Além dessas, existem contas adicionais que não foram projetadas para que pessoas reais façam login. Essas contas, que geralmente ocupam a faixa de UID 1 a 499 (ou até 999 dependendo da distribuição), são chamadas de contas de sistema. Elas existem para fornecer contextos de execução e segurança isolados para os diversos serviços e daemons que rodam no background do Linux.

As contas de sistema possuem alguns campos nos arquivos /etc/passwd e /etc/shadow que diferem bastante das contas comuns. Por exemplo, elas raramente possuem diretórios home válidos, já que serviços não costumam criar ou armazenar arquivos pessoais.

No arquivo /etc/passwd, as contas de sistema exibem um programa de bloqueio (não-login) no campo destinado ao shell: 

sshd:x:103:65534::/var/run/sshd:/usr/sbin/nologin

No arquivo /etc/shadow, as contas de sistema tipicamente trazem um caractere de asterisco (*) ou exclamação (!) no lugar destinado ao hash da senha, inviabilizando qualquer tentativa de autenticação direta: 

sshd:*:16874:0:99999:7:::
Aviso Crítico de Administração: A grande maioria das contas de sistema é estritamente necessária para o funcionamento correto do sistema operacional. Você nunca deve excluir uma conta de sistema a menos que tenha certeza absoluta de que a remoção dela não causará falhas nos serviços dependentes ou instabilidade no kernel.

Dedique um tempo para aprender a função de cada conta de sistema ativa (como bin, daemon, sshd, bind, mail). Os administradores de sistemas têm a tarefa crucial de garantir a segurança global do ambiente, e isso inclui auditar e proteger adequadamente os privilégios e acessos dessas contas de serviço.

15.5 Contas de Grupos (Group Accounts)

O seu nível de acesso a um sistema não é determinado unicamente pela sua conta de usuário. Cada usuário pode ser membro de um ou mais grupos, o que também afeta diretamente o nível de privilégios e acesso aos arquivos no sistema operacional.

Tradicionalmente, os sistemas UNIX limitavam a participação dos usuários a no máximo dezesseis grupos no total. No entanto, os kernels Linux recentes suportam usuários associados a mais de 65.000 grupos simultaneamente.

O arquivo /etc/passwd define a filiação ao grupo primário de um usuário. Já a filiação aos grupos suplementares (ou grupos secundários), bem como a existência dos próprios grupos, são definidas no arquivo /etc/group.

O arquivo /etc/group é mais um arquivo de texto estruturado e delimitado por caracteres de dois-pontos (:). Abaixo, descrevemos os seus campos em detalhes, utilizando uma linha típica de conta de grupo como base:

Nome do Grupo (Group Name) 

mail:x:12:mail,postfix

Este campo contém o nome do grupo. Assim como acontece com os nomes de usuário, termos em texto são mais naturais e fáceis de memorizar para as pessoas do que números isolados. Internamente, o sistema operacional utiliza IDs numéricos para gerenciar os grupos.

Marcador de Senha (Password Placeholder) 

mail:x:12:mail,postfix

Embora existam senhas para grupos, elas são raramente utilizadas no ecossistema Linux. Se um administrador optar por criar uma senha para um grupo, ela será armazenada de forma segura no arquivo /etc/gshadow. O caractere x neste campo serve apenas para indicar ao sistema que a senha não está armazenada de forma direta neste arquivo.

ID do Grupo (GID) 

mail:x:12:mail,postfix

Cada grupo mapeado no sistema operacional é associado de forma única a um número de identificação de grupo, chamado de GID (Group ID), posicionado exatamente neste campo.

Lista de Usuários (User List) 

mail:x:12:mail,postfix

Este último campo indica explicitamente quais usuários são membros deste grupo. Enquanto o grupo primário de um usuário fica registrado lá no arquivo /etc/passwd, os usuários que forem atribuídos a este grupo como uma função secundária ou suplementar terão seus nomes listados aqui, separados por vírgula. Neste exemplo prático, os usuários mail e postfix são membros secundários do grupo mail.

Nota de Padrão: No Linux, é extremamente comum que um nome de usuário também exista de forma idêntica como um nome de grupo (conhecido como grupo privado do usuário). Também é padrão o usuário pertencer de forma primária a esse grupo de mesmo nome.

Para inspecionar as informações sobre um grupo específico de forma ágil, você pode recorrer tanto ao comando grep quanto ao comando getent. Os exemplos a seguir exibem o mesmo resultado consultando o grupo mail: 

sysadmin@localhost:~$ grep mail /etc/group
mail:x:12:mail,postfix

sysadmin@localhost:~$ getent group mail
mail:x:12:mail,postfix

15.6 Visualizando Informações de Usuários

O comando id é utilizado para exibir as informações de identificação de usuário e de grupo de uma conta específica. 

id [opções] [nome_de_usuário]

Ao alternar frequentemente entre diferentes contas no terminal, pode ser confuso lembrar qual usuário está logado no momento. Quando executado sem nenhum argumento, o comando id exibe as informações do usuário atual da sessão, permitindo que você confirme a sua identidade no sistema. 

sysadmin@localhost:~$ id
uid=1001(sysadmin) gid=1001(sysadmin) groups=1001(sysadmin),4(adm),27(sudo)

A saída do comando id sempre lista as informações da conta do usuário em primeiro lugar, exibindo o ID do usuário (UID) e o nome do usuário: 

uid=1001(sysadmin) gid=1001(sysadmin) groups=1001(sysadmin),4(adm),27(sudo)

Logo após o nome do usuário, o grupo primário é listado, indicado tanto pelo ID do grupo (GID) quanto pelo nome do grupo: 

uid=1001(sysadmin) gid=1001(sysadmin) groups=1001(sysadmin),4(adm),27(sudo)

As demais informações listadas incluem todos os grupos aos quais o usuário pertence (grupos primário e secundários), também indicados pelos IDs dos grupos seguidos por seus respectivos nomes. O usuário do exemplo pertence a três grupos: 

uid=1001(sysadmin) gid=1001(sysadmin) groups=1001(sysadmin),4(adm),27(sudo)

Se o comando receber um nome de usuário como argumento (por exemplo, root), ele exibirá as informações específicas da conta informada, independentemente de quem estiver executando o comando: 

sysadmin@localhost:~$ id root
uid=0(root) gid=0(root) groups=0(root)

Para imprimir apenas o ID numérico do grupo primário do usuário, utilize a opção -g:

sysadmin@localhost:~$ id -g
1001

O comando id também pode ser utilizado para verificar todas as filiações a grupos do usuário (primário e suplementares) em formato numérico usando a opção -G: 

sysadmin@localhost:~$ id -G
1001 4 27
Correlação com o Sistema: O resultado do exemplo anterior se alinha perfeitamente com o conteúdo do arquivo /etc/group. Uma busca pelas ocorrências do termo sysadmin com o comando grep revela exatamente a associação do usuário aos grupos secundários (adm e sudo): 
sysadmin@localhost:~$ cat /etc/group | grep sysadmin
adm:x:4:syslog,sysadmin
sudo:x:27:sysadmin
sysadmin:x:1001:

15.7 Visualizando Usuários Atuais

O comando who exibe uma lista dos usuários que estão atualmente conectados (logados) no sistema, de onde eles estão conectados e quando efetuaram o login. Por meio do uso de opções, este comando também é capaz de exibir informações como o runlevel atual (o estado funcional do computador) e o horário em que o sistema foi inicializado (boot). 

sysadmin@localhost:~$ who
root     	tty2        2013-10-11 10:00
sysadmin	tty1        2013-10-11 09:58 (:0)
sysadmin 	pts/0       2013-10-11 09:59 (:0.0)
sysadmin 	pts/1       2013-10-11 10:00 (example.com)

Abaixo descrevemos detalhadamente as colunas do resultado do comando who:

Nome de Usuário (Username): Indica o nome de quem realizou a autenticação. É importante destacar que por "conectado" entende-se qualquer processo de login ativo ou janela de terminal aberta. 

root     	tty2        2013-10-11 10:00

Terminal: Indica em qual janela ou sessão de terminal o usuário está trabalhando. Se o nome começar com tty, indica um login local (terminal de linha de comando nativo). Se começar com pts, indica uma pseudo-tela, usada para conexões remotas ou janelas de terminal abertas dentro de uma interface gráfica. 

root     	tty2        2013-10-11 10:00
sysadmin	pts/0       2013-10-11 09:59 (:0.0)

Data (Date): Indica o momento exato (data e hora) em que o usuário efetuou o login no sistema.

root     	tty2        2013-10-11 10:00

Host / Origem: Exibe informações sobre a localização do acesso. Se contiver um hostname, nome de domínio ou endereço IP, o usuário realizou um login remoto: 

sysadmin 	pts/1       2013-10-11 10:00 (example.com)

Se houver dois-pontos seguidos de um número, indica que foi realizado um login gráfico local:

sysadmin     tty1        2013-10-11 09:59 (:0)

Se nenhuma informação de localização aparecer na última coluna, significa que o usuário logou diretamente por uma interface local de linha de comando: 

root     	tty2        2013-10-11 10:00
Considere Isto: Status do Sistema O comando who possui opções úteis para analisar o estado do sistema. A opção -b exibe a última inicialização do sistema (boot) e a opção -r mostra o momento em que o sistema atingiu o runlevel atual. 
sysadmin@localhost:~$ who -b -r
         system boot  	2013-10-11 09:54
         run-level 5    2013-10-11 09:54

O Comando w

Haverá momentos em que serão necessárias mais informações sobre os usuários e o que exatamente eles estão executando. O comando w fornece uma lista muito mais detalhada do que o who, além de trazer um resumo completo sobre o estado da máquina: 

sysadmin@localhost:~$ w
 10:44:03 up 50 min,  4 users,  load average: 0.78, 0.44, 0.19
USER     	TTY     FROM	    LOGIN@   IDLE  	JCPU   	PCPU    WHAT
root     	tty2    -           10:00    43:44 	0.01s  	0.01s   -bash
sysadmin 	tty1    :0          09:58    50:02	5.68s 	0.16s   pam: gdm-password
sysadmin	pts/0   :0.0        09:59    0.00s      0.14s  	0.13s   ssh 192.168.1.2
sysadmin 	pts/1   example.com 10:00    0.00s  	0.03s  	0.01s   w

A primeira linha de saída do comando w é idêntica à do comando uptime. Ela exibe a hora atual, há quanto tempo o sistema está ligado, o número total de usuários conectados e a média de carga (load average) do sistema calculada nos últimos 1, 5 e 15 minutos.

A média de carga representa a utilização da CPU onde, para um sistema de um único núcleo (single-core), o valor 1 significa 100% de uso da CPU naquele período. Para um sistema dual-core, significaria 50% de uso, e para um sistema quad-core, representaria 25% de uso.

Campos do Comando w

Coluna Exemplo Descrição
USER root O nome do usuário que efetuou o login.
TTY tty2 Em qual janela ou sessão de terminal o usuário está trabalhando.
FROM example.com A origem de onde o usuário se conectou (host remoto ou local).
LOGIN@ 10:00 O horário em que o usuário efetuou o login.
IDLE 43:44 Tempo de inatividade do usuário desde que o último comando foi executado.
JCPU 0.01s O tempo total de CPU utilizado por todos os processos iniciados desde o login.
PCPU 0.01s O tempo total de CPU consumido unicamente pelo processo atual.
WHAT -bash O comando ou processo atual que o usuário está executando.

* Nota: O caractere s representa segundos nas colunas de tempo de CPU.

15.8 Visualizando Histórico de Login

O comando last lê todo o histórico de autenticações a partir do arquivo /var/log/wtmp e exibe, por padrão, todos os registros de logins e reinicializações (reboots) do sistema.

Um detalhe interessante sobre os registros de reinicialização é que o comando exibe a versão do kernel Linux que foi carregada no boot em vez de exibir um local de login. O arquivo /var/log/wtmp mantém um log contínuo de todos os usuários que entraram e saíram do sistema. 

sysadmin@localhost:~$ last
sysadmin console Tue Sep 18 02:31   still logged in
sysadmin console                    Tue Sep 18 02:31 - 02:31  (00:00)
wtmp begins Tue Sep 18 02:31:57 2018

O comando last funciona de forma ligeiramente diferente dos comandos who e w. Por padrão, ele também exibe o nome de usuário, o terminal e o local de origem do login, mas não se limita apenas às sessões ativas no momento, mostrando também as sessões passadas (históricas).

Além disso, ele exibe a data e a hora exatas em que o usuário se conectou ao sistema. Se o usuário já tiver encerrado a sessão (logout), o comando calcula e exibe o tempo total que o usuário passou conectado; caso contrário, exibirá a mensagem still logged in (ainda conectado).

Considere Isto: utmp vs wtmp O comando who lê as informações diretamente do arquivo /var/log/utmp, que registra estritamente os usuários conectados no momento atual. Por outro lado, o comando last extrai seus dados do arquivo /var/log/wtmp, encarregado de manter o histórico acumulado de todos os logins e logouts do sistema.
