11.2 Shell Scripts em Resumo

Um shell script é um arquivo de texto que armazena comandos executáveis. Quando o arquivo é executado, cada comando é processado sequencialmente. Os shell scripts têm acesso a todos os comandos do shell, incluindo estruturas lógicas. Portanto, um script pode verificar a existência de um arquivo ou buscar por uma saída específica e alterar seu comportamento de acordo.

Você pode construir scripts para automatizar partes repetitivas do seu trabalho, o que libera o seu tempo e garante consistência a cada execução. Por exemplo, se você executa os mesmos cinco comandos todos os dias, pode transformá-los em um shell script que reduz o seu trabalho a apenas um comando.

Um Script Simples

Um script pode ser tão simples quanto um único comando:

echo "Hello, World!"

O script, test.sh, consiste em apenas uma linha que imprime a string Hello, World! no console.

Nota: Este arquivo não está disponível dentro do ambiente de máquina virtual deste curso.

Executando um Script

A execução de um script pode ser feita passando-o como um argumento para o seu shell ou executando-o diretamente:

sysadmin@localhost:~$ sh test.sh
Hello, World!
sysadmin@localhost:~$ ./test.sh
-bash: ./test.sh: Permission denied
sysadmin@localhost:~$ chmod +x ./test.sh
sysadmin@localhost:~$ ./test.sh
Hello, World!

No exemplo acima, primeiro o script é executado como um argumento do shell. Em seguida, o script é executado diretamente a partir do shell. É raro ter o diretório atual no caminho de busca binária $PATH, por isso o nome é prefixado com ./ para indicar que ele deve ser executado a partir do diretório atual.

O erro Permission denied (Permissão negada) significa que o script não foi marcado como executável. Um rápido chmod depois e o script funciona. O comando chmod é usado para alterar as permissões de um arquivo, o que será explicado em detalhes em um capítulo posterior.

O Conceito de Shebang

Existem vários shells com suas próprias sintaxes de linguagem. Portanto, scripts mais complexos indicarão um shell específico especificando o caminho absoluto para o interpretador logo na primeira linha, prefixado por #! como mostrado abaixo: 

#!/bin/sh
echo "Hello, World!"

ou

#!/bin/bash
echo "Hello, World!"

Os dois caracteres #! são tradicionalmente chamados de hash e bang, respectivamente, o que leva à forma abreviada de "shebang" quando usados no início de um script.

O shebang (ou crunchbang) é utilizado para scripts de shell tradicionais e outras linguagens baseadas em texto como Perl, Ruby e Python. Qualquer arquivo de texto marcado como executável será rodado sob o interpretador especificado na primeira linha, desde que o script seja executado diretamente.

Regra de Invocação: Se o script for invocado diretamente como um argumento para um interpretador, como sh script ou bash script, o shell fornecido será utilizado não importa o que esteja na linha do shebang.

Preparação do Ambiente

É fundamental ambientar-se com o uso de um editor de texto antes de começar a escrever shell scripts, já que você precisará criar arquivos em texto puro (plain text). Ferramentas de escritório tradicionais como o LibreOffice — que geram formatos de arquivo contendo estilizações, metadados e outras informações de formatação — não são adequadas para esta tarefa.

11.3 Editando Shell Scripts

O ecossistema UNIX possui muitos editores de texto, e os méritos de um sobre o outro são frequentemente debatidos de forma calorosa. Dois editores são especificamente mencionados no programa do LPI Linux Essentials:

  • O GNU nano: um editor muito simples, ideal para editar pequenos arquivos de texto.
  • O Visual Editor (vi) (ou sua versão mais recente, o VI improved - vim): um editor incrivelmente poderoso, mas que possui uma curva de aprendizado íngreme.

Neste módulo, nosso foco será o nano.

O editor nano possui os recursos básicos para você começar. Você simplesmente digita com o teclado, usa as setas direcionais para se mover pelo texto e o botão Delete/Backspace para apagar. Na parte inferior da tela, ficam visíveis os comandos disponíveis, que são sensíveis ao contexto e mudam dependendo do que você está fazendo.

Dica de Uso: Se você estiver operando diretamente na máquina Linux física (em vez de uma conexão remota via rede), também poderá usar o mouse para mover o cursor e selecionar textos dentro do nano.

Salvando e Saindo do Editor

Observe que a opção no canto inferior esquerdo é ^X Exit, o que significa "pressione Control e X para sair". Ao pressionar Ctrl e X juntos, o menu inferior mudará para o seguinte estado: 

Save modified buffer (ANSWERING "No" WILL DESTROY CHANGES) ?                 
 Y Yes                                                                       
 N No           ^C Cancel

Neste ponto, você pode sair do programar sem salvar pressionando a tecla N, ou salvar as alterações pressionando Y. O comportamento padrão é salvar o arquivo com o nome atual; basta pressionar a tecla Enter para confirmar o nome, salvar e fechar.

Você retornará imediatamente ao prompt do shell após salvar. Caso queira salvar o seu progresso enquanto trabalha sem fechar o editor, basta pressionar Ctrl + O (WriteOut).

Manipulação de Texto (Recortar e Colar)

Você pode praticar a edição utilizando atalhos de buffer de cópia:

  1. Use as setas direcionais para mover o cursor até a linha que contém "the time is ".
  2. Pressione Ctrl + K duas vezes seguidas para recortar as duas últimas linhas para o buffer.
  3. Mova o cursor para a linha restante e unsafe pressione Ctrl + U uma vez para colar o conteúdo do buffer na posição atual.

Isso fará com que o script exiba a hora atual antes de saudar o usuário, poupando o trabalho de ter que redigitar as linhas do zero.

11.4 Fundamentos de Scripting

Você teve o seu primeiro contato com o desenvolvimento de scripts anteriormente neste capítulo, onde introduzimos um script extremamente básico que executava um único comando. O script começava com a linha do shebang (ou hashbang), informando ao Linux que o interpretador /bin/bash (que é o Bash) deve ser utilizado para executar o script em questão.

Os Três Pilares Essenciais

Além de simplesmente executar sequências de comandos básicos, existem 3 tópicos essenciais com os quais você deve se familiarizar para construir scripts inteligentes:

Variáveis

Servem para armazenar e manipular informações temporárias durante o ciclo de execução do script.

Condicionais

Permitem que o script tome decisões e execute diferentes blocos de código com base nos testes e validações que você definir.

Loops (Laços de Repetição)

Permitem que o script repita a mesma tarefa ou conjunto de instruções de forma iterativa e automatizada quantas vezes for necessário.

11.4.1 Variáveis

As variáveis são uma parte fundamental de qualquer linguagem de programação. Pense em uma variável como uma caixa onde você pode armazenar informações temporárias. Veja um exemplo simples de uso: 

#!/bin/bash

ANIMAL="penguin"
echo "My favorite animal is a $ANIMAL"

Logo após a linha do shebang, temos uma diretiva para atribuir um texto a uma variável. O nome da variável é ANIMAL e o sinal de igual (=) atribui a string penguin a ela. Após a execução dessa linha, a caixa chamada ANIMAL conterá a palavra penguin.

Atenção com Espaços: É fundamental que não haja espaços entre o nome da variável, o sinal de igual e o valor atribuído. Se você inserir um espaço ali, receberá um erro estranho do tipo "command not found" (comando não encontrado).

Escrever o nome da variável em letras maiúsculas não é obrigatório, mas é uma convenção muito útil para separar visualmente as suas variáveis dos comandos do sistema que serão executados.

No comando echo, o nome da variável é precedido por um sinal de cifrão ($). Quando o interpretador encontra esse caractere, ele reconhece que deve substituir o nome pelo conteúdo real da variável — um processo chamado de interpolação. A saída do script será: My favorite animal is a penguin.

Atribuição Entre Variáveis

Para atribuir um valor a uma variável, use apenas o seu nome. Para acessar o seu conteúdo, adicione o prefixo $. É perfeitamente possível atribuir o conteúdo de uma variável a outra: 

#!/bin/bash

ANIMAL=penguin
SOMETHING=$ANIMAL
echo "My favorite animal is a $SOMETHING"

Aqui, ANIMAL recebe a string penguin (neste exemplo, demonstrando a sintaxe alternativa sem o uso de aspas). A variável SOMETHING recebe então o conteúdo de ANIMAL (porque ela possui o cifrão na frente).

Substituição de Comandos (Backticks)

Outra forma poderosa de definir uma variável é usar a saída de um comando do sistema como o seu conteúdo, envolvendo o comando com crases (backticks): 

#!/bin/bash
CURRENT_DIRECTORY=`pwd`
echo "You are in $CURRENT_DIRECTORY"

Esse padrão é amplamente utilizado no processamento de textos. Você pode extrair dados de uma variável ou arquivo de entrada, passá-los por comandos como sed (editor de fluxos para STDIN) ou awk (linguagem de processamento de texto) e salvar o resultado filtrado diretamente em uma nova variável.

Interação e Entrada do Usuário (read)

Você pode capturar dados digitados diretamente pelo usuário do script utilizando o comando read:

#!/bin/bash

echo -n "What is your name? "
read NAME
echo "Hello $NAME!"

O comando read aceita dados diretamente do teclado ou por meio de redirecionamentos de comandos (como pipes e arquivos).

Variáveis Especiais e Argumentos de Entrada

O Linux disponibiliza variáveis internas especiais para lidar com parâmetros passados externamente para o script:

#!/bin/bash
echo "Hello $1"

O sinal de cifrão seguido por um número N corresponde ao enésimo argumento passado para o script. Se você executar o script acima como ./test.sh World, a saída será Hello World. A variável especial $0 contém o próprio nome do script executado.

Códigos de Retorno (Exit Codes)

Sempre que um programar ou script termina sua execução, ele retorna um código de saída (exit code), que é um número inteiro entre 0 e 255. Você pode consultar o resultado do último comando executado através da variável especial $?: 

sysadmin@localhost:~$ grep -q root /etc/passwd
sysadmin@localhost:~$ echo $?
0
sysadmin@localhost:~$ grep -q slartibartfast /etc/passwd
sysadmin@localhost:~$ echo $?
1

O comando grep foi executado com a flag -q (modo silencioso ou quiet). Nesse modo, o grep não exibe texto na tela, mas retorna 0 se a string for encontrada e 1 caso contrário. Essa resposta é crucial para estruturas condicionais tomarem decisões.

Controlando a Saída e Comentários

Você pode definir manualmente o código de saída do seu script utilizando o comando exit:

#!/bin/bash
# Algo de errado aconteceu!
exit 1

O exemplo acima também introduz o uso de comentários usando o caractere #. Qualquer texto inserido após a hashtag na mesma linha será ignorado pelo interpretador, servindo como notas para o desenvolvedor.

Convenção Padrão: Por padrão no Linux, um código de saída igual a 0 significa que tudo ocorreu perfeitamente ("everything is OK"). Qualquer código maior que 0 indica que algum tipo de erro específico do programa aconteceu.

11.4.2 Condicionais

Agora que você já sabe manipular variáveis, é hora de fazer seu script executar funções diferentes com base em testes e tomadas de decisão — um conceito chamado de desvio condicional (branching). A instrução if é o operador básico para implementar essa lógica.

Uma estrutura básica do comando if funciona da seguinte forma:

if comando_qualquer; then
  # este bloco será executado se o comando_qualquer retornar exit code 0
fi

O interpretador executará tudo o que estiver posicionado até o ponto e vírgula. Se o código de saída (exit code) for 0 (sucesso), as instruções localizadas até o fechamento com a palavra-chave invertida fi serão processadas.

A Estrutura if/else

Utilizando o comportamento do comando grep, podemos criar um script que reage de formas diferentes dependendo da existência de um usuário dentro do arquivo de senhas do sistema: 

#!/bin/bash

if grep -q root /etc/passwd; then
  echo "root is in the password file"
else
  echo "root is missing from the password file"
fi

Em vez de apenas fechar o bloco com fi, introduzimos a cláusula else. Isso permite determinar uma ação padrão caso a condição testada seja falsa. O bloco do else também deve ser finalizado obrigatoriamente com o termo fi.

O Comando test e Operadores de Comparação

Para tarefas comuns, como verificar a existência de arquivos, diretórios ou comparar strings e valores numéricos, utilizamos o comando test. Ele disponibiliza operadores específicos para essas validações:

Comando Descrição
test -f /dev/ttyS0 Retorna 0 se o arquivo existir e for um arquivo regular.
test ! -f /dev/ttyS0 Retorna 0 se o arquivo não existir (operador de negação !).
test -d /tmp Retorna 0 se o diretório pesquisado existir.
test -x `which ls` Localiza o binário do comando ls e testa se o usuário atual tem permissão de execução.
test 1 -eq 1 Retorna 0 se os números forem numericamente iguais (Equal).
test ! 1 -eq 1 Inverte o resultado. Retorna 0 se a comparação falhar.
test 1 -ne 1 Forma direta para testar desigualdade numérica (Not Equal).
test "a" = "a" Retorna 0 se a comparação de strings for idêntica.
test "a" != "a" Retorna 0 se as strings comparadas forem diferentes.
test 1 -eq 1 -o 2 -eq 2 Operador lógico OR (-o): retorna sucesso se pelo menos uma das condições for verdadeira.
test 1 -eq 1 -a 2 -eq 2 Operador lógico AND (-a): retorna sucesso somente se ambas as condições forem verdadeiras.
Importante: O comando test avalia de forma totalmente distinta strings e inteiros. Por exemplo, os valores 01 e 1 são considerados idênticos em uma comparação numérica (-eq), mas são interpretados como diferentes em uma comparação de strings (=). Fique sempre atento ao tipo de dado esperado.

Existem diversos outros operadores, como o -gt (greater than) para validar se um número é maior que outro. Para uma listagem completa, consulte as páginas de manual do comando rodando man test.

O Atalho dos Colchetes [ ]

Como o comando test é usado de forma recorrente, o shell disponibiliza um alias mais enxuto: o caractere de colchete esquerdo [. Envolver uma expressão em colchetes é semanticamente idêntico a chamar o comando test. Portanto, estas duas estruturas são equivalentes: 

if test -f /tmp/foo; then

ou

if [ -f /tmp/foo ]; then
Sintaxe do Colchete: Embora a segunda forma seja a mais utilizada no dia a dia, lembre-se de que o colchete esquerdo é um comando isolado do sistema. Ele requer obrigatoriamente um espaço após a sua abertura e exige o colchete de fechamento ] como seu último argumento.

Múltiplas Validações com elif

A instrução if permite realizar encadeamentos de múltiplos testes sequenciais utilizando o operador elif (abreviação de else if): 

#!/bin/bash

if [ "$1" = "hello" ]; then
  echo "hello yourself"
elif [ "$1" = "goodbye" ]; then
  echo "nice to have met you"
  echo "I hope to see you again"
else
  echo "I didn't understand that"
fi

O script acima avalia o primeiro argumento ($1) enviado pelo terminal. Observe que a variável $1 foi envolvida em aspas e foi utilizado o operador de igualdade textual (=) em vez da versão numérica (-eq).

Simplificando Fluxos com o comando case

Quando as estruturas com múltiplos elif tornam-se muito extensas e complexas, o comando case oferece uma alternativa mais limpa e legível para realizar casamentos de padrões: 

#!/bin/bash

case "$1" in
hello|hi)
  echo "hello yourself"
  ;;
goodbye)
  echo "nice to have met you"
  echo "I hope to see you again"
  ;;
*)
  echo "I didn't understand that"
esac

A instrução inicial define a expressão que passará pelo crivo de testes: case EXPRESSÃO in. Cada bloco avaliativo termina com um caractere de parêntese de fechamento ). No primeiro caso, usamos a barra vertical | para funcionar como o operador lógico OR, aceitando tanto hello quanto hi.

As instruções internas executadas dentro de um padrão correspondido devem obrigatoriamente terminar com **dois pontos e vírgulas seguidos (;;)**. O caractere curinga de asterisco * funciona de forma análoga à cláusula else, capturando qualquer valor residual que não tenha casado com as regras anteriores. Por fim, fechamos toda a estrutura invertendo a palavra inicial: esac.

11.4.3 Loops (Laços de Repetição)

Os Loops permitem que um bloco de código seja executado repetidamente. Eles são extremamente úteis em inúmeras situações, como quando você precisa aplicar os mesmos comandos para cada arquivo dentro de um diretório ou repetir uma ação específica 100 vezes. Existem dois laços de repetição principais em shell scripts: o loop for e o loop while.

O Loop for

Os loops for são utilizados quando você possui uma coleção finita sobre a qual deseja iterar, como uma lista de arquivos ou uma lista de nomes de servidores: 

#!/bin/bash

SERVERS="servera serverb serverc"
for S in $SERVERS; do
  echo "Doing something to $S"
done

O script define primeiro uma variável contendo uma lista de nomes de servidores separados por espaço. A instrução for então itera sobre essa lista, e a cada passagem ela define a variável temporária S com o nome do servidor atual. A escolha do nome S foi arbitrária. Note que o S inicial não possui o cifrão, mas $SERVERS possui, indicando que a variável original será expandida na lista de elementos.

Passagem Direta e Globbing de Arquivos

A lista de elementos não precisa obrigatoriamente estar dentro de uma variável. O exemplo abaixo demonstra duas formas alternativas de passar dados para o laço: 

#!/bin/bash

for NAME in Sean Jon Isaac David; do
  echo "Hello $NAME"
done

for S in *; do
  echo "Doing something to $S"
done

O primeiro loop funciona exatamente como o exemplo anterior, mas a lista de nomes é passada diretamente para o for, sem intermediários. No entanto, usar uma variável no início ajuda na clareza do script, pois permite que outra pessoa faça alterações na lista facilmente sem precisar mexer na lógica do laço.

O segundo loop utiliza o caractere asterisco (*), que é um glob de arquivo. O shell expande esse caractere transformando-o em uma lista contendo todos os arquivos presentes no diretório atual.

O Loop while

O outro tipo de laço, o loop while, opera sobre listas ou condições de tamanho desconhecido. O seu papel é continuar executando e, a cada iteração, realizar um teste lógico para verificar se deve ou não rodar mais uma vez. Você pode pensar nele como: "enquanto esta condição for verdadeira, continue fazendo isso". 

#!/bin/bash

i=0
while [ $i -lt 10 ]; do
  echo $i
  i=$(( $i + 1 ))
done
echo "Done counting"

O exemplo acima mostra um loop while que faz uma contagem de 0 a 9. Uma variável contadora, i, é inicializada com o valor 0. Em seguida, o while é executado testando: "o valor de $i é menor que 10?" (operador -lt de less than). Observe que o loop while utiliza a mesmíssima sintaxe de colchetes que aprendemos no comando if!

Dentro do bloco, o valor atual de i é exibido na tela e, logo depois, o valor 1 é somado à variável por meio da sintaxe de expressão aritmética $(( aritmética )). Assim que i atinge o valor 10, o teste do while retorna falso e o interpretador segue o fluxo, executando o código posicionado após o laço.
