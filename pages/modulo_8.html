Módulo 8

Manipulando Arquivos e Diretórios

Aprenda a criar, mover, copiar e remover arquivos e diretórios no Linux

8.1 Introdução

Ao trabalhar em um sistema operacional Linux, é importante saber como manipular arquivos e diretórios. Algumas distribuições Linux possuem aplicações baseadas em interface gráfica (GUI) que permitem gerenciar arquivos, mas é vantajoso saber como realizar essas operações via linha de comando.

Nota: É importante notar que tudo no Linux é sensível a maiúsculas e minúsculas (case-sensitive), uma característica herdada do Unix. Isso significa que o shell reconhece um caractere minúsculo a-z como completamente diferente de um caractere maiúsculo A-Z. Ao manipular arquivos, preste atenção às suas maiúsculas: um arquivo hello.txt é diferente dos arquivos HELLO.txt e Hello.txt.

O padrão de caracteres usado para Linux é o padrão UTF-8, que é baseado no ASCII (American Standard Code for Information Interchange - Código Padrão Americano para Intercâmbio de Informações). Para aprender mais sobre ASCII, execute o comando man -s 7 ascii. 

sysadmin@localhost:~$ man -s 7 ascii

8.2 Globbing

Os caracteres glob são frequentemente chamados de curingas (wild cards). Estes são caracteres simbólicos que têm significado especial para o shell.

Os globs são poderosos porque permitem que você especifique padrões que correspondem a nomes de arquivos em um diretório. Então, em vez de manipular um único arquivo por vez, você pode facilmente executar comandos que afetam muitos arquivos. Por exemplo, usando caracteres glob, é possível manipular todos os arquivos com uma extensão específica ou com um comprimento de nome de arquivo particular.

Ao contrário dos comandos que o shell executa, ou opções e argumentos que o shell passa para os comandos, os caracteres glob são interpretados pelo próprio shell antes que ele tente executar qualquer comando. Como resultado, os caracteres glob podem ser usados com qualquer comando.

Os exemplos fornecidos neste capítulo usam o comando echo para demonstração.

Importante: O globbing é feito pelo shell, não pelo comando. Isso significa que os caracteres curinga são expandidos antes do comando ser executado.

8.2.1 Caractere Asterisco *

O caractere asterisco * é usado para representar zero ou mais de qualquer caractere em um nome de arquivo. Por exemplo, para exibir todos os arquivos no diretório /etc que começam com a letra t: 

sysadmin@localhost:~$ echo /etc/t*                              
/etc/terminfo /etc/timezone /etc/tmpfiles.d

O padrão t* corresponde a qualquer arquivo no diretório /etc que começa com o caractere t seguido por zero ou mais de qualquer caractere. Em outras palavras, quaisquer arquivos que começam com a letra t.

Você pode usar o caractere asterisco em qualquer lugar dentro do padrão do nome do arquivo. Por exemplo, o seguinte corresponde a qualquer nome de arquivo no diretório /etc que termina com .d: 

sysadmin@localhost:~$ echo /etc/*.d                                 
/etc/apparmor.d /etc/binfmt.d /etc/cron.d /etc/depmod.d /etc/init.d /etc/insserv.conf.d /etc/ld.so.conf.d /etc/logrotate.d /etc/modprobe.d /etc/modules-load.d /etc/pam.d /etc/profile.d /etc/rc0.d /etc/rc1.d /etc/rc2.d /etc/rc3.d /etc/rc4.d /etc/rc5.d /etc/rc6.d /etc/rcS.d /etc/rsyslog.d /etc/sudoers.d /etc/sysctl.d /etc/tmpfiles.d /etc/update-motd.d

No próximo exemplo, todos os arquivos no diretório /etc que começam com a letra r e terminam com .conf são exibidos: 

sysadmin@localhost:~$ echo /etc/r*.conf                             
/etc/resolv.conf /etc/rsyslog.conf

8.2.2 Caractere Ponto de Interrogação ?

O caractere ponto de interrogação ? representa qualquer caractere único. Cada caractere de ponto de interrogação corresponde a exatamente um caractere, nem mais nem menos.

Suponha que você queira exibir todos os arquivos no diretório /etc que começam com a letra t e têm exatamente 7 caracteres após o caractere t: 

sysadmin@localhost:~$ echo /etc/t???????      
/etc/terminfo /etc/timezone

Os caracteres glob podem ser usados em conjunto para encontrar padrões ainda mais complexos. O padrão /etc/*???????????????????? corresponde apenas a arquivos no diretório /etc com vinte ou mais caracteres no nome do arquivo: 

sysadmin@localhost:~$ echo /etc/*????????????????????            
/etc/bindresvport.blacklist /etc/ca-certificates.conf

O asterisco e o ponto de interrogação também podem ser usados juntos para procurar arquivos com extensões de três letras usando o padrão /etc/*.???: 

sysadmin@localhost:~$ echo /etc/*.???                
/etc/issue.net /etc/locale.gen

8.2.5 Listando com Globs

O comando ls é normalmente usado para listar arquivos em um diretório; como resultado, usar o comando echo pode parecer ter sido uma escolha estranha. No entanto, há algo sobre o comando ls que causa problemas ao listar arquivos usando padrões glob.

Tenha em mente que é o shell, não o comando echo ou ls, que expande o padrão glob em nomes de arquivos correspondentes. Em outras palavras, se o comando echo /etc/a* for executado, o que o shell fez antes de executar o comando echo foi substituir a* por todos os arquivos e diretórios dentro do diretório /etc que correspondem ao padrão.

Então, se o comando ls /etc/a* for executado, o que o shell realmente executaria seria isto:

ls /etc/adduser.conf  /etc/alternatives  /etc/apparmor  /etc/apparmor.d  /etc/apt

Quando o comando ls vê múltiplos argumentos, ele executa uma operação de lista em cada item separadamente. Em outras palavras, ls /etc/a* é o mesmo que executar os seguintes comandos consecutivamente: 

ls /etc/adduser.conf  
ls /etc/alternatives  
ls /etc/apparmor  
ls /etc/apparmor.d  
ls /etc/apt

Agora considere o que acontece se o comando ls receber um arquivo, como /etc/adduser.conf:

sysadmin@localhost:~$ ls /etc/adduser.conf
/etc/adduser.conf

Executar o comando ls em um único arquivo resulta na impressão do nome do arquivo; tipicamente isso é útil se a opção -l for usada para ver detalhes sobre um arquivo específico: 

sysadmin@localhost:~$ ls -l /etc/adduser.conf                                   
-rw-r--r-- 1 root root 3028 May 26  2018 /etc/adduser.conf

No entanto, e se o comando ls receber um nome de diretório como argumento? Neste caso, a saída do comando é diferente do que se o argumento fosse um arquivo regular: 

sysadmin@localhost:~$ ls /etc/apparmor                                          
init  parser.conf  subdomain.conf

Se o comando ls receber um nome de diretório, o comando exibe o conteúdo do diretório (os nomes dos arquivos no diretório), não apenas o nome do diretório. Os nomes de arquivos no exemplo anterior são os nomes dos arquivos no diretório /etc/apparmor.

Por que isso é um problema ao usar globs? Considere a seguinte saída:

sysadmin@localhost:~$ ls /etc/ap*                                               
/etc/apparmor:                                                                  
init  parser.conf  subdomain.conf                                               
                                                                                
/etc/apparmor.d:                                                                
abstractions  disable         local          tunables     usr.sbin.named        
cache         force-complain  sbin.dhclient  usr.bin.man  usr.sbin.rsyslogd     
                                                                                
/etc/apt:                                                                       
apt.conf.d  preferences.d  sources.list  sources.list.d  trusted.gpg.d

Quando o comando ls vê um nome de arquivo como argumento, ele apenas exibe o nome do arquivo. No entanto, para qualquer diretório, ele exibe o conteúdo do diretório, não apenas o nome do diretório.

Isso se torna ainda mais confuso em uma situação como a seguinte:

sysadmin@localhost:~$ ls /etc/x*                                                
autostart  systemd  user-dirs.conf  user-dirs.defaults

No exemplo anterior, parece que o comando ls está simplesmente errado. No entanto, o que realmente aconteceu é que a única coisa que corresponde ao glob /etc/x* é o diretório /etc/xdg.

Então, o comando ls apenas exibiu os arquivos naquele diretório!

Há uma solução simples para este problema: sempre use a opção -d com globs, que instrui o comando ls a exibir o nome dos diretórios, em vez de seu conteúdo: 

sysadmin@localhost:~$ ls -d /etc/x*                                             
/etc/xdg

8.3 Copiando Arquivos

O comando cp é usado para copiar arquivos. Ele requer uma origem e um destino. A estrutura do comando é a seguinte: 

cp source destination

A origem é o arquivo a ser copiado. O destino é onde a cópia será localizada. Quando bem-sucedido, o comando cp não tem nenhuma saída (sem notícias é boa notícia). O seguinte comando copia o arquivo /etc/hosts para o seu diretório home: 

sysadmin@localhost:~$ cp /etc/hosts ~                                     
sysadmin@localhost:~$ ls
Desktop    Downloads  Pictures  Templates  hosts                          
Documents  Music      Public    Videos
Dica: O símbolo ~ (til) é um atalho que representa o diretório home do usuário atual.

8.3.1 Modo Verboso

A opção -v faz com que o comando cp produza saída se for bem-sucedido. A opção -v significa verboso (verbose): 

sysadmin@localhost:~$ cp -v /etc/hosts ~                              
`/etc/hosts' -> `/home/sysadmin/hosts'

Quando o destino é um diretório, o novo arquivo resultante mantém o mesmo nome que o arquivo original. Para dar ao novo arquivo um nome diferente, forneça o novo nome como parte do destino: 

sysadmin@localhost:~$ cp /etc/hosts ~/hosts.copy                      
sysadmin@localhost:~$ ls                                               
Desktop    Downloads  Pictures  Templates  hosts                       
Documents  Music      Public    Videos     hosts.copy
Dica: A opção -v é útil para verificar se a operação foi realizada com sucesso, especialmente ao copiar muitos arquivos de uma só vez.

8.3.2 Evitando Sobrescrita de Dados

O comando cp pode ser destrutivo para dados existentes se o arquivo de destino já existir. No caso em que o arquivo de destino existe, o comando cp sobrescreve o conteúdo do arquivo existente com o conteúdo do arquivo de origem.

Para ilustrar este problema potencial, primeiro um novo arquivo é criado no diretório home copiando um arquivo existente:

sysadmin@localhost:~$ cp /etc/hostname example.txt

Visualize as informações sobre o arquivo com o comando ls:

sysadmin@localhost:~$ ls -l example.txt                                         
-rw-r--r-- 1 sysadmin sysadmin 10 Dec 15 22:55 example.txt

Visualize o conteúdo do arquivo usando o comando cat:

sysadmin@localhost:~$ cat example.txt                                           
localhost

No próximo exemplo, o comando cp destrói o conteúdo original do arquivo example.txt:

sysadmin@localhost:~$ cp /etc/timezone example.txt

Observe que após o comando cp ser concluído, o tamanho do arquivo mudou e o conteúdo é diferente:

sysadmin@localhost:~$ ls -l example.txt                                         
-rw-r--r-- 1 sysadmin sysadmin 8 Dec 15 22:58 example.txt
sysadmin@localhost:~$ cat example.txt
Etc/UTC

Duas opções podem ser usadas para proteger contra sobrescritas acidentais. Com a opção interativa -i, o comando cp solicita ao usuário antes de sobrescrever um arquivo. O exemplo a seguir demonstra esta opção, primeiro restaurando o conteúdo do arquivo original: 

sysadmin@localhost:~$ cp -i /etc/hosts example.txt                   
cp: overwrite `/home/sysadmin/example.txt'? n

Se um valor y (yes/sim) fosse dado, então o processo de cópia teria ocorrido. No entanto, o valor n (no/não) foi dado quando solicitado a sobrescrever o arquivo, então nenhuma mudança foi feita no arquivo.

A opção -i exige que você responda y ou n para cada cópia que possa acabar sobrescrevendo o conteúdo de um arquivo existente. Isso pode ser tedioso quando muitas sobrescritas ocorrem, como no exemplo demonstrado abaixo: 

sysadmin@localhost:~$ cp -i /etc/skel/.* ~                             
cp: -r not specified; omitting directory '/etc/skel/.'                          
cp: -r not specified; omitting directory '/etc/skel/..'                                   
cp: overwrite `/home/sysadmin/.bash_logout'? n                         
cp: overwrite `/home/sysadmin/.bashrc'? n                              
cp: overwrite `/home/sysadmin/.profile'? n                            
cp: overwrite `/home/sysadmin/.selected_editor'? n

Como você pode ver no exemplo acima, o comando cp tentou sobrescrever quatro arquivos existentes, forçando o usuário a responder a quatro prompts. Se esta situação acontecesse para 100 arquivos, poderia se tornar muito irritante, muito rapidamente.

Para responder n a cada prompt automaticamente, use a opção -n. Ela significa no clobber (sem sobrescrita). 

sysadmin@localhost:~$ cp -n /etc/skel/.* ~                                      
cp: -r not specified; omitting directory '/etc/skel/.'                          
cp: -r not specified; omitting directory '/etc/skel/..'
Cuidado: Sempre tenha atenção ao usar o comando cp, pois ele substitui arquivos sem aviso prévio a menos que você use as opções -i ou -n.

8.3.3 Copiando Diretórios

Por padrão, o comando cp não copia diretórios; qualquer tentativa de fazê-lo resulta em uma mensagem de erro:

sysadmin@localhost:~$ cp -n /etc/skel/.* ~                                      
cp: -r not specified; omitting directory '/etc/skel/.'                          
cp: -r not specified; omitting directory '/etc/skel/..'

No entanto, a opção recursiva -r permite que o comando cp copie tanto arquivos quanto diretórios.

cp -r source_directory destination_directory

Tenha cuidado com esta opção. Toda a estrutura de diretórios será copiada, o que pode resultar na cópia de muitos arquivos e diretórios!

Considere Isto: As opções -r e -R servem ao mesmo propósito. No entanto, -R pode ser usada com a maioria dos comandos, enquanto -r pode ter significados diferentes com alguns comandos. Por exemplo, enquanto cp -r significa copiar recursivamente (ambos arquivos e diretórios), ls -r significa ordenação reversa (reverse sort).

8.4 Movendo Arquivos

Para mover um arquivo, use o comando mv. A sintaxe para o comando mv é muito parecida com o comando cp: 

mv source destination

No exemplo a seguir, o arquivo hosts que foi gerado anteriormente é movido do diretório atual para o diretório Videos: 

sysadmin@localhost:~$ ls                                               
Desktop    Downloads  Pictures  Templates  example.txt  hosts.copy     
Documents  Music      Public    Videos     hosts                       
sysadmin@localhost:~$ mv hosts Videos                                  
sysadmin@localhost:~$ ls                                               
Desktop    Downloads  Pictures  Templates  example.txt                 
Documents  Music      Public    Videos     hosts.copy                 
sysadmin@localhost:~$ ls Videos                                        
hosts

Quando um arquivo é movido, o arquivo é removido da localização original e colocado em uma nova localização. Mover arquivos pode ser um pouco complicado no Linux porque os usuários precisam de permissões específicas para remover arquivos de um diretório. Sem as permissões corretas, uma mensagem de erro Permission denied é retornada: 

sysadmin@localhost:~$ mv /etc/hosts .
mv: cannot move `/etc/hosts' to `./hosts': Permission denied
Nota: Permissões serão abordadas em detalhes mais adiante no curso.

8.4.1 Renomeando Arquivos

O comando mv não é usado apenas para mover um arquivo, mas também para renomear um arquivo. Se o destino do comando mv for um diretório, o arquivo é movido para o diretório especificado. O nome do arquivo só muda se um nome de arquivo de destino também for especificado. 

sysadmin@localhost:~$ ls                                               
Desktop    Downloads  Pictures  Templates  example.txt                          
Documents  Music      Public    Videos     hosts.copy                 
sysadmin@localhost:~$ mv example.txt Videos/newexample.txt             
sysadmin@localhost:~$ ls
Desktop    Downloads  Pictures  Templates  hosts.copy                           
Documents  Music      Public    Videos                               
sysadmin@localhost:~$ ls Videos                                       
hosts  newexample.txt

Se um diretório de destino não for especificado, o arquivo é renomeado usando o nome do arquivo de destino e permanece no diretório de origem. Por exemplo, os seguintes comandos renomeiam o arquivo newexample.txt para myfile.txt: 

sysadmin@localhost:~$ cd Videos                                        
sysadmin@localhost:~/Videos$ ls                                        
hosts  newexample.txt                                                  
sysadmin@localhost:~/Videos$ mv newexample.txt myfile.txt           
sysadmin@localhost:~/Videos$ ls
hosts  myfile.txt
Dica: Pense no exemplo anterior como: mova o arquivo newexample.txt do diretório atual para o diretório atual e dê ao novo arquivo o nome myfile.txt.

8.4.2 Opções Adicionais do Move

Assim como o comando cp, o comando mv fornece as seguintes opções:

Opção Significado
-i Interativo: Pergunta se um arquivo deve ser sobrescrito.
-n No Clobber: Não sobrescreve o conteúdo de um arquivo de destino.
-v Verbosos: Mostra a movimentação resultante.
Importante: Não há opção -r pois o comando mv move diretórios por padrão.

8.5 Criando Arquivos

Existem várias maneiras de criar um novo arquivo, incluindo o uso de um programa projetado para editar um arquivo (um editor de texto).

Também há uma maneira de criar um arquivo vazio que pode ser preenchido com dados posteriormente. Este recurso é útil para alguns sistemas operacionais, pois a própria existência de um arquivo pode alterar como um comando ou serviço funciona. Também é útil criar um arquivo como um "placeholder" para lembrá-lo de criar o conteúdo do arquivo em um momento posterior.

Para criar um arquivo vazio, use o comando touch conforme demonstrado abaixo:

sysadmin@localhost:~$ touch sample                                     
sysadmin@localhost:~$ ls -l sample                                     
-rw-rw-r-- 1 sysadmin sysadmin 0 Nov  9 16:48 sample

Observe que o tamanho do novo arquivo é 0 bytes. Como mencionado anteriormente, o comando touch não coloca nenhum dado dentro do novo arquivo.

Nota: Editores de texto serão abordados em detalhes mais adiante no curso.

8.6 Removendo Arquivos

Para deletar um arquivo, use o comando rm:

sysadmin@localhost:~$ ls                                               
Desktop    Downloads  Pictures  Templates  hosts.copy                           
Documents  Music      Public    Videos     sample                         
sysadmin@localhost:~$ rm sample    
sysadmin@localhost:~$ rm hosts.copy                                    
sysadmin@localhost:~$ ls
Desktop  Documents  Downloads  Music  Pictures  Public  Templates  Videos

Observe que os arquivos foram deletados sem nenhuma pergunta. Isso pode causar problemas ao deletar múltiplos arquivos usando caracteres glob. Como esses arquivos são deletados sem questionamento, um usuário pode acabar deletando arquivos que não pretendia deletar.

Atenção: Os arquivos são permanentemente deletados. Não há comando para desfazer a exclusão (undelete) e não há lixeira de onde recuperar arquivos deletados.

Como precaução, os usuários devem usar a opção -i ao deletar múltiplos arquivos:

sysadmin@localhost:~$ touch sample.txt example.txt test.txt            
sysadmin@localhost:~$ ls                                               
Desktop    Downloads  Pictures  Templates  example.txt  test.txt       
Documents  Music      Public    Videos     sample.txt                 
sysadmin@localhost:~$ rm -i *.txt                                     
rm: remove regular empty file `example.txt'? y                         
rm: remove regular empty file `sample.txt'? n                          
rm: remove regular empty file `test.txt'? y                            
sysadmin@localhost:~$ ls                                               
Desktop    Downloads  Pictures  Templates  sample.txt                  
Documents  Music      Public    Videos
Dica: Use sempre rm -i ao trabalhar com globs para evitar exclusões acidentais. A opção -i torna o comando interativo, perguntando antes de cada exclusão.

8.7 Criando Diretórios

Para criar um diretório, use o comando mkdir:

sysadmin@localhost:~$ ls                                               
Desktop  Documents  Downloads  Music  Pictures  Public  Templates  sample.txt
sysadmin@localhost:~$ mkdir test                                       
sysadmin@localhost:~$ ls                                               
Desktop    Downloads  Pictures  Templates   test                       
Documents  Music      Public    sample.txt
Dica: mkdir vem de make directory (criar diretório).
