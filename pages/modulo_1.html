1.2 Linux é um Kernel

A definição da palavra Linux depende do contexto em que é usada. Linux significa o kernel do sistema, que é o controlador central de tudo o que acontece no computador.


Quando a maioria das pessoas se refere ao Linux, elas estão na verdade se referindo a uma combinação de software chamada GNU/Linux, que define o sistema operacional. GNU é o software livre que fornece equivalentes de código aberto para muitos comandos comuns do UNIX. A parte Linux desta combinação é o kernel Linux, que é o núcleo do sistema operacional. O kernel é carregado na inicialização e permanece em execução para gerenciar todos os aspectos do funcionamento do sistema.

A História do UNIX

A história do Linux começa com UNIX, um sistema operacional desenvolvido nos laboratórios AT&T Bell na década de 1970. UNIX foi escrito na linguagem C, tornando-o unicamente portável entre sistemas operacionais concorrentes, que normalmente estavam intimamente ligados ao hardware para o qual foram escritos. Ele rapidamente ganhou popularidade em ambientes de pesquisa e acadêmicos, bem como entre programadores atraídos por sua modularidade.


Com o tempo, foi modificado e bifurcado (forked - isto é, as pessoas o modificaram, e essas modificações serviram de base para outros sistemas), de modo que atualmente existem muitas variantes diferentes do UNIX. No entanto, UNIX é agora tanto uma marca registrada quanto uma especificação, pertencente a um consórcio da indústria chamado Open Group. Apenas software que foi certificado pelo Open Group pode se chamar UNIX.

O Nascimento do Linux

O Linux começou em 1991 como um projeto de hobby de Linus Torvalds, um cientista da computação finlandês que estudava na Universidade de Helsinque. Frustrado com o licenciamento do MINIX (um sistema operacional semelhante ao UNIX projetado para uso educacional) e com o desejo de seu criador de não torná-lo um sistema operacional completo, Linus decidiu criar seu próprio kernel de SO.


A partir deste começo humilde, o Linux cresceu para se tornar o sistema operacional dominante na Internet, e indiscutivelmente o programa de computador mais importante de todos os tipos. Apesar de adotar todos os requisitos da especificação UNIX, o Linux não foi certificado, então o Linux realmente não é UNIX! É apenas... semelhante ao UNIX (UNIX-like).

O Projeto GNU

Antes e paralelamente a este desenvolvimento estava o Projeto GNU, criado por Richard Stallman em 1983. Enquanto o GNU inicialmente focava em construir seu próprio sistema operacional, eles acabaram sendo muito mais eficazes na construção de ferramentas que acompanham um sistema operacional semelhante ao UNIX, como editores, compiladores e interfaces de usuário que tornam um kernel utilizável.


Como o código-fonte estava totalmente disponível gratuitamente, os programadores do Linux puderam incorporar as ferramentas GNU para fornecer um sistema operacional completo. Assim, muitas das ferramentas e utilitários que fazem parte do sistema Linux evoluíram a partir dessas primeiras ferramentas GNU. 

$ uname -r
5.15.0-generic
# O kernel Linux em ação
📌 Considere Isto:

Linus originalmente nomeou o projeto de Freax, no entanto, um administrador do servidor onde os arquivos de desenvolvimento foram carregados o renomeou para Linux, um portmanteau (junção) do nome de Linus e UNIX. O nome pegou.

GNU é um acrônimo recursivo para "GNU's Not Unix" (GNU Não é UNIX), e é pronunciado como o antílope africano de chifres que lhe dá nome.

1.3 Linux é Código Aberto (Open Source)

Historicamente, a maioria dos softwares foi distribuída sob uma licença de código fechado (closed-source), o que significa que você obtém o direito de usar o código de máquina, mas não pode ver o código-fonte. Frequentemente, a licença diz explicitamente que você não pode tentar fazer engenharia reversa do código de máquina de volta para o código-fonte para descobrir o que ele faz!

A Filosofia Open Source

O desenvolvimento do Linux acompanha de perto a ascensão do software de código aberto (open source). O código aberto adota uma visão centrada no código-fonte do software. A filosofia do código aberto é que você tem o direito de obter o código-fonte do software e modificá-lo para seu próprio uso.


O Linux adotou esta filosofia com grande sucesso. Linus disponibilizou gratuitamente o código-fonte da programação (as instruções que um computador usa para operar), permitindo que outros se juntassem e moldassem este sistema operacional nascente.

Desenvolvimento Colaborativo

O Linux não foi o primeiro sistema a ser desenvolvido por um grupo de voluntários, mas como foi construído do zero, os primeiros adeptos puderam influenciar a direção do projeto. As pessoas pegavam o código-fonte, faziam alterações e as compartilhavam de volta com o resto do grupo, acelerando enormemente o ritmo de desenvolvimento e garantindo que os erros de outros sistemas operacionais não fossem repetidos. 

$ cat /proc/version
Linux version 5.15.0-generic (gcc version 11.2.0)
# Código aberto - livre para ver, modificar e compartilhar
📌 Considere Isto:

O código-fonte pode ser escrito em centenas de linguagens diferentes. O Linux, por acaso, é escrito em C, uma linguagem versátil e relativamente fácil de aprender, que compartilha história com o UNIX original. Esta decisão, tomada muito antes de sua utilidade ser comprovada, acabou sendo crucial para sua adoção quase universal como o sistema operacional principal para servidores de internet.

Por que a Linguagem C?

A escolha da linguagem C para escrever o kernel Linux foi fundamental para seu sucesso. Diferente de linguagens de nível mais alto, C oferece o equilíbrio perfeito entre desempenho (próximo ao hardware) e portabilidade (capacidade de rodar em diferentes arquiteturas). Isso permitiu que o Linux se espalhasse desde pequenos dispositivos embarcados até os maiores supercomputadores do mundo.

1.4 Linux tem Distribuições

Pessoas que dizem que seu computador roda Linux geralmente se referem ao kernel, às ferramentas e ao conjunto de aplicativos que vêm agrupados no que é chamado de distribuição.


Pegue o Linux e as ferramentas GNU, adicione alguns aplicativos voltados para o usuário, como um navegador web e um cliente de e-mail, e você terá um sistema Linux completo. Indivíduos e até mesmo empresas começaram a agrupar todo esse software em distribuições quase assim que o Linux se tornou utilizável.

O que uma Distribuição inclui?

A distribuição inclui ferramentas que cuidam da configuração do armazenamento, instalação do kernel e instalação do restante do software. As distribuições completas (full-featured) também incluem ferramentas para gerenciar o sistema e um gerenciador de pacotes (package manager) para ajudar você a adicionar e remover software após a instalação ser concluída.

Famílias de Distribuições

Assim como o UNIX, existem distribuições adequadas para todos os propósitos imagináveis. Existem distribuições focadas em executar servidores, desktops ou até mesmo ferramentas específicas da indústria, como design eletrônico ou computação estatística.


Os principais players do mercado podem ser rastreados até Red Hat, Debian ou Slackware. A diferença mais visível entre os derivados do Red Hat e do Debian é o gerenciador de pacotes, embora existam outras diferenças em tudo, desde locais de arquivos até filosofias políticas.

Família Distribuições Conhecidas Gerenciador de Pacotes
Debian Ubuntu, Linux Mint, Kali Linux apt (APT)
Red Hat RHEL, Fedora, CentOS dnf / yum

Para que serve cada distribuição?

  • Servidores: Ubuntu Server, RHEL, Debian Stable
  • Desktop: Ubuntu Desktop, Fedora Workstation, Linux Mint
  • Segurança: Kali Linux, Parrot OS
  • Dispositivos Embarcados: Raspberry Pi OS, Yocto
  • Computação Científica: Ubuntu Studio, Fedora Scientific

1.5 Linux Abraça a CLI

Existem dois tipos básicos de interfaces disponíveis que permitem que você interaja com o sistema operacional. O usuário de computador típico hoje está mais familiarizado com uma interface gráfica do usuário (GUI) (graphical user interface). Em uma GUI, os aplicativos se apresentam em janelas que podem ser redimensionadas e movidas. Existem menus e ferramentas para ajudar os usuários a navegar. Aplicativos gráficos incluem navegadores web, ferramentas de edição de gráficos e e-mail, para citar alguns.

Interface de Linha de Comando (CLI)

O segundo tipo de interface é a interface de linha de comando (CLI) (command line interface), uma interface baseada em texto para o computador. A CLI depende principalmente da entrada do teclado. Tudo o que o usuário deseja que o computador faça é transmitido digitando comandos, em vez de clicar em ícones.


Pode-se dizer que quando um usuário clica em um ícone, o computador está dizendo ao usuário o que fazer, mas, quando o usuário digita um comando, ele está dizendo ao computador o que fazer.

A Filosofia Linux sobre a CLI

Tipicamente, os sistemas operacionais oferecem interfaces GUI e CLI. No entanto, a maioria dos sistemas operacionais de consumo (Windows, macOS) são projetados para proteger o usuário da complexidade da CLI. A comunidade Linux é diferente, pois celebra positivamente a CLI por seu poder, velocidade e capacidade de realizar uma vasta gama de tarefas com uma única instrução de linha de comando.


As máquinas virtuais usadas para os capítulos e laboratórios deste curso fornecem uma CLI para você praticar sem medo de danificar qualquer coisa.

Desafios e Benefícios da CLI

Quando um usuário encontra a CLI pela primeira vez, pode achá-la desafiadora porque requer memorizar uma quantidade vertiginosa de comandos e suas opções. No entanto, uma vez que o usuário aprendeu a estrutura de como os comandos são usados, onde os arquivos e diretórios necessários estão localizados e como navegar na hierarquia de um sistema de arquivos, ele pode ser imensamente produtivo.


Essa capacidade proporciona controle mais preciso, maior velocidade e a capacidade de automatizar tarefas facilmente através de scripts.

Vantagem da CLI entre Distribuições

Além disso, ao aprender a CLI, um usuário pode ser produtivo quase que instantaneamente em QUALQUER distribuição Linux, reduzindo o tempo necessário para se familiarizar com um sistema devido às variações na GUI.
