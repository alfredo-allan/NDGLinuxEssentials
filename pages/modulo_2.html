Sistemas Operacionais

Entenda o que são sistemas operacionais, como funcionam e as principais diferenças entre Linux, Windows e macOS

2.1 Sistemas Operacionais

Um sistema operacional (operating system) é um software que executa em um dispositivo computacional e gerencia os componentes de hardware e software que compõem um sistema computacional funcional.


Os sistemas operacionais modernos não apenas gerenciam recursos de hardware e software, eles programam tarefas para executar de maneira multitarefa (compartilhando o processador para que múltiplas tarefas possam ocorrer aparentemente simultaneamente), fornecem serviços padrão que permitem que usuários e programas solicitem algo (por exemplo, um trabalho de impressão) do sistema operacional e, desde que seja solicitado corretamente, o sistema operacional aceitará a solicitação e executará a função necessária. 

┌─────────────────────────────────────────────────────────┐
│                      👤 USUÁRIOS                        │
├─────────────────────────────────────────────────────────┤
│                   📱 APLICAÇÕES                         │
│         (Navegador, Editor, E-mail, Jogos)              │
├─────────────────────────────────────────────────────────┤
│              ⚙️ SISTEMA OPERACIONAL                      │
│         (Gerencia hardware, processos, memória)          │
├─────────────────────────────────────────────────────────┤
│                   🖥️ HARDWARE                            │
│      (CPU, Memória, Disco, Rede, Periféricos)            │
└─────────────────────────────────────────────────────────┘

Sistemas operacionais de desktop e servidores são, por natureza, mais complexos do que um sistema operacional executado em um dispositivo de propósito único, como um firewall ou um telefone celular. Desde um simples set-top box que fornece uma interface de menu para um provedor de TV a cabo, até supercomputadores e enormes clusters de computação paralela, o termo genérico sistema operacional é usado para descrever qualquer software que é inicializado e executado nesse dispositivo.

O Software de um Sistema

O software de um sistema é o intermediário entre usuários e hardware. O software inclui o software de sistema, aplicações e o sistema operacional.

Sistema Operacional Base Característica Principal
Microsoft Windows Código proprietário (não UNIX/Linux) Administrado principalmente via GUI
Apple macOS UNIX (BSD Unix) + código proprietário Hardware otimizado para o software Apple
Linux UNIX-like (código aberto) Centenas de distribuições para diversas finalidades

Interação e Administração

Um usuário pode facilmente interagir com qualquer um desses sistemas apontando e clicando em tarefas diárias de produtividade que se comportam de forma semelhante, independentemente do sistema operacional subjacente.


Exceto pelo Windows, que é administrado principalmente via GUI, a maioria das tarefas de administração de sistema é executada usando comandos digitados em um terminal. Um administrador familiarizado com UNIX normalmente pode executar tarefas em um sistema Linux e vice-versa. Muitas funções de linha de comando do Linux também têm equivalentes no Microsoft Windows que os administradores usam para trabalhar de forma eficiente. 

$ # Comandos Linux e seus equivalentes no Windows
$ ls          # Linux: lista arquivos
$ dir         # Windows: lista arquivos

$ ps aux      # Linux: lista processos
$ tasklist    # Windows: lista processos

$ chmod 755 script.sh  # Linux: permissões
$ icacls script.sh /grant User:F  # Windows: permissões
💡 Você sabia? Dos três principais sistemas operacionais, apenas o Microsoft Windows é único em seu código subjacente. O macOS é um UNIX totalmente certificado baseado no BSD Unix, e o Linux é um sistema UNIX-like de código aberto.

2.2 Pontos de Decisão

Função (Role)

A primeira decisão ao especificar qualquer sistema computacional é a função da máquina. Você estará sentado no console executando aplicativos de produtividade ou navegando na web? Se sim, um desktop familiar é o melhor. A máquina será acessada remotamente por muitos usuários ou fornecerá serviços para usuários remotos? Então é um servidor.


Servidores normalmente ficam em rack e compartilham teclado e monitor com muitos outros computadores, pois o acesso ao console geralmente é usado apenas para configuração e solução de problemas. Servidores geralmente executam uma CLI, o que libera recursos para o propósito real do computador: servir informações para clientes. Sistemas desktop executam principalmente uma GUI para facilitar o uso por seus usuários.

Função (Function)

Em seguida, determine as funções da máquina. Existe software específico que ela precisa executar ou funções específicas que precisa realizar? Haverá centenas, ou até milhares, dessas máquinas rodando ao mesmo tempo? Qual é o conjunto de habilidades da equipe que gerencia o computador e o software?

Ciclo de Vida (Life Cycle)

O tempo de vida do serviço e a tolerância a riscos do servidor também precisam ser determinados. As atualizações de sistemas operacionais e software vêm em bases periódicas, chamadas de ciclo de lançamento. Os fornecedores suportam versões mais antigas de software apenas por um certo período antes de não oferecerem mais atualizações; isso é chamado de ciclo de manutenção ou ciclo de vida.


Em um ambiente de servidor empresarial, os ciclos de manutenção e lançamento são considerações críticas, porque é demorado e caro fazer grandes atualizações. Em vez disso, o próprio hardware do servidor é frequentemente substituído porque o aumento de desempenho vale o custo extra, e os recursos envolvidos são muitas vezes mais caros que o hardware.

📌 Considere Isto:

Há uma quantidade considerável de trabalho envolvido na atualização de um servidor devido a configurações especializadas, correções de software de aplicação e testes de usuários. Portanto, uma organização proativa buscará maximizar seu retorno sobre o investimento tanto em capital humano quanto monetário.

Virtualização e Nuvem

Os data centers modernos estão enfrentando esse desafio através da virtualização. Em um ambiente virtual, uma única máquina física pode hospedar dezenas ou até centenas de máquinas virtuais, diminuindo os requisitos de espaço e energia, além de fornecer automação para muitas das tarefas anteriormente feitas manualmente por administradores de sistemas.


A necessidade de atualizações de hardware físico também diminuiu imensamente com o advento dos provedores de serviços em nuvem como Amazon Web Services (AWS), Rackspace e Microsoft Azure. Avanços semelhantes ajudaram administradores de desktop a gerenciar atualizações de forma automatizada e com pouca ou nenhuma interrupção para o usuário. 

$ # Exemplo de automação com script para gerenciar VMs
$ for vm in web-server-{01..10}; do
    echo "Criando VM: $vm"
    # Comandos para criar/configurar VM
done

Estabilidade (Stability)

Lançamentos individuais de software podem ser caracterizados como beta ou estável, dependendo de onde estão no ciclo de lançamento. Quando um lançamento de software tem muitos recursos novos que não foram testados, é tipicamente chamado de beta. Após ser testado em campo, sua designação muda para estável.


Usuários que precisam dos recursos mais recentes podem decidir usar software beta. Isso é frequentemente feito na fase de desenvolvimento de uma nova implantação e fornece a capacidade de solicitar recursos não disponíveis na versão estável.


Servidores de produção tipicamente usam software estável, a menos que os recursos necessários não estejam disponíveis e o risco de executar código que não foi completamente testado seja superado pela utilidade fornecida.

Código Aberto (Open Source)

Software no reino do código aberto é frequentemente lançado para revisão por pares muito cedo em seu processo de desenvolvimento e pode ser rapidamente colocado em ambientes de teste e até mesmo de produção, fornecendo feedback extremamente útil e submissões de código para corrigir problemas encontrados ou recursos necessários.

Código Proprietário

Por outro lado, software proprietário é frequentemente mantido em segredo durante a maior parte de seu desenvolvimento, só alcançando um estágio beta público quando está quase pronto para ser lançado.

Compatibilidade (Compatibility)

Um conceito relacionado é a compatibilidade reversa, que se refere à capacidade de sistemas operacionais posteriores serem compatíveis com software feito para versões anteriores. Isso geralmente é uma preocupação quando é necessário atualizar um sistema operacional, mas uma atualização de software de aplicação não é possível devido ao custo ou falta de disponibilidade.


A norma para o desenvolvimento de software de código aberto é garantir a compatibilidade reversa primeiro e quebrar coisas apenas como último recurso. A prática comum de manter e versionar bibliotecas de funções ajuda muito nisso.

Custo (Cost)

Custo é sempre um fator ao especificar novos sistemas. A Microsoft tem taxas de licenciamento anuais que se aplicam a usuários, servidores e outros softwares, assim como muitas outras empresas de software. Em última análise, a escolha do sistema operacional será afetada pelo hardware disponível, recursos e habilidades da equipe, custo de compra, manutenção e requisitos futuros projetados.


Virtualização e serviços de suporte terceirizados oferecem à organização de TI moderna a promessa de pagar apenas pelo que usa, em vez de construir capacidade excedente. Isso não apenas controla custos, mas oferece oportunidades para pessoas dentro e fora da organização fornecerem expertise e valor.

Característica Desktop Servidor
Interface GUI CLI
Acesso Console local Remoto
Propósito Produtividade Fornecer serviços
Atualizações Mais frequentes Planejadas e testadas

Interface

Os primeiros sistemas de computadores eletrônicos eram controlados por meio de chaves e painéis de plugues semelhantes aos usados por operadoras de telefonia na época. Depois vieram os cartões perfurados e finalmente um sistema de terminal baseado em texto semelhante à interface de linha de comando (CLI) do Linux em uso hoje. A interface gráfica do usuário (GUI), com mouse e botões para clicar, foi pioneira no Xerox PARC no início dos anos 1970 e popularizada pela Apple Computer nos anos 1980.


Hoje, os sistemas operacionais oferecem interfaces GUI e CLI, no entanto, a maioria dos sistemas operacionais de consumo (Windows, macOS) são projetados para proteger o usuário dos detalhes da CLI. 

$ echo "A escolha do sistema depende da função, estabilidade, compatibilidade e custo"
A escolha do sistema depende da função, estabilidade, compatibilidade e custo
✅ Resumo: Ao especificar um sistema, considere: Função → Funções → Ciclo de Vida → Estabilidade → Compatibilidade → Custo → Interface.

2.3 Microsoft Windows

A Microsoft oferece diferentes versões de seu sistema operacional de acordo com a função da máquina: desktop ou servidor. A versão desktop do Windows passou por vários esquemas de nomenclatura, com a versão atual (no momento desta escrita) sendo simplesmente Windows 11.


Enquanto novas versões da maioria das distribuições Linux saem duas vezes por ano, por volta de março e setembro, novas versões do Windows tendem a ser lançadas apenas a cada poucos anos. No total, houve 16 versões do Windows desde 1985. A compatibilidade reversa é uma prioridade para a Microsoft, chegando até mesmo a incluir tecnologia de máquina virtual para que os usuários possam executar softwares mais antigos.

Windows Server

O Windows Server atualmente (no momento desta escrita) está na versão 2019 para denotar a data de lançamento. O servidor pode executar uma GUI, mas recentemente a Microsoft, em grande parte como uma resposta competitiva ao Linux, fez avanços incríveis em suas capacidades de script de linha de comando através do PowerShell e do Windows Subsystem for Linux (WSL).


Há também um pacote opcional chamado Desktop Experience que imita uma máquina de produtividade padrão. A Microsoft também incentiva ativamente os clientes empresariais a incorporar seu serviço de nuvem Azure.

Categoria Versão Desktop Versão Servidor
Última Versão Windows 11 Windows Server 2019
Frequência de Lançamento A cada poucos anos A cada poucos anos
Interface GUI principal GUI ou CLI (PowerShell/WSL)
Compatibilidade Alta (prioridade) Alta (inclui VM para software antigo)

PowerShell

Ferramenta de linha de comando e scripting da Microsoft que combina comandos tradicionais do Windows (cmd) com uma linguagem de script poderosa baseada no .NET. Permite administração avançada e automação de tarefas.

WSL (Windows Subsystem for Linux)

Camada de compatibilidade que permite executar binários Linux (em formato ELF) nativamente no Windows 10 e Windows 11. Inclui distribuições como Ubuntu, Debian e Kali Linux. 

$ # PowerShell (Windows)
PS C:\> Get-Process
PS C:\> Get-Service

$ # Bash (Linux/WSL)
$ ps aux
$ systemctl list-units

Microsoft Azure

A Microsoft incentiva ativamente clientes empresariais a incorporar seu serviço de nuvem Azure. A plataforma oferece máquinas virtuais Linux e Windows, serviços de contêineres, bancos de dados e soluções de IA, integrando-se perfeitamente com ferramentas de administração Windows como o Active Directory e o System Center.

📌 Curiosidade: A compatibilidade reversa é tão importante para a Microsoft que o Windows ainda suporta muitas aplicações originalmente escritas para Windows 95, usando técnicas como virtualização e emulação.

2.4 Apple macOS

A Apple desenvolve o sistema operacional macOS, que é parcialmente baseado no software do projeto FreeBSD e passou pela certificação UNIX. O macOS é conhecido por ser "fácil de usar" e, como tal, continua sendo favorecido por usuários com acesso limitado a recursos de TI, como escolas e pequenas empresas. Também é muito popular entre programadores devido à sua base robusta em UNIX.

macOS Server

No lado do servidor, o macOS Server é direcionado principalmente para organizações menores. Esta adição de baixo custo ao macOS desktop permite que os usuários colaborem e que os administradores controlem o acesso a recursos compartilhados. Ele também fornece integração com dispositivos iOS, como iPhone e iPad.

Adoção em Empresas

Alguns grandes departamentos de TI corporativos permitem que os usuários escolham o macOS, pois os usuários geralmente precisam de menos suporte do que as implantações padrão de produtividade da Microsoft. A contínua popularidade do macOS garantiu um suporte saudável dos fornecedores de software.


O macOS também é bastante popular nas indústrias criativas, como produção de gráficos e vídeo. Para muitos desses usuários, a escolha do aplicativo direciona a decisão do sistema operacional.

Integração Hardware e Software

O hardware da Apple, sendo tão integrado ao sistema operacional e sua insistência na adesão a padrões na programação de aplicativos, oferece a esses profissionais criativos uma plataforma estável para executar muitas funções computacionalmente intensivas com menos preocupações sobre compatibilidade.

Característica Descrição
Base técnica
Base UNIX (FreeBSD) + certificação UNIX
Público-alvo desktop Usuários domésticos, escolas, pequenas empresas, programadores
Público-alvo servidor Pequenas organizações (macOS Server)
Indústrias principais Criativa (gráficos, vídeo), desenvolvimento de software
Integração iOS (iPhone/iPad), hardware Apple otimizado

Certificação UNIX

O macOS é um sistema operacional UNIX certificado, o que significa que segue padrões rigorosos de compatibilidade e segurança, diferentemente de sistemas "UNIX-like" que apenas imitam o comportamento.

FreeBSD

O núcleo do macOS (Darwin) é baseado no FreeBSD, um sistema UNIX de código aberto conhecido por sua estabilidade, segurança e recursos avançados de rede.

Indústria Criativa

Adobe Creative Cloud, Final Cut Pro, Logic Pro e outras ferramentas criativas líderes de mercado são desenvolvidas primariamente para macOS.

Ecosistema Apple

Integração perfeita com iPhone, iPad, Apple Watch e iCloud, permitindo Continuidade, Handoff e AirDrop entre dispositivos.

2.5 Linux

Usuários Linux normalmente obtêm um sistema operacional baixando uma distribuição. Uma distribuição Linux é um pacote de software, tipicamente composto pelo kernel Linux, utilitários, ferramentas de gerenciamento e até mesmo alguns softwares aplicativos em um pacote que também inclui os meios para atualizar o software central e instalar aplicações adicionais.


A distribuição cuida da configuração do armazenamento, construção do kernel e instalação de drivers de hardware, bem como da instalação de aplicações e utilitários para fazer um sistema computacional totalmente funcional. As organizações que criam distribuições também incluem ferramentas para gerenciar o sistema, um gerenciador de pacotes para adicionar e remover software, além de programas de atualização para fornecer correções de segurança e funcionalidade.


O número de distribuições Linux disponíveis chega a centenas, então a escolha pode parecer assustadora no início. No entanto, os pontos de decisão são praticamente os mesmos destacados para a escolha de um sistema operacional.

Função (Role)

Com o Linux, há múltiplas opções para escolher dependendo das necessidades organizacionais. A variedade de distribuições e software acompanhante permite que o sistema operacional seja significativamente mais flexível e customizável. Distribuições estão disponíveis para uma variedade muito maior de sistemas, desde ofertas comerciais para funções tradicionais de servidor ou desktop, até distribuições especializadas projetadas para transformar um computador antigo em um firewall de rede; desde distribuições criadas para alimentar um supercomputador até aquelas que habilitam sistemas embarcados.

Função (Function)

Governos e grandes empresas também podem limitar suas escolhas a distribuições que oferecem suporte comercial porque pagar por um nível adicional de suporte pode ser melhor do que arriscar extensas interrupções. Na maior parte, as preocupações com segurança foram abordadas através da grande comunidade de código aberto, que monitora as mudanças do kernel em busca de vulnerabilidades e fornece relatórios de bugs e correções em uma escala muito maior do que os fornecedores de código fechado podem alcançar.


O suporte para aplicações necessárias pode variar e é, portanto, uma consideração adicional. Frequentemente, os fornecedores de aplicações escolhem um subconjunto de distribuições para suportar. No entanto, algumas aplicações como Firefox e LibreOffice são amplamente suportadas e disponíveis para todas as principais distribuições.

Ciclo de Vida (Life Cycle)

A maioria das distribuições tem ciclos de atualização maiores e menores para introduzir novos recursos e corrigir bugs existentes. Além disso, existem pacotes de desenvolvimento onde os usuários podem contribuir com código e enviar correções para possível inclusão em novos lançamentos.


Distribuições Linux podem ser amplamente classificadas em duas categorias principais: enthusiast (entusiasta) e enterprise (empresarial).

Categoria Características Exemplos
Enthusiast (Entusiasta) Ciclo de atualização rápido, sem suporte empresarial, recursos podem mudar ou ser removidos openSUSE Tumbleweed, Fedora, Ubuntu Desktop
Enterprise (Empresarial) Estável e consistente, suporte enterprise de 5-13 anos RHEL (Red Hat), Ubuntu LTS, SLES (SUSE)

Suporte de Longo Prazo (LTS)

Software aplicativo pode ser escrito de forma que suporte apenas um lançamento específico de uma distribuição, exigindo que os usuários permaneçam em um sistema operacional mais antigo e menos seguro do que gostariam. Portanto, algumas versões do Linux são consideradas de suporte de longo prazo (LTS) de 5 anos ou mais, enquanto outras são suportadas apenas por dois anos ou menos.

Estabilidade (Stability)

Algumas distribuições oferecem lançamentos estável (stable), teste (testing) e instável (unstable). Ao escolher uma versão instável para recursos necessários, deve-se considerar que esses recursos podem mudar a qualquer momento durante o ciclo de desenvolvimento. Quando os recursos foram integrados ao sistema por um longo tempo, com a maioria dos bugs e questões resolvidos, o software passa do teste para o lançamento estável.

Fedora → Red Hat

O Fedora é frequentemente considerado a versão beta comunitária do Red Hat. Recursos são adicionados e alterados no Fedora antes de chegarem à distribuição Red Hat pronta para empresas.

openSUSE → SLES

openSUSE e sua contraparte empresarial SLES são similares. Versões posteriores têm codebases quase idênticos, permitindo migração mais fácil de recursos e código.

📌 Considere Isto:

A distribuição Debian avisa os usuários sobre as armadilhas de usar a versão "sid" (instável) com o seguinte aviso:

"'sid' está sujeito a mudanças massivas e atualizações de bibliotecas in-place. Isso pode resultar em um sistema muito 'instável' que contém pacotes que não podem ser instalados devido a bibliotecas faltantes, dependências que não podem ser satisfeitas, etc. Use por sua conta e risco!"

Custo (Cost)

Sua distribuição Linux escolhida pode ter custo zero, mas pagar por suporte pode valer a pena dependendo das necessidades e capacidades organizacionais.

No modo gráfico, os usuários podem ter várias janelas diferentes com aplicativos de terminal (shells) abertos, o que é muito útil ao realizar tarefas em múltiplos computadores remotos. Administradores e usuários podem fazer login com seu nome de usuário e senha através de uma interface gráfica.

Interface de Linha de Comando (CLI)

O segundo tipo de interface, a CLI, é uma interface baseada em texto para o computador, onde o usuário digita um comando e o computador então o executa. O ambiente CLI é fornecido por uma aplicação no computador conhecida como terminal. O terminal aceita o que o usuário digita e passa para um shell. O shell interpreta o que o usuário digitou em instruções que podem ser executadas pelo sistema operacional. Se a saída for produzida pelo comando, então este texto é exibido no terminal. Se problemas com o comando forem encontrados, então uma mensagem de erro é exibida. 

$ # CLI - Login baseado em texto
Ubuntu 22.04 LTS ubuntu tty2

ubuntu login: sue
Password: ********

Welcome to Ubuntu 22.04 LTS (GNU/Linux 5.15.0-generic x86_64)

* Documentation: https://help.ubuntu.com

212 packages can be updated.
91 updates are security updates.

sue@ubuntu:~$ _

A CLI começa com um login baseado em texto como mostrado acima. Em um login bem-sucedido, após ser solicitado um nome de usuário e senha, você é levado a um shell CLI customizado para o usuário específico.


No modo CLI não há janelas para mover. Editores de texto, navegadores web e clientes de e-mail são apresentados apenas em formato de texto. Foi assim que o UNIX operou antes dos ambientes gráficos se tornarem a norma. A maioria dos servidores também executa neste modo, já que as pessoas não fazem login diretamente neles, tornando uma interface gráfica um desperdício de recursos. 

sue@ubuntu:~$ w
 17:27:22 up 14 min,  2 users,  load average: 1.73, 1.83, 1.69
USER     TTY     FROM             LOGIN@   IDLE   JCPU   PCPU WHAT
sue      tty2    20:08            14.35   0.05s   0.00s  w

O prompt de login original está no topo, com texto mais novo adicionado abaixo. Durante o login, pode haver algum texto exibido chamado mensagem do dia (MOTD) (message of the day). Esta é uma oportunidade para o administrador do sistema passar informações aos usuários, ou apenas fazer uma piada boba.


Após o MOTD vem o prompt de comando. No exemplo acima, o usuário digitou o comando w que mostra quem está logado. Conforme novos comandos são inseridos e processados, a janela rola para cima e o texto mais antigo é perdido no topo. O terminal em si é responsável por manter qualquer histórico, como permitir que o usuário role para cima e veja comandos inseridos anteriormente. Do ponto de vista do Linux, o que está na tela é tudo o que existe. Não há nada para mover.

✅ Resumo: O Linux oferece centenas de distribuições para diferentes necessidades (Role, Function, Life Cycle, Stability, Cost, Interface). A escolha certa depende do seu caso de uso - desktop, servidor, firewall, supercomputador ou sistemas embarcados.

2.6 Distribuições Linux

Red Hat

A Red Hat começou como uma distribuição simples que introduziu o Red Hat Package Manager (RPM). O desenvolvedor eventualmente formou uma empresa em torno dela, que tentou comercializar um desktop Linux para negócios. Com o tempo, a Red Hat começou a focar mais em aplicações para servidores, como servidores web e arquivos, e lançou o Red Hat Enterprise Linux (RHEL), que era um serviço pago com um ciclo de lançamento longo.


O ciclo de lançamento dita com que frequência o software é atualizado. Uma empresa pode valorizar a estabilidade e querer ciclos de lançamento longos, enquanto um hobbyista ou uma startup pode querer o software mais recente e optar por um ciclo de lançamento mais curto. Para satisfazer este último grupo, a Red Hat patrocina o Projeto Fedora, que cria um desktop pessoal com o software mais recente, mas ainda construído sobre as mesmas bases da versão empresarial.

CentOS e Derivados

Como tudo no Red Hat Enterprise Linux é código aberto, um projeto chamado CentOS surgiu. Ele recompilou todos os pacotes do RHEL (convertendo seu código-fonte da linguagem de programação em que foram escritos para uma linguagem utilizável pelo sistema) e os distribuiu gratuitamente. CentOS e outros como ele (como o Scientific Linux) são amplamente compatíveis com o RHEL e integram alguns softwares mais novos, mas não oferecem o suporte pago que a Red Hat oferece.


Scientific Linux é um exemplo de uma distribuição de uso específico baseada no Red Hat. O projeto é uma distribuição patrocinada pelo Fermilab projetada para permitir a computação científica. Entre suas muitas aplicações, o Scientific Linux é usado com aceleradores de partículas, incluindo o Grande Colisor de Hádrons no CERN.

SUSE

SUSE, originalmente derivada do Slackware, foi uma das primeiras distribuições Linux abrangentes, tendo muitas semelhanças com o Red Hat Enterprise Linux. A empresa original foi comprada pela Novell em 2003, que foi então comprada pelo Attachmate Group em 2011. O grupo Attachmate então se fundiu com a Micro Focus International em 2014, e em 2018 a SUSE anunciou planos de seguir como um negócio independente. Através de todas as fusões e aquisições, a SUSE conseguiu continuar e crescer.


Enquanto o SUSE Linux Enterprise contém código proprietário e é vendido como produto para servidores, o openSUSE é uma versão completamente aberta e gratuita com múltiplos pacotes de desktop, semelhante ao CentOS e Linux Mint.

Debian

Debian é mais um esforço comunitário e, como tal, também promove o uso de software de código aberto e a adesão a padrões. O Debian criou seu próprio sistema de gerenciamento de pacotes baseado no formato de arquivo .deb. Enquanto a Red Hat deixa o suporte a plataformas não-Intel e AMD para projetos derivados, o Debian suporta muitas dessas plataformas diretamente.

Ubuntu

Ubuntu é a distribuição derivada do Debian mais popular. É uma criação da Canonical, uma empresa criada para promover o crescimento do Ubuntu e ganha dinheiro fornecendo suporte. O Ubuntu tem várias variantes diferentes para desktop, servidor e várias aplicações especializadas. Eles também oferecem uma versão LTS que é mantida atualizada por 3 anos em desktops e 5 anos em servidores, o que dá aos desenvolvedores e às empresas em que trabalham confiança para construir soluções baseadas em uma distribuição estável.

Linux Mint

Linux Mint foi iniciado como um fork do Ubuntu Linux, ainda dependendo dos repositórios do Ubuntu. Existem várias versões, todas gratuitas, mas algumas incluem codecs proprietários, que não podem ser distribuídos sem restrições de licença em certos países.

Android

Linux é um kernel, e muitos dos comandos abordados neste curso são na verdade parte do pacote GNU. É por isso que algumas pessoas insistem em usar o termo GNU/Linux em vez de apenas Linux.


Android, patrocinado pelo Google, é a distribuição Linux mais popular do mundo. É fundamentalmente diferente de suas contrapartes. O Android usa a máquina virtual Dalvik com Linux, fornecendo uma plataforma robusta para dispositivos móveis, como telefones e tablets. No entanto, por não ter os pacotes tradicionais que são frequentemente distribuídos com Linux (como GNU e Xorg), o Android é geralmente incompatível com distribuições Linux desktop.


Essa incompatibilidade significa que um usuário Red Hat ou Ubuntu não pode baixar software da Google Play store. Da mesma forma, um emulador de terminal no Android não tem muitos dos comandos de suas contrapartes Linux. É possível, no entanto, usar BusyBox com Android para habilitar a maioria dos comandos a funcionar.

Raspbian

Raspbian é uma distribuição Linux especializada otimizada para funcionar em hardware Raspberry Pi. Esta combinação tem visto uso significativo no treinamento de programadores e designers de hardware em todos os níveis. Seu baixo custo e facilidade de uso a tornaram uma favorita de educadores em todo o mundo, e muitos dispositivos adicionais estão disponíveis para estender suas capacidades para o mundo físico.

Linux From Scratch (LFS)

Linux From Scratch (LFS) é mais uma ferramenta de aprendizado do que uma distribuição funcional. Este projeto consiste em um livro online e código-fonte, com "instruções passo a passo" para construir uma distribuição Linux personalizada a partir do código-fonte. Esta "distribuição" incorpora o verdadeiro espírito do Linux, onde os usuários podem modificar qualquer aspecto do sistema operacional e aprender como todas as peças funcionam juntas.

2.7 Sistemas Embarcados (Embedded Systems)

O Linux começou como algo que só funcionaria em um computador como o de Linus Torvalds: um PC Intel 386 com um controlador de disco rígido específico, mas como qualquer um poderia adicionar ou modificar o Linux, as pessoas começaram a construir suporte para outros hardwares. Eventualmente, o Linux começou a suportar outros chips com ênfase em tamanho pequeno e baixo consumo de energia.

O que são Sistemas Embarcados?

Devido a essa flexibilidade, um número significativo de fabricantes de dispositivos usou o Linux como sistema operacional para seus produtos de hardware. Hoje chamamos esses de sistemas embarcados (embedded systems) porque são projetados para fazer uma tarefa específica em hardware otimizado apenas para esse propósito. Esses sistemas abrangem uma tremenda diversidade de dispositivos usados hoje, desde telefones celulares até TVs inteligentes e eletrodomésticos, até sistemas de monitoramento remoto para oleodutos e fábricas.

Evolução do Linux Embarcado

À medida que o Linux evoluiu, chips de processador especializados foram desenvolvidos para dispositivos de consumo e industriais para aproveitar suas capacidades. O suporte ao Linux se tornou tão onipresente que é possível prototipar e lançar no mercado novos dispositivos usando componentes prontos (off-the-shelf).


A ascensão de computadores de placa única (single-board computers) baratos, pequenos e adaptáveis, como o Raspberry Pi, deu a experimentadores e empreendedores de todo o mundo ferramentas para construir rapidamente soluções personalizadas, alimentadas por Linux, que teriam exigido meses de trabalho de equipes especializadas há apenas alguns anos.

Internet das Coisas (IoT)

Embora os consumidores estejam familiarizados com dispositivos de entretenimento Linux embarcados como DVRs e "Smart TVs", o impacto real do Linux embarcado está apenas começando a ser percebido. A internet das coisas (IoT) está crescendo com dispositivos baratos e onipresentes sendo implantados em tudo, desde poços de petróleo até fazendas de geração solar.


Essas redes de sensores inteligentes e controladores permitem que engenheiros ajustem processos críticos em tempo real, enquanto monitoram e reportam de volta a estações centrais de controle.
